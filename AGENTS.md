# Tournament HUB: памятка исполнителя

- Перед любой работой прочитай `ai-context/README.md`, `ai-context/task-list.md`, router `ai-context/rules/README.md`, пять core rules и conditional rules, чьи triggers совпали со scope.
- Любое изменение репозитория выполняй только через задачу из `task-list.md`.
- До реализации найди связанную карточку или создай новую в `ai-context/tasks/` по шаблону.
- В каждой карточке добавляй ссылку на router, evidence для пяти core rules, результат conditional trigger scan и прямые ссылки на сработавшие conditional rules.
- `Применимо` обязано менять scope, plan, criteria, checks или ограничение; декоративная ссылка не считается соблюдением.
- Не переиспользуй номера: новый `NNN` следует за максимальным номером в истории реестра.
- До первого изменения переведи готовую карточку в `В работе` и поставь `🚧` в реестре.
- Одновременно держи только одну свою задачу со статусом `В работе`.
- Если scope меняется, сначала обнови карточку, план и критерии, затем продолжай реализацию.
- При изменении scope повтори routing правил до следующего изменения файлов.
- Синхронизируй словесный статус карточки и emoji в `task-list.md` при каждом переходе.
- Не угадывай отсутствующие требования: зафиксируй неизвестное и запроси решение, если выбор существенно меняет результат.
- Ищи канонические требования через `docs/README.md`; `docs/source` не редактируй и не используй как замену нормализованной документации.
- Не трогай несвязанные пользовательские изменения, секреты и удалённые ранее файлы.
- Добавляй соразмерную проверку изменения и честно записывай её результат в карточке.
- Перед завершением заполни критерии, проверки, решения и итог задачи.
- Перед `Выполнена` сверь routing и evidence с итоговым diff либо оставь задачу активной/заблокированной.
- Каждое серьёзное решение документируй по `docs/governance/decision-policy.md`; изменение архитектуры требует ADR до реализации, изменение rules — записи в rule-change log.
- Завершённую задачу перенеси в раздел завершённых с `✅`; незавершённую не помечай выполненной.
- `$task` используй только для декомпозиции и записи задач; реализацию веди отдельным шагом.
- Коммуникацию и документацию пиши по-русски; технические identifiers сохраняй без перевода.
- Коммит создавай только по прямому запросу пользователя.
