# R-006.b. Именованные callbacks в widgets

## Применение

Scope: Flutter-клиент `apps/tournament_app` и его тесты, включая app/domain/infrastructure/presentation. К другим приложениям и инструментам проекта это правило не применяется; их архитектура определяется отдельно.

Обязательное правило. Проверяется при изменении Flutter widgets, их build/lifecycle и передачи функций в UI.

## Ограничения

- Анонимные функции и лямбды внутри widgets запрещены, включая `() { ... }`, `() => ...`, async callbacks и callback с параметрами.
- Каждый обработчик выделяется в именованный метод с конкретной сигнатурой и именем по действию, например `_handleSubmit` или `_handleParticipantChanged`. В параметр callback передаётся method tear-off.
- Именованный метод может иметь выражение-тело `=>`: запрет относится к анонимной функции, а не к синтаксису тела метода.
- Передача уже именованного типизированного callback через параметр widget допустима: пустая обёртка ради переименования не требуется.
- Для недоступного действия nullable callback получает `null`; при доступном действии передаётся именованный обработчик, например `onTap: state.canSubmit ? _handleSubmit : null`. Пустой обработчик или обработчик, который лишь проверяет доступность и ничего не делает, не заменяет `null`.
- Для привязки аргументов используй типизированные поля приватного widget и его именованный обработчик; не создавай анонимную функцию при передаче callback.
- Единственное исключение — настоящие builders по контракту UI API (`builder`, `itemBuilder` и аналогичные). Функция должна строить UI; название параметра или функции без такого контракта не является основанием для исключения.
- Именованный обработчик обращается к state/controller; это не разрешает вызов use case напрямую из widget.

## Проверка

Проверить анонимные функции в widgets и определить назначение каждой. Исключения должны соответствовать builder-контракту; остальные callbacks имеют именованный метод или передаются как именованный типизированный callback.
Проверить обе ветки доступности действия: nullable callback равен `null`, когда действие недоступно, и получает именованный обработчик, когда доступно.

Обоснование и примеры: [Композиция widgets и callbacks](../../../docs/architecture/widget-composition.md).
