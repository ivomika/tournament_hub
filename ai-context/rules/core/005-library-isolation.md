# R-005. Изоляция библиотек и технических механизмов

## Применение

Обязательное правило. Проверяется при добавлении пакетов, генераторов, хранения, HTTP, SDK, domain ports и инфраструктурных адаптеров.

## Ограничения

- Domain не зависит от Flutter, платформенных SDK, HTTP и библиотек хранения. Любой дополнительный технический пакет требует явно документированного решения о допуске.
- Предметные ports определяются в domain и не раскрывают библиотечные типы.
- Для реально используемой инфраструктурной механики вводится минимальная собственная техническая абстракция в infrastructure; конкретная библиотека скрывается внутри её адаптера.
- Контракт абстракции определяется нуждами потребителей; нельзя механически копировать весь API библиотеки или создавать обёртки ради гипотетической замены.
- Конкретные адаптеры выбираются и связываются в `app`.

## Проверка

Проверить новые зависимости и сигнатуры контрактов. Убедиться, что библиотечные типы не выходят из адаптера, а допуск пакета в domain имеет документированное обоснование с различением runtime и генератора.

Размещение ports, технических core-абстракций и условия допуска пакетов: [Границы слоёв](../../../docs/architecture/layer-boundaries.md).
