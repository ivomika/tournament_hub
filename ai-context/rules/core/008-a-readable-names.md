# R-008.a. Понятные имена переменных

## Применение

Обязательное core-правило для нового и изменённого кода: переменные, поля, параметры, bindings в циклах, catch и patterns. Имя сообщает назначение без поиска расшифровки в коде.

## Ограничения

- Не использовать однобуквенные и непонятные сокращённые имена: t, ctx, cfg, args. Писать theme, context, configuration, arguments или более точное предметное имя. Private underscore не разрешает сокращение.
- Общепринятые id/url/uri допускаются. Generic type parameters и wildcard без binding не являются переменными.
- Исключение первого Dart-контракта: локальные x/y с явно указанным типом double/int/num непосредственно в paint класса, напрямую наследующего Flutter CustomPainter. Это координаты. Исключение не распространяется на t, поля/другие методы/вложенные функции и классы только с суффиксом Painter.
- AST отклоняет однобуквенные bindings и целые сегменты ctx/cfg/args в camelCase/snake_case. Остальные сокращения и смысл имён проверяются review; автоматическая проверка не доказывает понятность любого прошедшего имени.
- Не добавлять blanket ignore/exemptions для старого или generated кода. Новое контекстное исключение документируется с positive/negative tests.

## Проверка

В Flutter lib/test проверяет make architecture-check/test. Для других языков правило действует на review, автоматизация пока не реализована. Ошибки: путь, строка, R-008.a и ненулевой exit.
