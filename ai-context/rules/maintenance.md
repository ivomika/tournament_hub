# Сопровождение правил

Читать перед добавлением или изменением правила. [README.md](README.md) определяет чтение по scope, [registry.json](registry.json) содержит действующие ID и пути.

## Размещение

- `core` — требования ко всему коду проекта: SOLID, документирование и типизация.
- `flutter` — требования к Flutter-клиенту и его тестам. R-003 задаёт его архитектуру; R-005 — локализацию; R-006 — композицию widgets и callbacks.
- Архитектура другой технологии получает собственное документированное решение и правила в соответствующем scope. R-003 на неё не распространяется.

## Выбор ID

- Уточнение существующего требования изменяет его файл с сохранением ID.
- Новое самостоятельное требование внутри группы получает следующий suffix: a…z, aa…az и далее.
- Новая независимая ответственность получает следующий root после максимального номера в registry. Текущий ряд root ID — R-001–R-006; следующий — R-007.
- ID группы обозначает ответственность; в findings и карточках используется конкретный leaf ID.
- Действующие root и suffix образуют последовательности без пропусков. Изменение существующего ID выполняется только по явному решению с одновременным обновлением имён файлов, ссылок, router и registry.
- Предложения не резервируют номера. Проверяй registry непосредственно перед записью.

## Запись и проверка

1. Оформи изменение через task-list: уточнение цели продолжает текущую карточку, независимая цель получает новую задачу.
2. Документируй существенное решение в docs в той же задаче.
3. Leaf содержит ID, scope/trigger, ограничения, способ проверки и ссылку на docs. Имя файла содержит ID.
4. При добавлении или изменении ID обнови registry и router вместе с rule-файлом. При уточнении только текста новая запись registry не нужна.
5. Обнови актуальные ссылки и примеры. Changelog сохраняет ранее выполненные действия; он не задаёт текущие требования.
6. Выполни `node tools/check_rules.cjs`, проверь ссылки, запиши фактические изменения, проверки и ограничения в карточку.
