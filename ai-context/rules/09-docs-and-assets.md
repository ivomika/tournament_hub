# Documentation and assets enforcement

## Trigger

Изменение серьёзного решения, behavior, architecture, rule, schema/protocol, design token, README/roadmap/ADR, terminology, manifest или asset.

## Обязательно

- Обновить owning document в той же задаче.
- Architecture change оформить ADR; rule change записать в rule-change journal.
- Серьёзное решение связать с task, rationale, consequences, migration/rollback и verification.
- Проверить links/terminology/assets integrity.

## Запрещено

- Оставлять серьёзное решение только в code/task/chat.
- Дублировать project fact в rules.
- Редактировать `docs/source` или лицензируемые originals без отдельного scope.
