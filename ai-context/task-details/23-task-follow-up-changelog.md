# Задача 23. Зафиксировать продолжение задачи через changelog без создания задач на правки

## Статус

✅ Выполнена

## Цель

Изменить процесс ведения задач так, чтобы обратная связь и исправления в пределах исходной цели продолжали существующую карточку, а не создавали новую задачу.

## Контекст и границы

- Изменяется процесс `ai-context`, шаблон карточки, инструкция `AGENTS.md` и локальный навык `Task`.
- Закрытая задача при новой правке в её scope возвращается в статус `🚧 В работе` под тем же номером.
- Если исходная raw-задача не имела detail, карточка создаётся для её существующего номера при первом follow-up.
- Каждая итерация фиксирует пользовательский prompt и фактически выполненные изменения в append-only changelog карточки.
- Новая задача создаётся только для самостоятельной цели, которую можно принять независимо от исходной задачи.
- История уже закрытых задач не объединяется задним числом и не удаляется.
- Продуктовый код и долговременная документация проекта в `docs/` не меняются.

## Ключевые решения

- Критерий нового номера — независимо реализуемый и принимаемый результат, а не новый пользовательский prompt.
- Follow-up в пределах цели сохраняет номер, переоткрывает закрытую задачу на время изменений и добавляет новую changelog-итерацию.
- Changelog является append-only и дословно хранит относящийся к задаче prompt; изменения и проверки фиксируют фактический результат итерации.
- Если raw-задача не имела карточки, detail создаётся при первом follow-up под существующим номером.
- Старые задачи не объединяются задним числом: сохранение фактической истории важнее косметической нормализации прошлого реестра.

## Итог

Процесс больше не создаёт отдельные задачи на каждую итерацию приёмки. Уточнение или исправление продолжает исходную карточку с тем же номером и записывается отдельной changelog-итерацией; новая задача появляется только для независимого результата. Это поведение закреплено в основном AI Context, шаблоне, корневой инструкции и локальном навыке `Task`.
