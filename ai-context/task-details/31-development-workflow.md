# Задача 31. Экспериментальный development workflow

## Статус и этап

✅ Завершена

- Mode: DOCUMENTATION.
- Stage: DONE.
- TestGate: NOT_REQUIRED — документация процесса и instructions skills, логика продукта не меняется.
- Версия specification/plan: 2.

## Цель и контекст

Агент получает краткий запрос задачи и из файлов проекта определяет discovery, clarification, spec, plan, test gate, approval, implementation и verification. Существующая механика задач сохраняется.

Аудит выполнен read-only. В текущем клиенте только main.dart; Domain/business test suite отсутствует. Сохранённая карта viewer не считается источником действующих бизнес-правил. Эта задача меняет инструкции, шаблон и skills, не бизнес-функцию и не production-код.

## Scope и non-goals

- Один канонический ai-context/workflow.md, короткие указатели, расширение шаблона, существующих skills и R-007.
- Не создавать второй task manager, дополнительные статусы task-list, общие бизнес-правила или product API.
- Не менять закрытые карточки и не реализовывать проверочную гипотетическую feature.

## Применимые правила

- R-001 — единственный источник процесса, skills используют ссылки.
- R-002 — описание workflow и проверочного walkthrough на русском.
- R-004 — тестовые идентификаторы в walkthrough обозначены как гипотетические, не строки состояния приложения.
- R-007 — применяются структурные и сценарные проверки документации/skills, а не runtime-тесты неизменённого продукта.
- Conditional rules отсутствуют; Flutter-код не меняется.

## Первоначальные ответы и решения v1 (история)

- Полный цикл — для любых изменений кода; documentation — структурная проверка без test-first gate.
- Этапы, ответы, plan, test evidence и approval живут в карточке. Существующие четыре статуса и task-list сохраняются.
- Уточнение интерактивное. Агент предлагает общее business rule, но не утверждает его самостоятельно.
- Specification: цель/context, scope/non-goals, наблюдаемые критерии, ошибки/границы и тестовые сценарии. Dependencies/Architecture Impact — по необходимости.
- Реальные бизнес-правила проверяются через use case; внешние зависимости можно подменять. Сценарии связываются с критериями, без требования одной test-функции на критерий.
- Production-код и минимальные API-заглушки до approval запрещены. Ожидаемый compile failure допустим как RED.
- Контекстное «ок» разрешает реализацию только после отчёта gate; diff тестов и команду в чат показывать не обязательно. В карточке сохраняется проверяемая информация о запуске.
- Approval с текстом, датой и version записывается в историю; существенное изменение бизнес-смысла требует нового gate.
- Во время реализации допустимы исправления в рамках approval до GREEN; новая бизнес-неоднозначность вызывает BLOCKED и уточнение.
- После GREEN возможен behavior-preserving refactor; завершение и ✅ выполняет агент после проверки.
- Утверждённое исключение: чистый refactor/mechanical change может использовать подтверждённый baseline GREEN вместо искусственного RED, но human gate сохраняется.
- Workflow экспериментальный и удаляемый через файл и указатели.

## План реализации

1. Создать canonical workflow и расширить существующий template разделами этапа, spec, plan, evidence и approval.
2. Связать AGENTS, README, R-007 и skills с workflow; не копировать нормативный процесс в docs.
3. Описать пример и removal checklist в docs.
4. Проверить ссылки, состав rules, сохранение invocation policy skills и сценарии остановки/возобновления.

## Критерии и сценарии проверки

- [x] Обычный запрос feature запускает процесс без необходимости вручную вызвать skill.
- [x] Нет production-изменений до contextual explicit approval; compile RED и baseline GREEN различаются.
- [x] Новая неоднозначность/смысловая правка возвращает gate; ошибка реализации — допускает повторный запуск без нового approval.
- [x] Документация и planning-only task skill не получают искусственный RED или автоматическую реализацию.
- [x] Закрытые задачи и старые карточки остаются совместимыми; процесс можно удалить.
- [x] Walkthrough проверяет полный путь гипотетического business rule без product code.
