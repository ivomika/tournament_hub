# Задача 14. Сгруппировать Domain architecture checker по визуальным кластерам

## Статус

✅ Выполнена

## Цель

Разнести Domain-объекты по читаемым кластерам областей, чтобы границы групп и связи между ними были видны без плотной вертикальной раскладки.

## Контекст и границы

- Входит: area-контейнеры с заголовками и количеством объектов, двухколоночная раскладка узлов внутри кластера, увеличенные межкластерные интервалы и адаптированная трассировка edges.
- Входит: сохранение поиска, фильтров, выбора объекта и режима «Фокус связей».
- Не входит: изменение JSON-инвентаря, Domain-кода, семантики связей или автоматический graph layout сторонней библиотекой.
- В рабочем дереве уже есть несвязанные изменения generated plugin registrants; задача их не изменяет и не включает в commit.
- Итерация 2 добавляет вложенные контейнеры фактических каталогов внутри area. Для этого generated schema получает folder group; ручная классификация в viewer запрещена.

## Ключевые решения

- Кластеры распределяются по трём колонкам алгоритмом shortest-column; это уменьшает пустоты при разных размерах областей и остаётся детерминированным без внешней graph-layout зависимости.
- Внутри area используются две колонки карточек, поскольку крупнейшая область содержит 12 объектов, а одна колонка делает кластер чрезмерно высоким.
- Schema v6 хранит точный относительный folder id у node и отдельный generated-реестр folders; viewer не выводит назначение папки из kind, role или имени declaration.
- Folder containers располагаются вертикально внутри area, сохраняя двухколоночную карточную сетку и существующие широкие горизонтальные коридоры для edges.
- Фильтрация сначала определяет visible nodes, затем оставляет только соответствующие generated folders; поэтому пустых контейнеров и неверных счётчиков нет.

## Итог

Domain areas отображаются отдельными подписанными кластерами со счётчиком видимых объектов. Кластеры детерминированно распределяются по трём колонкам, карточки внутри — по две в строке с увеличенными интервалами. Edge routing выбирает ближайшую горизонтальную или вертикальную сторону узла. Поиск, фильтры, selection и relationship focus сохранены. Domain inventory и пользовательские generated plugin files не изменялись.

После итерации 2 каждая area дополнительно разделена на подписанные контейнеры фактических каталогов. Их состав полностью генерируется из расположения Dart declarations, поэтому новые папки появляются на карте автоматически, а viewer не угадывает архитектурную принадлежность объектов.
