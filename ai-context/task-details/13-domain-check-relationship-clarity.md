# Задача 13. Улучшить читаемость связей в Domain architecture checker

## Статус

✅ Выполнена

## Цель

Сделать направление и контекст связей выбранного Domain-объекта понятными без ручной расшифровки всей карты.

## Контекст и границы

- Входит: направленные стрелки на связях, режим фокуса прямых зависимостей, визуальное затухание нерелевантных узлов и раздельный список входящих/исходящих связей в detail panel.
- Не входит: изменение Domain-кода, JSON-инвентаря, автоматический анализ исходного Dart-кода или перестройка всей топологии карты.
- Связанные документы: `docs/development/domain-check.md`, задача 11.

## Применимые правила

### Обязательные правила

- [x] [R-001 · SOLID](../rules/core/001-solid.md) — вычисление graph relationship context остаётся отдельной функцией viewer; renderer только применяет готовый контекст к узлам, рёбрам и detail panel.
- [x] [R-002 · Документирование на русском](../rules/core/002-documentation-russian.md) — в `docs/` фиксируется значение направления связи и поведение режима фокуса.

### Conditional rules

- Scan выполнен: conditional rules отсутствуют; задача ограничена статическим developer-tool и не изменяет Domain contract, persistence, UI приложения или transport.

## Декомпозиция

- [x] Проанализировать текущую визуализацию связей и найти препятствия чтению направления.
- [x] Добавить управляемый фокус прямых связей и направленные edges.
- [x] Разделить inbound/outbound связи в detail panel, обновить документацию и проверить viewer.

## Критерии готовности

- [x] Каждая связь на карте визуально имеет направление от source к target.
- [x] При выборе объекта пользователь видит отдельно «Использует» и «Используется в», с понятными переходами.
- [x] Режим фокуса выделяет выбранный объект и его прямых соседей, не скрывая карту полностью.
- [x] Viewer остаётся статическим, запускается через `make domain-check`, JSON и JavaScript валидны.

## Открытые вопросы и блокеры

- Нет.

## Ключевые решения

- Фокус ограничивается прямыми связями, чтобы не смешивать наблюдаемую dependency graph с транзитивным анализом, которого JSON-инвентарь не обещает.
- Исходящие связи выделяются золотым, входящие — голубым; направление дополнительно передаётся стрелкой и текстовой группировкой, а не только цветом.

## Проверки

- `node --check tools/domain-check/app.js` — JavaScript синтаксически валиден.
- `python -m json.tool tools/domain-check/domain-architecture.json` — JSON-инвентарь валиден.
- `make domain-check DOMAIN_CHECK_PORT=8092` и `Invoke-WebRequest http://127.0.0.1:8092/` — HTTP 200, отдан обновлённый viewer HTML.
- `git diff --check` — успешно.
- Встроенный browser automation в окружении недоступен, поэтому интерактивная browser-проверка стрелок/фокуса не выполнена автоматически; ручная проверка доступна через `make domain-check`.

## Итог

Viewer показывает стрелки от использующего объекта к зависимости. Выбор карточки подсвечивает и подписывает её прямые incoming/outgoing edges, а detail panel делит их на «Использует» и «Используется в». Режим «Фокус связей» приглушает нерелевантный контекст, не скрывая карту. JSON-инвентарь и Domain-код не менялись.
