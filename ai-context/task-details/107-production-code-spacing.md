# 107. Вертикальные отступы в production Dart-коде

✅ Выполнено · Mode CODE · TestGate NOT_REQUIRED · Stage DONE.
Specification/plan/test set2.

## Цель и scope

Отделить конструкторы от полей, поля от методов, самостоятельные методы друг от друга пустой строкой. Сохранить связанные поля единым блоком. Итоговый scope — только рукописные production Dart-файлы apps/tournament_app/lib из текущего git diff, включая untracked. Generated, Widgetbook, тесты и остальные файлы не форматируются этой задачей. Семантика, API, UI и порядок членов классов не меняются.

TestGate не требуется: меняются только пробельные символы исходников, не логика или её структура. Это не рефакторинг выражений/контрактов. Сохранность содержимого проверяется сравнением лексем Dart до/после; при необходимости менять токены такая правка выходит из данного scope.

## Применимые правила

Прочитаны core R-001/002/004/007/008.a/b и все обязательные Flutter R-003.a–h, R-005, R-006.a–d. Архитектура, имена, условия, callbacks, локализация и темы сохраняются; R-007 — структурное подтверждение отсутствия семантического diff, analyzer и architecture scan. Conditional rules отсутствуют. Workflow прочитан. UI не меняется, новые goldens не нужны. Сборки, запуск приложения и коммиты запрещены прежними указаниями пользователя.

## План и проверки

1. AST analyzer определяет границы class/enum/mixin/extension members, добавляются только отсутствующие пустые строки. Комментарии и metadata не отделяются от следующего member. Соседние поля не дробятся пустыми строками.
2. dart format затронутых файлов; сравнение с snapshot этой итерации, включая существующие незакоммиченные изменения. Проверяется неизменность лексем, не только diff относительно HEAD.
3. flutter analyze --no-pub, полный architecture scan, git diff --check. Не добавлять тесты количества пустых строк; runtime не меняется.
