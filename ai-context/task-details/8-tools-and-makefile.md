# Задача 8. Добавить tools и Makefile

## Статус

✅ Выполнена

## Цель

Обозначить `tools/` как утилитарную папку проекта и предоставить единый набор Make-команд для запуска, сборки и проверки Flutter-приложения.

## Контекст и границы

- Входит: описание `tools/`, корневой `Makefile`, документация локальных команд.
- Не входит: добавление конкретных скриптов в `tools/`, CI и кросс-компиляция недоступных на текущей машине платформ.

## Применимые правила

### Обязательные правила

- [x] [R-001 · SOLID](../rules/core/001-solid.md) — `Makefile` только оркестрирует команды Flutter; runtime-код остаётся в `apps/tournament_app`, а утилиты — в `tools/`.
- [x] [R-002 · Документирование на русском](../rules/core/002-documentation-russian.md) — назначение `tools/`, команды и ограничения платформ описаны в `docs/` и корневом README.

### Conditional rules

- Scan выполнен: conditional rules пока отсутствуют.

## Критерии готовности

- [x] `tools/` явно обозначена как папка утилит проекта.
- [x] `make run`, `make build PLATFORM=...`, `make analyze` и `make clean` доступны из корня.
- [x] Makefile валидирует значение `PLATFORM`.
- [x] `make help` и `make analyze` завершаются успешно.

## Открытые вопросы и блокеры

- Нет.

## Ключевые решения

- `PLATFORM` по умолчанию равна `macos`, поскольку это локальная платформа разработки; остальные поддерживаемые Flutter target’ы выбираются явно.
- Единый `build` собирает одну выбранную платформу. Полная одновременная сборка всех target’ов не вводится, потому что платформенные toolchain и требования подписи различаются.

- `make help` — успешно.

- `make build PLATFORM=unsupported` — корректно завершился ошибкой валидации.
- `git diff --check` — успешно.
