## Цель и scope

Ввести обязательное core-правило для проектных асинхронных операций: явное владение, отменяемый контракт, кооперативная отмена вложенной работы, завершение ожиданий и защита от поздних результатов. Документировать фактические ограничения внешних API. Не выбирать конкретный lifecycle package, не заменять _disposed и не переписывать весь существующий async-код.

## Применимые правила

Прочитаны README/router, все core R-001/002/004/007/008.a/b, maintenance/registry и workflow; conditional rules отсутствуют. Новая независимая ответственность — R-009 по текущему реестру; исторические записи старой нумерации не меняются. Canonical facts в docs, исполняемые требования в rules. Все обязательные Flutter rules прочитаны для связанной задачи106; эта задача меняет только documentation/rule metadata.
