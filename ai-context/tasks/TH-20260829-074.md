# TH-20260829-074: Унифицировать role-aware навигацию и вторичные действия

- Статус: Готова
- Создана: 2026-08-29
- Обновлена: 2026-08-29
- Источник: P1-вывод UX-аудита о перегруженной навигации и необходимости различать Host, Participant и Spectator контексты

## Цель

Снизить навигационный шум на mobile и desktop, показывая роль- и state-relevant разделы, сохранив предсказуемый доступ к истории, профилю и восстановлению.

## Контекст

Одинаковая плотность navigation для Host, Participant и Spectator конкурирует с контентом и ActionDock. Вторичные действия должны быть доступны, но не занимать постоянное место; role-aware nav не меняет guards и domain permissions.

## Границы задачи

### Входит

- Матрица navigation items по ролям и lifecycle states.
- Компактное представление вторичных разделов на mobile и overflow/secondary grouping на desktop.
- Согласование nav labels, current location, back behavior и recovery entry points.
- Удаление визуально главного, но редко нужного `изменить никнейм` из primary profile actions.

### Не входит

- Новые routes, guards или permissions.
- Изменение domain lifecycle и network transport.
- ActionDock contract и Host critical actions (069–070).

## Требования и ограничения

- Navigation не является скрытым domain transition.
- Текущий раздел и recovery path всегда понятны; role-specific items не исчезают без объяснимого state.
- На mobile навигация не должна вместе с action region занимать более 25% viewport.
- Все экраны используют публичный design-system API и русские пользовательские тексты.

## План

1. Составить role/state navigation matrix без изменения route contract.
2. Сгруппировать secondary items и реализовать компактную подачу.
3. Проверить labels, current location, back/recovery и profile secondary action.
4. Прогнать adaptive/semantics matrix.

## Критерии приёмки

- [ ] Для Host, Participant и Spectator определён набор видимых nav items для основных states.
- [ ] Вторичные разделы не конкурируют с primary content и доступны предсказуемым способом.
- [ ] Guards/routes/back behavior не изменены непреднамеренно.
- [ ] Профиль не делает изменение никнейма главным действием.
- [ ] Adaptive и semantics checks пройдены.
