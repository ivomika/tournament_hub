# TH-20260831-102: Исправить запуск Spectator Web

- Статус: Выполнена
- Создана: 2026-08-31
- Обновлена: 2026-08-31
- Источник: пользователь сообщил «не запускается spectator».

## Цель

Воспроизвести отказ запуска и сделать development-запуск Spectator Web и documented Host serving path однозначными и работоспособными на Windows без production build.

## Контекст

Spectator имеет отдельный Vite development server и статический bundle, который Flutter Host раздаёт после production build. Эти режимы нельзя смешивать: `make run-spectator` должен запускать Vite, а Host обязан безопасно сообщать об отсутствующем bundle.

## Границы задачи

### Входит

- Воспроизведение root/Make/Dart orchestration запуска Spectator Web.
- Исправление пути, команды или lifecycle процесса, если дефект подтверждён.
- Smoke-проверка HTTP development entry и документация точной команды запуска.

### Не входит

- Production build, signing и deploy.
- Изменение WebSocket v1, Host authority или tournament rules.
- Participant transport.

## Требования и ограничения

- Не запускать production build по прямому указанию пользователя.
- Windows и Unix-like интерфейс Makefile остаётся единым через Dart orchestrator.
- Исправление не должно добавлять mutation surface Spectator.

## Проверка

- `dart run tool/project.dart run-spectator`: Vite `8.2.2`, `http://localhost:5173`, process оставался активным до явной остановки.
- HTTP smoke: `/` = 200, `/fighters/scorpion.png` = 200; запрос `/api/...` на standalone Vite подтвердил отсутствие Host API и помог отделить режимы.
- `npm.cmd run format:check`, `npm.cmd run check`, `npm.cmd test`: успешно, 13 tests.
- `dart analyze tool/project.dart`: успешно; Dart format check — без изменений.
- `.vscode/launch.json` и `tasks.json`: JSON parse успешно, сохранены три tasks.
- `apps/spectator_web/dist/index.html`: отсутствовал — подтверждён источник plain Shelf `404 Not Found`.
- Новый `make run` не запускался, поскольку он намеренно включает Spectator preparation/build, а пользователь запретил запуск builds; порядок гарантирован orchestration, static serving покрыт существующим adapter test.

## Результат

`make run` и production VS Code launch теперь сначала выполняют `build-spectator`, затем запускают Flutter Host. Shelf получает ожидаемый `dist` и адрес из Host перестаёт вести на plain `404 Not Found`. `make run-spectator` оставлен отдельным Vite UI режимом и явно описан как не содержащий Host snapshot/WebSocket API.
