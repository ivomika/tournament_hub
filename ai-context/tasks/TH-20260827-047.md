# TH-20260827-047: Устранить overflow token showcase в Widgetbook

- Статус: Выполнена
- Создана: 2026-08-27
- Обновлена: 2026-08-27
- Источник: пользователь сообщил об overflow на странице Tokens в Widgetbook.

## Цель

Сделать `TokenShowcase` устойчивым к compact/mobile viewport и длинным именам токенов без выхода контента за доступную ширину.

## Контекст

После задачи `046` полный manifest выводится карточками внутри `Wrap`. Текущая карточка метрики не получает ограничение ширины и может расширяться по длине текста, из-за чего Widgetbook показывает overflow.

## Границы задачи

### Входит

- Исправление adaptive layout компонента `TokenShowcase` через его typed theme.
- Widget test на compact viewport и полный token showcase.
- Прогон architecture check и project quality gate.

### Не входит

- Изменение token manifest или значений токенов.
- Перестройка Widgetbook navigation и других компонентов/экранов.
- Build и интерактивный запуск приложения.

## Требования и ограничения

- Компонент продолжает читать только `TokenShowcaseTheme` и публичные DS components.
- Raw dimensions/colors не добавляются; adaptive ограничение задаётся через theme composition.
- Весь token manifest остаётся доступен и читаем.

## Журнал решений

- 2026-08-27 — исправление выполняется внутри `TokenShowcase`, а ширина карточки передаётся его typed theme, чтобы не создавать raw breakpoint/layout в runtime widget.
- 2026-08-27 — overflow оказался вертикальным; компонент получил собственный scroll container. Metric cards дополнительно ограничены фактической шириной `LayoutBuilder`, чтобы длинные token paths переносились.

## Результат

`TokenShowcase` теперь прокручивает полный manifest по вертикали и ограничивает каждую metric card доступной шириной. Regression test фиксирует compact viewport `320x480` и отсутствие Flutter overflow exception. Token manifest, theme architecture и остальные Widgetbook use cases не изменялись.
