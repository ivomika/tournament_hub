# TH-20260824-006: Добавить экран профиля и изменение nickname

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя добавить экран профиля с возможностью изменить nickname.

## Цель

Пользователь с локальным профилем может открыть экран профиля, увидеть актуальный nickname и изменить его с устойчивым локальным сохранением без изменения identity.

## Контекст

Экран использует тот же domain profile и repository contract, что и первый вход. Изменение nickname должно немедленно становиться доступным остальным presentation-сценариям через единое application state.

Зависимости:

- `TH-20260824-003` — domain-модель и операция изменения nickname.
- `TH-20260824-004` — сохранение обновлённого профиля.
- `TH-20260824-005` — bootstrap и созданный локальный профиль.

## Границы задачи

### Входит

- Application use case загрузки и изменения nickname.
- Экран просмотра локального профиля.
- Режим редактирования nickname, сохранение, отмена и состояния ошибки.
- Обновление общего presentation state после успешного сохранения.
- Адаптивный mobile-first layout для телефона и desktop.
- Widget/application tests просмотра и редактирования.

### Не входит

- Изменение identity профиля.
- Удаление профиля, logout и переключение между несколькими профилями.
- Аватар, статистика, достижения и другие поля профиля.
- Синхронизация nickname по сети с активной группой — для неё нужна отдельная задача при подтверждении требования.

## Требования и ограничения

- Экран не обращается к database client напрямую; работа проходит через application use case и repository contract.
- Неизменённый или невалидный nickname нельзя сохранять как новое состояние.
- UI сообщает об ошибке записи и сохраняет введённое значение для повторной попытки.
- Успешное изменение не меняет identity локального профиля.
- После успешного сохранения все потребители текущего profile state получают новый nickname.
- Desktop-композиция не растягивает форму на всю ширину и поддерживает клавиатуру/focus states.

## План

1. Добавить use case получения и изменения текущего профиля.
2. Реализовать presentation state просмотра, редактирования, сохранения и ошибки.
3. Реализовать адаптивный экран профиля и доступ к нему из основной части приложения.
4. Обеспечить обновление общего profile state после сохранения.
5. Добавить тесты успешного изменения, валидации, ошибки хранения и сохранения identity.

## Проверка

- Widget test просмотра: отображается текущий nickname.
- Widget tests изменения и отмены: nickname сохраняется или откатывается без лишней записи; identity остаётся прежней.
- Widget test ошибки storage: введённое значение сохраняется для повторной попытки.
- Widget test desktop `1200x800`: ширина формы не превышает 560 px, overflow отсутствует.
- Persistence test повторного открытия базы: профиль восстанавливается с сохранённой identity.
- Профильный набор: 20 тестов прошли; полный `make check` прошёл.
- `make build`: собраны spectator bundle и release APK размером 55,1 МБ.
- `flutter build macos`: собран release `tournament_app.app` размером 46,4 МБ.

## Журнал решений

- 2026-08-24 — сетевое распространение изменения nickname не включено, потому что запрос ограничен локальным профилем.
- 2026-08-24 — экран профиля использует единое profile state, чтобы другие UI-области не оставались с устаревшим nickname.

## Результат

Добавлен адаптивный экран профиля с просмотром nickname, входом в режим редактирования, отменой, сохранением и русскими сообщениями ошибок. Экран доступен из основной части приложения. `LocalProfileController` хранит единое profile state, сохраняет изменения через repository и обновляет все presentation-потребители только после успешной локальной записи. Изменение nickname сохраняет identity и переживает повторное открытие Drift-базы.
