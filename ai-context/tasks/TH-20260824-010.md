# TH-20260824-010: Добавить полный registry бойцов MK11

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя добавить registry бойцов Mortal Kombat 11.

## Цель

Приложение получает полный, проверяемый и заменяемый registry бойцов MK11 со стабильными идентификаторами и метаданными, доступный Tournament Core через абстрактный контракт.

## Контекст

Registry нужен как самостоятельный источник данных для будущего назначения бойцов участникам и связи с chibi assets. Конкретный список не должен быть зашит в domain или UI.

## Границы задачи

### Входит

- Domain entity/value objects бойца.
- Абстрактный `FighterRegistry` для получения полного списка и поиска по ID.
- Локальная data-реализация registry с каноническим набором MK11.
- Стабильные машиночитаемые ID, display name и ссылка на avatar asset ID.
- Validation уникальности ID и полноты данных.
- Tests контракта и локальной реализации.

### Не входит

- Генерация изображений — `TH-20260824-011`.
- Назначение бойцов участникам и правила уникальности внутри турнира.
- Загрузка registry из сети или удалённая конфигурация.
- UI просмотра roster.

## Требования и ограничения

- Domain зависит только от `FighterRegistry`, локальный список является заменяемым data adapter.
- Порядок списка детерминирован; ID не меняются при локализации display name.
- Registry не содержит Flutter widgets и не загружает bitmap assets самостоятельно.
- Под полным roster понимается MK11 Ultimate: 25 бойцов основной игры, 6 из Kombat Pack 1, 3 из Aftermath и 3 из Kombat Pack 2 — всего 37.
- Перед реализацией список и написание display names нужно проверить по первичному авторитетному источнику.

## План

1. Подтвердить целевое издание и точный состав roster.
2. Определить domain-контракт `FighterRegistry` и модель метаданных.
3. Реализовать локальный immutable dataset за data abstraction.
4. Добавить проверки уникальности ID, отсутствующих полей и стабильного порядка.
5. Документировать выбранный состав roster и источник проверки.

## Критерии приёмки

- [x] Подтверждено издание MK11 и задача переведена в `Готова`.
- [x] Registry содержит каждого подтверждённого бойца ровно один раз.
- [x] Каждый боец имеет стабильный ID, display name и avatar asset ID.
- [x] Domain работает через абстрактный registry contract.
- [x] Локальную реализацию можно заменить без изменения Tournament Core и UI use cases.
- [x] Dataset tests и `make check` проходят.

## Проверка

- Dataset test: ожидается подтверждённое число бойцов, уникальные ID и avatar asset ID.
- Contract test: поиск существующего/неизвестного ID и детерминированный список.
- `flutter analyze` и `make check`: ожидается успешное выполнение.

## Журнал решений

- 2026-08-24 — задача оставлена в `Черновик`, пока не подтверждено, относится ли «полный roster» к MK11 Ultimate или базовой версии.
- 2026-08-24 — registry проектируется как port + local adapter, чтобы позднее заменить dataset или источник без изменения domain.
- 2026-08-24 — по допущению из запроса «полный roster» выбран MK11 Ultimate; состав из 37 бойцов подтверждён официальными материалами WB Games, задача переведена через `Готова` в `В работе`.

## Результат

Созданы Equatable-модель бойца, value objects, port `FighterRegistry` и immutable adapter `Mk11UltimateFighterRegistry` с 37 бойцами. Официальные источники и состав записаны в `docs/product/mk11-roster.md`. Тесты проверяют количество, уникальность ID/avatar ID, детерминированность, поиск и неизменяемость. `make check` завершён успешно 2026-08-24.
