# TH-20260830-086: Зафиксировать app lifecycle и state-driven navigation contract

- Статус: Выполнена
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: запрос пользователя о новом `app`-потоке, bootstrap, composition и правиле «состояние управляет роутингом»

## Цель

Принять ADR и обновить каноническую документацию так, чтобы app lifecycle, bootstrap, composition и state-driven routing стали однозначным контрактом до реализации кода.

## Контекст

Сейчас architecture guide описывает `app` как bootstrap/router/DI, а screen map — что navigation отражает committed state, но не задаёт отдельную модель состояния приложения, порядок bootstrap и запрет прямой связи router с lifecycle mutation. Без этого разные разработчики могут реализовать переходы через ephemeral callbacks и сделать router владельцем состояния.

## Границы задачи

### Входит

- ADR-0011 с lifecycle state model, bootstrap pipeline, composition boundary и state-driven routing.
- Каноническое описание `AppState`/projection contract, условий переходов и восстановления после restart.
- Правило, что router подписывается на опубликованное состояние, но не вызывает lifecycle/domain transitions.
- Обновление architecture guide, screen map, traceability и ADR index.
- Migration/rollback и критерии, по которым последующие задачи реализуют контракт.

### Не входит

- Production Dart-код bootstrap, composition или router — задачи 087–088.
- Реализация tournament domain transitions и новых format engines.
- LAN server, port conflict, network reconnect и protocol changes; OD-013 остаётся отдельным решением.
- Изменение Flutter UI и visual layout.

## Требования и ограничения

- `AppState` — опубликованное read model приложения, а не mutable route state.
- Bootstrap владеет startup/recovery checks и публикует только валидные состояния.
- Router выбирает logical route по `AppState`; route callbacks не заменяют application commands.
- App lifecycle отделён от tournament lifecycle и connection state.
- Состояние считается authoritative после успешного local restore/commit; ephemeral navigation не создаёт truth.
- Каждая state transition имеет observable guard и recoverable error path.
- Неизвестные решения по OD-013 не угадываются и явно исключаются из scope.
