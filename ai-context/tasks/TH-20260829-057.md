# TH-20260829-057: Ввести полную матрицу состояний форм и действий

- Статус: Выполнена
- Создана: 2026-08-29
- Обновлена: 2026-08-29
- Источник: UX-аудит Widgetbook

## Цель

Сделать Registration, Join и Draft формы честными интерактивными состояниями с validation, focus, error, disabled, loading и success feedback.

## Границы задачи

### Входит

- Расширение публичного `DsTextField` state contract.
- Error/helper text, keyboard/input semantics, controller/onChanged/onSubmitted boundary.
- Матрица состояний `DsAction`, `DsTextField`, `Confirmation` в Widgetbook.

### Не входит

- Изменение profile/tournament validation rules или persistence.
- Реализация network handshake.

## Требования и ограничения

- Domain остаётся владельцем validation; UI только отображает результат.
- Заглушки preview не должны выглядеть как рабочая mutation без явного state.

- [x] Каждая форма показывает default/focus/error/disabled/loading/success.

## Проверка

- `make architecture` — успешно после вынесения keyboard action в публичный DS enum.
- `flutter analyze` — успешно, замечаний нет.
- `flutter test` — успешно, 65 тестов.
- Widgetbook содержит default/disabled, focus/validation, loading/success и три confirmation state.
- Component tests подтверждают visible focus, локальный error text, прозрачную передачу необработанного ввода наружу и недоступную loading action с live semantics.
- Golden matrix обновлена для Registration, Join и Draft; общая viewport/text-scale matrix проходит.

## Журнал решений

- 2026-08-29 — state matrix отделена от экранной полировки, чтобы не размножать форму-specific hacks.
- 2026-08-29 — задача активирована после 056. DS получает только presentation state и callbacks; правила допустимости nickname/code/title остаются за domain/application и в widget не переносятся.

## Результат

`DsTextField` получил controller/focus/callback boundary, helper/error, enabled, keyboard action и typed idle/loading/success state. `DsAction` получил typed idle/loading/success state, блокировку во время выполнения и доступное live announcement. Confirmation переведён на единую action hierarchy и покрыт idle/loading/success use cases. Registration, Join и Draft задают helper text и корректное действие клавиатуры, не выполняя business validation внутри widgets.

Итоговый routing сверен с diff: domain/application rules и persistence не менялись; UI отображает переданный validation result и возвращает сырой ввод владельцу состояния. Новый boundary/ADR не потребовался.
