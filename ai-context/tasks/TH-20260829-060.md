## Цель

Сделать `TournamentStandings` отображением authoritative places/results/tie-break context, а не генерацией демонстрационных очков внутри widget.

## Контекст и blocker

Сейчас компонент вычисляет значение вида `participants.length - index`. OD-006/OD-007 остаются открытыми, поэтому компонент переводится на готовые presentation rows и не определяет semantics place/result/tie-break самостоятельно.

## Границы задачи

### Входит

- Typed standings row contract с place, fighter identity, result context и tie-break marker.
- Desktop table и mobile compact rows/scroll.
- Empty/loading/unknown-place states.

### Не входит

- Изменение ranking engine, scoring или tie-break policy.
- Догадки по незакрытым OD.

## Требования и ограничения

- UI не рассчитывает очки, победы или places.
- После assignment каждая row показывает fighter artwork, fighter name и nickname.

## Результат

`TournamentStandings` больше не принимает список участников и не генерирует place/points. Новый `StandingRowViewData` требует готовые `placeLabel`, fighter/participant identity, `resultLabel` и optional `tieBreakLabel`. На широкой области renderer показывает table columns, на compact — семантически эквивалентные rows; loading, empty, ranged place и unknown place представлены явно. Preview fixtures вынесены отдельно и не являются ranking logic.

Итоговый routing сверен с diff: изменения ограничены presentation contract/renderer, previews, tests и design canon. Domain scoring, ranking, tie-break, persistence и DTO не затронуты; OD-006/007 не закрыты и новый ADR не требуется.
