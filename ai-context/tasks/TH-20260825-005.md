# TH-20260825-005: Реализовать Double Elimination Core

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос пользователя добавить режим Double Elimination; приложенное изображение 8-team bracket используется как визуальный ориентир.

## Цель

Tournament Core поддерживает заменяемый формат Double Elimination: участник выбывает после второго поражения, матчи корректно продвигают победителей и проигравших по winners/losers brackets, а финал определяет единственного champion.

## Контекст

Текущая реализация построена вокруг одного круга round robin (`TH-20260824-015`–`TH-20260824-020`). Новый режим требует отдельной bracket topology и progression policy, но общие participant snapshots, fighter assignment, best-of-three result и repository boundaries должны переиспользоваться без ветвления правил в UI/data слоях.

Приложенный визуальный ориентир показывает вариант для 8 участников: winners bracket сверху, losers bracket снизу, grand final справа и связи между матчами. Он не определяет все domain-правила.

## Границы задачи

### Входит

- Stable tournament format identity для round robin и Double Elimination.
- Чистые domain entities/value objects для bracket, slots, matches и связей продвижения.
- Генерация winners/losers topology для произвольного конечного состава от двух участников с дополнением bracket до ближайшей степени двойки через `bye`.
- Продвижение winner и loser после подтверждённого best-of-three match result.
- Инвариант двух поражений для выбывания и определение единственного champion.
- Формат-независимые application contracts и стратегии, позволяющие добавлять другие форматы.
- Domain/property/invariant tests.

### Не входит

- Drift persistence — `TH-20260825-006`.
- Новый bracket UI — `TH-20260825-007`.
- Сетевая синхронизация и spectator projection.
- Изменение правил отдельных best-of-three матчей.

## Требования и ограничения

- Core остаётся чистым Dart и не знает о Flutter, Drift, координатах UI или приложенном изображении.
- Round robin поведение и существующие snapshots не должны регрессировать.
- Match identity и bracket edges стабильны и детерминированы для persistence/reconnect.
- Результат применяется идемпотентно; исправление завершённого матча не может оставить downstream bracket в противоречивом состоянии.
- Fighter assignment остаётся отдельной стратегией и не дублируется внутри bracket generator.
- Количество участников сверху не ограничивается; действующий общий minimum — два участника.
- Начальный seeding выполняется случайно через внедряемый источник случайности и воспроизводим в tests.
- Недостающие slots до ближайшей степени двойки заполняются `bye`, которые случайно распределяются между участниками через внедряемый источник случайности.
- Grand-final reset обязателен: если champion losers bracket выигрывает первый grand final у ранее непобеждённого champion winners bracket, проводится второй решающий матч.
- Если основная bracket topology не даёт уникальные итоговые места, все участники с общим местом проводят отдельный placement replay round robin друг с другом. При повторном равенстве весь исходный состав этого спорного места переигрывает этап до получения уникального порядка.
- Исправление upstream result запускает пересчёт: результаты всех затронутых downstream matches инвалидируются, entrants/losses/advancement строятся заново; незатронутые ветви сохраняются.

## План

1. Выделить format strategy без изменения общих participant/match concepts.
2. Реализовать воспроизводимый случайный seeding и распределение `bye` через внедряемый источник случайности.
3. Реализовать детерминированную topology winners и losers brackets после seeding.
4. Реализовать advancement/elimination, обязательный grand-final reset и placement replay round robin.
5. Реализовать контролируемую инвалидацию и полный пересчёт зависимой части bracket после исправления.
6. Добавить invariant/property tests для произвольного состава, `bye`, reset, replay и исправлений.
7. Обновить tournament rules и архитектурные решения.

- [x] Каждый проигравший winners bracket попадает в определённый topology slot losers bracket.

## Проверка

- Golden topology tests для 8 участников по структуре приложенного ориентира.
- Tests произвольных размеров, включая 2, 3, степени двойки и составы с несколькими случайными `bye`.
- Progression tests winners → losers → elimination → grand final.
- Grand-final reset tests: победа winners champion без reset и победа losers champion через обязательный второй финал.
- Placement replay round-robin tests для двух, трёх и более участников, включая повторное равенство и новый полный этап для сохранившей равенство группы.
- Property tests: максимум два поражения, уникальный champion, стабильные match IDs, отсутствие self-match.
- Correction/recalculation tests с очисткой зависимых результатов и сохранением независимой ветви.
- Полный round robin regression suite и `make check`.
