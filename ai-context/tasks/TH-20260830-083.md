# TH-20260830-083: Выровнять desktop header actions по границе контента

- Статус: Выполнена
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: замечание пользователя после визуальной проверки задачи 082

## Цель

Сделать desktop-композицию страницы цельной: заголовок, действия и основной контент должны иметь общую левую и правую границу, чтобы toolbar не улетал к правому краю широкого окна за пределы content frame.

## Контекст

`AppShell` уже ограничивает body через `contentMaxWidth`, но `PageHeader` строится на всей доступной ширине scrollable canvas. Поэтому desktop actions выравниваются по окну, а не по последнему элементу основного контента. Это нарушает визуальный контур страницы и особенно заметно на широких viewport.

## Границы задачи

### Входит

- Единый content frame для `PageHeader` и body внутри `AppShell`.
- Выравнивание desktop `ActionDock`/`ResponsiveActions` по правой границе основного контента.
- Проверка всех Flutter screen previews и обновление затронутых desktop goldens.
- Уточнение дизайн-канона о том, что «правый край page layout» означает content frame, а не край окна.

### Не входит

- Изменение mobile ActionDock, navigation rail/bar или порядка действий.
- Изменение ширины отдельных `PageLayout` regions, typography, domain или networking.
- Индивидуальные отступы и screen-specific max width.

## Требования и ограничения

- Header и body используют один `AppShellTheme.contentMaxWidth` и одну alignment policy.
- На viewport уже `contentMaxWidth` поведение не меняется.
- Desktop primary остаётся крайним правым control внутри content frame; contextual/overflow остаются слева.
- Решение применяется централизованно в design system и не требует изменений каждого screen.

## План

1. Закрепить общий content-frame contract тестом `AppShell` на широком desktop viewport.
2. Ограничить header тем же `contentMaxWidth`, что и body, сохранив left alignment и responsive wrapping.
3. Перегенерировать desktop viewport/full-page/role goldens и визуально проверить все screen previews.
4. Обновить design canon и выполнить полный quality gate.

## Журнал решений

- 2026-08-30 — Правой границей desktop toolbar считается правая граница `AppShell` content frame, а не край доступного canvas после navigation rail.
- 2026-08-30 — Новая ширина или screen-level параметр не вводятся: header переиспользует существующий `contentMaxWidth` body.

## Результат

`AppShell` теперь строит `PageHeader` и body через один left-aligned content frame с существующим `contentMaxWidth`. На широком desktop header toolbar больше не выравнивается по краю окна: его primary action совпадает с правой границей основной композиции. Добавлены геометрический regression test, wide-desktop golden и уточнение дизайн-документации; mobile и стандартные desktop layouts не изменились.
