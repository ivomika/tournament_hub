# TH-20260824-020: Добавить start-to-end flow, итоги и экран чемпиона

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-25
- Источник: запросы пользователя изменить UI проведения, добавить start-to-end сценарий, подведение итогов и экран чемпиона.

## Цель

Host проходит единый адаптивный сценарий от запуска или восстановления турнира до подведения итогов и отдельного экрана чемпиона. UI отображает результат выбранного ruleset, но не знает конкретных scoring, tie-break и champion selection правил.

## Контекст

`TH-20260824-016` показывает обзор и статичную матрицу tournament rounds, но не поддерживает выбор победителя и завершение. Новые экраны должны использовать match engine `TH-20260824-017`, persistence `TH-20260824-018` и standings/champion `TH-20260824-019`, не вычисляя правила в presentation.

Зависимости:

- `TH-20260824-011` — fighter avatars и resolver;
- `TH-20260824-016` — текущие обзор/раунды и navigation flow;
- `TH-20260824-017` — ввод схваток и match result;
- `TH-20260824-018` — устойчивое состояние и ошибки записи;
- `TH-20260824-019` — standings, finish eligibility и champion;
- `TH-20260824-023` — воспроизводимое сохранение ruleset и завершённого результата;
- `TH-20260824-022` — уже реализованный ввод и исправление результата схваток;
- разделы 72–73 и end-to-end шаги 18–19 [Technical Design Document](../../docs/architecture/tournament-hub-technical-design.md) требуют result editing и полного пересчёта standings;
- условие готовности: `TH-20260824-019` переведена в `Готова` и подтверждены UI-состояния tie-break.

## Границы задачи

### Входит

- Встраивание реализованного в `TH-20260824-022` проведения матчей в полный start-to-end flow.
- Восстановление незавершённого турнира при повторном входе в приложение.
- Актуальная standings/points область на экране турнира после каждого результата.
- Действие завершения, доступное только при domain-разрешении.
- UI разрешения tie, если подтверждённая policy требует ручного Host-решения.
- Отдельный адаптивный экран завершённого турнира с champion, итоговой таблицей и понятным переходом из active flow.
- Экран подведения итогов до фиксации завершения: полная таблица, применённый ruleset, незавершённые условия или причина необходимости tie-break.
- Единый presentation-компонент упоминания участника: nickname вместе с fighter avatar и display name во всех затронутых tournament/match/standings/champion областях.
- Phone/tablet/desktop layouts, keyboard/focus states и widget/integration tests полного сценария.
- Актуализация пользовательской документации.

### Не входит

- Изменение scoring/tie-break правил в UI.
- Сетевой Host/Participant flow и spectator projection.
- Career, achievements и постоянная история завершённых snapshot.
- Изменение состава, выход участника и автоматические технические результаты, если они не реализованы отдельной задачей.

## Требования и ограничения

- Presentation отправляет application-команды и отображает domain state; оно не вычисляет счёт, standings, победителя или champion самостоятельно.
- UI зависит от стабильной проекции standings/completion и не ветвится по конкретному ruleset; изменение policy не требует переписывать widgets.
- Упоминание участника в затронутом турнирном UI всегда содержит три элемента: nickname, avatar назначенного бойца и display name бойца. Исключение допустимо только для технической ошибки отсутствующих данных и должно иметь явный fallback.
- Avatar разрешается через `FighterAvatarResolver`, а fighter metadata — через `FighterRegistry`; asset paths не формируются widgets.
- Внутренние схватки визуально вложены в конкретный матч и не смешиваются с номером tournament round.
- UI сообщает об успехе только после подтверждения repository; recoverable error сохраняет выбранные данные для retry.
- Исправление результата не выполняется неявно: UI показывает текущее значение, запрашивает подтверждение замены и после успеха отображает полностью пересчитанные standings.
- Завершение недоступно при незавершённых матчах или неразрешённом tie.
- Champion screen получает вычисленный domain-result и не позволяет вручную заменить чемпиона.
- Mobile-first layout сохраняет основные действия в зоне доступности; desktop использует дополнительную колонку/master-detail только при достаточной ширине.

## Проверка

Заполняется фактическими результатами в ходе работы.

- Widget test одного матча `2:0` и `2:1`: ожидаются отдельные схватки, верный счёт и блокировка лишнего ввода.
- Persistence/retry widget test: ошибка не подтверждает результат, повтор сохраняет тот же выбор.
- Result editing test: подтверждённое исправление заменяет счёт и обновляет standings; отмена и storage error сохраняют прежнее авторитетное состояние.
- Rounds widget test: planned/in-progress/completed states, счёт и победитель визуально различимы.
- Participant mention audit test: в overview, rounds, match, standings и champion для каждой ссылки на participant присутствуют avatar и fighter name.
- Finish tests: незавершённый турнир и tie блокируют действие; полный уникальный итог открывает champion screen.
- Layout tests узкого телефона, широкого телефона/планшета и desktop resize без overflow.
- `make check` и production build: ожидается успешное выполнение.

- 2026-08-24 — создан обязательный participant-with-fighter visual contract для затронутого турнирного UI: nickname без avatar и имени бойца считается неполным отображением.

- 2026-08-24 — пользователь подтвердил возможность исправления результата; неизвестность снята, но задача остаётся `Черновик` до утверждения scoring/tie-break в `TH-20260824-019`.

- 2026-08-24 — запрос расширен до start-to-end flow с отдельными экранами предварительных итогов и чемпиона. Проведение схваток считается готовой зависимостью `TH-20260824-022`, а UI обязан оставаться независимым от конкретного ruleset.
- 2026-08-25 — после последовательного завершения `TH-20260824-019` и `TH-20260824-023` задача переведена через `Готова` в `В работе`; завершение выполняется только через domain outcome и устойчивый snapshot.
- 2026-08-25 — добавлены предварительные итоги, champion screen, обработка retry и восстановление finished flow; задача завершена.

## Результат

Rounds завершаются экраном предварительных итогов с полной таблицей, ruleset и причиной недоступности finish. При полном уникальном результате кнопка атомарно сохраняет snapshot и открывает отдельный экран champion; ошибка остаётся на итогах и допускает retry. После перезапуска сохранённый snapshot открывается без пересчёта, а редактирование завершённых матчей заблокировано. Widget suite покрывает start-to-end, correction, ошибки записи, reopen и phone/desktop layout. При оставшемся равенстве UI корректно блокирует finish и сообщает о необходимости отдельного Tie-Break Stage; генерация этого дополнительного этапа не входила в реализованную standings projection.
