# TH-20260831-117: Реализовать каноничные Spectator brackets с zoom/fullscreen

- Статус: Выполнена
- Создана: 2026-08-31
- Обновлена: 2026-08-31
- Источник: запрос пользователя; Spectator/Турнир должен показывать каноничные DE/SE/RR brackets с высоким performance.

## Цель

Дать зрителю отдельную каноничную визуализацию сетки для Double Elimination, Single Elimination и Round Robin с pan/zoom и fullscreen, не перенося domain progression в React.

## Контекст

Текущий operational MatchList не заменяет bracket presentation. Web получает versioned read-only projection; связи, current/result и identity должны быть видимы с distance и на TV.

## Границы задачи

### Входит

- DE winner/loser brackets, Grand Final и Reset.
- SE rounds/finals и RR round/pairings/standings composition.
- Zoom, pan, fullscreen, fit-to-screen, keyboard alternative и performance budget.

### Не входит

- Изменение format engines, seeding, Bye, ranking или protocol schema.
- Host Structure renderer и mobile operational MatchList.

## Требования и ограничения

- Renderer выбирается по `formatId`, данные и progression остаются в Host projection.
- DE должен быть каноничным: winners/losers lanes, transfers, Grand Final и reset semantics.
- На TV/desktop не рендерить все узлы тяжёлым DOM способом без измерения performance; на compact должен быть доступен список/альтернатива.
- Fullscreen не скрывает exit/focus affordance.

3. Добавить TV/desktop/compact fixtures, performance и accessibility gates.

## Критерии приёмки

- [x] DE визуально содержит обе сетки, Grand Final и Reset; связи не теряются.
- [x] SE и RR имеют отдельные каноничные композиции без ложных DE-элементов.
- [x] Zoom/pan/fullscreen работают мышью, touch и клавиатурой; есть fit/reset.
- [x] 500+ nodes fixture не блокирует UI и укладывается в согласованный budget.
- [x] React не содержит progression/ranking calculations.

## Проверка

- `npm test`, `npm run check`, browser screenshots, keyboard/accessibility сценарии и performance fixture.
- Непроведённые проверки и фактический budget фиксируются исполнителем.
- `npm.cmd test` — успешно, 6 suites / 23 tests; весь suite занял 640 ms, включая DOM fixture из 500 matches с отдельным budget `< 2500 ms`.
- `npm.cmd run check` — успешно (`tsc -b` и `oxlint`).
- Interaction tests покрывают buttons/wheel/keyboard zoom, keyboard/touch-pointer pan, fit/reset и fullscreen exit affordance; model tests покрывают DE/SE/RR compositions.
- Browser screenshots пропущены: в сессии нет подключённого Browser backend; риск — отсутствие ручной TV/compact pixel-level проверки. Production build не запускался по указанию пользователя.

## Журнал решений

- 2026-08-31 — Spectator получает отдельный bracket renderer; Host operational Structure остаётся MatchList.
- 2026-08-31 — renderer группирует только переданные `formatId/stageId/round/order`, не выводит winner progression, seeding, Bye, ranking или result links. Architecture/authority и wire schema не меняются, поэтому новый ADR не требуется; серьёзное UI-решение зафиксировано в design canon и screen map. Rollback — вернуть прежний read-only stage list без изменения protocol/Host.

## Результат

Spectator Tournament View получил отдельный format-aware bracket viewport. DE разделён на winners/losers/finals с Grand Final и Reset, SE и RR используют собственные round compositions. Canvas поддерживает pan/zoom/fullscreen/fit/reset для mouse, touch и keyboard, сохраняет текстовый DOM order и fullscreen exit control; `content-visibility` ограничивает стоимость больших сеток. Presentation mapper лишь переносит public `formatId/stageId/round/order`; protocol, Host authority и progression остаются неизменными.
