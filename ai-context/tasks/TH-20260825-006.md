# TH-20260825-006: Сохранять прогресс Double Elimination

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос пользователя добавить локальный режим Double Elimination в local-first приложение.

## Цель

Активный Double Elimination tournament и его завершённый immutable snapshot атомарно сохраняются локально и после reopen восстанавливают ту же bracket topology, slots, результаты, поражения и champion.

## Контекст

Текущие active/finished repositories и Drift schema реализованы для round robin в `TH-20260824-018` и `TH-20260824-023`. Double Elimination Core из `TH-20260825-005` добавляет format-specific state, которое нельзя терять или выводить только из текущего UI.

Зависимости:

- `TH-20260825-005` — подтверждённая topology и progression semantics;
- `TH-20260825-003` — append-only история finished snapshots.

## Границы задачи

### Входит

- Persistence projection format identity и Double Elimination bracket state.
- Drift tables/migration, Freezed models и отдельные mappers.
- Атомарное сохранение topology, случайного seeding, slots, `bye`, results, losses, advancement, grand-final reset и placement replay state.
- Reopen active tournament и append-only finished snapshot/history.
- Repository contract tests, rollback, migration и corrupted-state handling.

### Не входит

- Bracket generation/progression rules — `TH-20260825-005`.
- Presentation — `TH-20260825-007`.
- Cloud/network sync.

## Требования и ограничения

- Application зависит от format-neutral repository ports, а не от Drift tables.
- Stable match/slot/edge IDs из Core сохраняются без пересоздания на reopen.
- Вся авторитетная bracket mutation сохраняется транзакционно до сообщения об успехе.
- Finished snapshot содержит достаточно данных для read-only history detail без повторного расчёта текущей policy.
- Migration сохраняет существующие round robin active/finished tournaments и history.
- Schema не должна представлять Double Elimination как набор round robin rounds с особыми номерами.
- Случайные seeding и `bye` сохраняются как часть авторитетной topology и не разыгрываются заново на reopen.
- Исправление upstream result сохраняет пересчитанную topology и удаление невалидных downstream results в одной транзакции.
- Grand-final reset и каждый placement replay round robin сохраняются как отдельные format-specific stages, а не маскируются под основные bracket matches.
- Domain-модель `TH-20260825-005` завершена; persistence сохраняет её авторитетное состояние без повторной генерации.

## План

1. После завершения Core определить format-neutral persistence envelope и DE data models.
2. Добавить schema/migration для bracket topology и state.
3. Реализовать atomic save/reopen active bracket, включая `bye` и пересчитанные downstream branches.
4. Расширить finished snapshot/history reset и placement replay details.
5. Добавить round-trip, rollback, migration и corruption tests.
6. Обновить ADR локального хранения.

## Проверка

- Round-trip/reopen active bracket на нескольких стадиях.
- Reopen после случайного seeding с несколькими `bye`: порядок и распределение остаются идентичными.
- Correction transaction test: downstream results удалены, независимая ветвь сохранена.
- Grand-final reset и placement replay round-trip tests.
- Transaction rollback при ошибке записи slot/result.
- Finished snapshot/history reopen с champion.
- Migration из актуальной round robin schema.
- Corrupted edge/slot reference возвращает нормализованную storage error.
- `make generate`, `flutter analyze`, `make check`.
