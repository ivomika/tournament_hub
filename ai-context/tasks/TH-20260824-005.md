# TH-20260824-005: Добавить первый экран ввода nickname

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя добавить первый экран авторизации с вводом nickname.

## Цель

Пользователь без локального профиля при первом запуске видит экран ввода nickname, создаёт профиль и после успешного локального сохранения переходит в основную часть приложения.

## Контекст

Под «авторизацией» в этой задаче понимается локальное создание профиля без сервера, пароля и онлайн-аккаунта. При существующем профиле экран первого входа показываться не должен.

Зависимости:

- `TH-20260824-003` — domain-модель и repository contract.
- `TH-20260824-004` — устойчивое локальное хранение профиля.

## Границы задачи

### Входит

- Application use case загрузки или создания локального профиля.
- Стартовое состояние загрузки профиля.
- Mobile-first экран ввода nickname.
- Отображение domain validation и ошибок сохранения.
- Переход в основную часть приложения только после успешной записи.
- Адаптивная компоновка для desktop без растягивания формы на всю ширину.
- Widget/application tests основного сценария.

### Не входит

- Пароль, email, внешняя identity и сетевая авторизация.
- Выбор из нескольких локальных профилей.
- Дополнительные поля профиля, аватар и выбор бойца.
- Финальный визуальный дизайн за пределами базовой дизайн-системы приложения.

## Требования и ограничения

- Экран показывается только при отсутствии сохранённого локального профиля.
- Нельзя перейти дальше с невалидным nickname или до завершения сохранения.
- Повторное нажатие во время сохранения не должно создавать дубликаты операций.
- Ошибка хранения отображается явно и позволяет повторить действие.
- На телефоне форма оптимизирована для клавиатуры и доступна без overflow; на desktop имеет ограниченную ширину и адаптивное позиционирование.
- Состояние UI зависит от application use case, а не обращается к database client напрямую.

## План

1. Добавить use case определения начального состояния и создания профиля.
2. Связать bootstrap приложения с состояниями loading, profile missing и profile available.
3. Реализовать форму nickname и обработку отправки/ошибок.
4. Реализовать переход после устойчивого сохранения профиля.
5. Добавить widget и application tests для первого и повторного запуска.

## Критерии приёмки

- [x] При отсутствии профиля первым показывается ввод nickname.
- [x] Валидный nickname сохраняется, после чего открывается основная часть приложения.
- [x] При существующем профиле экран ввода пропускается.
- [x] Невалидный nickname и ошибка сохранения имеют понятное русское сообщение.
- [x] Повторное действие во время сохранения защищено от дубликатов.
- [x] Экран корректно адаптируется к телефону и desktop-окну.
- [x] Widget/application tests и полный `make check` проходят.

## Проверка

- Widget test без профиля: форма nickname показана, после сохранения открывается основная часть.
- Widget test с сохранённым профилем: форма пропущена.
- Widget test ошибки storage: сообщение показано, кнопка повторной попытки активна.
- Widget test повторного сохранения: кнопка блокируется до завершения операции.
- Widget test при размере `1200x800`: ширина формы не превышает 440 px, overflow отсутствует.
- Профильный набор: 14 тестов прошли.
- После завершения связанного экрана профиля полный `make check` прошёл.

## Журнал решений

- 2026-08-24 — термин «авторизация» трактуется как локальный onboarding профиля, поскольку запрос относится к локальным профилям и не содержит требований онлайн-аутентификации.

## Результат

Добавлены `LocalProfileController`, profile gate и адаптивный mobile-first экран первого входа. Приложение загружает профиль при старте, показывает onboarding только при его отсутствии, блокирует повторное сохранение, отображает ошибки и переходит в основную часть только после успешной записи. Production composition использует Drift repository, тесты — fake repository.
