# TH-20260831-108: Подключить перераспределение fighters в Distribution

- Статус: Выполнена
- Создана: 2026-08-31
- Обновлена: 2026-08-31
- Источник: пользовательский аудит экрана раздачи персонажей.

## Цель

Сделать действие перераспределения fighters рабочим: по нажатию создаётся новый допустимый assignment и экран показывает его результат.

## Контекст

Кнопка перераспределения присутствует на Distribution, но не вызывает изменения состояния и не даёт Host понять, что операция выполнена.

## Границы задачи

### Входит

- Подключение кнопки к application/domain command reroll.
- Loading, success, error и повторное отображение assignments.
- Защита от duplicate tap и сохранение уникальности fighter assignments.
- Проверка role/state guard Distribution.

### Не входит

- Изменение fighter registry, roster или алгоритма random seeding.
- Изменение правил турнира и форматов.

## Требования и ограничения

- Domain остаётся владельцем допустимого распределения.
- Операция не должна применяться после начала Running или в terminal state.
- UI не реализует генерацию случайности самостоятельно.

## Критерии приёмки

- [x] Нажатие перераспределяет fighters и меняет видимый assignment.
- [x] Повторное нажатие не запускает параллельные операции.
- [x] Fighters не дублируются и соответствуют registry.
- [x] Ошибка объясняется и не теряет прежний committed assignment.
- [x] Команда недоступна вне Distribution.

## Журнал решений

- 2026-08-31 — случайность и допустимость остаются в Domain; presentation только отправляет команду и показывает результат.
- 2026-08-31 — обновление содержимого Distribution передаётся отдельным stream projection. Lifecycle state остаётся единственным источником route, поэтому content mutation не маскируется под навигацию и не связывает router с revision турнира.

## Результат

Кнопка перераспределения вызывает application command, блокирует повторный tap и показывает безопасный success/error feedback. После атомарного сохранения aggregate composition публикует новую Host projection, поэтому Distribution немедленно перестраивается даже при неизменном lifecycle route. Domain guard запрещает операцию вне Distribution, а интеграционный тест подтверждает новый уникальный fighter для каждого участника.
