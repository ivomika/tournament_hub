# TH-20260827-044: Добавить минимальные application skeletons и cross-platform Makefile

- Статус: Выполнена
- Создана: 2026-08-27
- Обновлена: 2026-08-27
- Источник: пользователь запросил первичную структуру проекта и кроссплатформенные команды build/run без преждевременных папок внутри приложений.

## Цель

Получить минимальные запускаемые Flutter и React Spectator application skeletons и единый root Make interface, который одинаково оркестрирует setup, run и build обоих приложений на Windows, macOS и Linux без shell-specific логики.

## Контекст

Architecture canon определяет Flutter Host/Participant и read-only React Spectator. После уточнения пользователя задача bootstrap-ит оба приложения, но не создаёт внутренние layers/features до появления их implementation scope.

## Границы задачи

### Входит

- Минимальный Flutter project `apps/tournament_app` с официальными platform runners.
- Минимальный React/Vite project `apps/spectator_web`.
- Только необходимый `lib/main.dart`, smoke/widget test и Flutter metadata/config.
- Root `Makefile` как thin interface и cross-platform Dart orchestration script для обоих приложений.
- Команды `setup`, `run`, `build`, `format`, `lint`, `test`, `check` и справка.
- Документация фактических команд и bootstrap state.

### Не входит

- Domain/application/infrastructure/presentation folders и business logic.
- LAN transport, spectator realtime/data model и persistence.
- Фиксация production platform support matrix из OD-009, signing/installer/CI.
- Применение design tokens/theme beyond placeholder shell.

## Требования и ограничения

- Не создавать speculative directories внутри application.
- Makefile не использует bash/cmd/PowerShell branching; platform selection выполняет Dart script.
- `make run` принимает optional `DEVICE`; без него Flutter выбирает доступный device.
- `make build` принимает optional `TARGET`; default выбирается по host OS, explicit targets валидируются.
- Сгенерированные platform runners — development skeleton, а не решение OD-009 о production support.

- `flutter create ... --empty`: success, dependencies resolved, official Android/iOS/Linux/macOS/Web/Windows runners созданы.
- `make help`: exit 0 в Windows PowerShell/GNU Make, все команды и параметры показаны.
- `make format`: exit 0, три Dart files отформатированы.
- `make check`: exit 0; format check без изменений, `flutter analyze` — no issues, `flutter test` — 1/1 passed.
- `make --dry-run run DEVICE=windows` и `make --dry-run build TARGET=web`: корректные аргументы передаются Dart script.
- `dart run tool/project.dart build --target invalid`: ожидаемый отказ и exit 64 без запуска build.
- Markdown link scan: broken links отсутствуют; generated `.dart_tool/.idea/build` artifacts не попадают в Git.
- `git diff -- docs/source`: пусто; `git diff --check`: ошибок нет, только предупреждения Git о будущей LF/CRLF normalization.
- `make run` и реальный `make build` не запускались: первая команда интерактивна, вторая создаёт тяжёлые platform artifacts и не нужна для проверки orchestration.
- Node dependencies установлены через `npm.cmd`; audit сообщает 0 vulnerabilities.
- Повторный `make check`: Prettier check успешен, Flutter analyze без issues, Flutter test 1/1, Spectator `tsc -b && oxlint` без diagnostics.
- Dry-run общего и изолированных build targets подтвердил Make routing. Dart orchestrator вызывает Flutter build, затем Spectator `npm run build`; реальные builds не запускались согласно прежнему запрету пользователя.

## Журнал решений

- 2026-08-27 — cross-platform branching размещается в Dart orchestration, Makefile остаётся одинаковым для GNU Make на всех host OS.
- 2026-08-27 — platform runners bootstrap-ятся для development portability, но не закрывают OD-009 и не обещают release support.
