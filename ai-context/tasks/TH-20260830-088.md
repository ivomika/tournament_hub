# TH-20260830-088: Реализовать state-driven router и logical navigation

- Статус: Выполнена
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: реализация navigation projection после `TH-20260830-086` и `TH-20260830-087`

## Цель

Подключить router к опубликованному `AppState`, чтобы logical route и guards всегда отражали committed application/tournament state, а навигационные callbacks не меняли lifecycle.

## Контекст

Screen map уже требует, чтобы navigation отражала committed state, но текущий поток не имеет одного state-driven router adapter. Без него route callbacks могут начать напрямую открывать следующий экран или дублировать Domain transition.

## Границы задачи

### Входит

- Router adapter, который слушает AppState projection и выбирает logical routes.
- Guards profile, active tournament, role, binding и terminal/read-only state.
- Mapping loading/ready/needsProfile/recoverable/fatal/active states в route compositions.
- Deep-link and back behavior без lifecycle mutation.
- Подключение router к composition через публичные contracts.

### Не входит

- Изменение AppBootstrap state machine — 087.
- Изменение Domain/application command semantics.
- Новый UI layout, visual components или route-specific business decisions.
- Concrete go_router choice, если он не требуется каноном; logical contract важнее библиотеки.

## Требования и ограничения

- Router получает только read-only AppState projection и presentation route model.
- Route selection идемпотентен: одинаковое состояние даёт одинаковую logical route.
- Guard failure возвращает безопасный route/error projection и не вызывает mutation.
- Back/Main сохраняет active state; terminal snapshots остаются read-only.
- Deep link не переводит lifecycle и не создаёт active tournament.
- Router не импортирует concrete infrastructure/platform и не вызывает Domain/application command для перехода.
- State changes после application command приводят к новой route projection.

## План

1. Определить typed route projection и mapping всех AppState variants.
2. Реализовать guards для profile/active/role/binding/terminal/deep-link.
3. Подключить state subscription в composition и обеспечить идемпотентные transitions.
4. Добавить route/widget tests для happy/error/stale/read-only/back cases.

## Критерии приёмки

- [x] Каждый AppState имеет единственную logical route projection или безопасный error fallback.
- [x] Router не вызывает lifecycle/domain/application mutation при route selection, back или deep link.
- [x] Guards блокируют недопустимые role/state/binding и не теряют committed state.
- [x] Finished/Cancelled/history routes read-only.
- [x] Router не импортирует concrete infrastructure/platform.
- [x] Tests подтверждают state changes → route changes и отсутствие обратного влияния.
- [x] Rule routing повторно сверён с итоговым diff.

## Журнал решений

- 2026-08-30 — Router является pure projection/adapter поверх AppState, а не state owner.
- 2026-08-30 — Logical route IDs остаются каноном; библиотека маршрутизации не определяет lifecycle.

## Результат

Реализованы immutable `NavigationIntent`/`AppRouteProjection`, pure `AppRoutePolicy`, history-aware `NavigationIntentStore` и reactive `AppRouter`. Policy исчерпывающе маппит AppState, Host/Participant lifecycle, role/tournament/snapshot guards и typed failures. Router подписывается на read-only AppState, но не получает writer/application commands.

`AppComposition` теперь собирает router, `TournamentHubApp` отображает route projection и обрабатывает system Back через navigation history. `AppNavigationScope` подключает существующие AppShell destinations к intent sink без импорта app в presentation. Recoverable retry вызывает runtime bootstrap, fatal state не показывает retry.

Проверки: `make architecture` — layer/design-system gates успешны; `flutter analyze` — issues отсутствуют; targeted bootstrap/router/widget/smoke suite — 19 tests успешно; widget test подтверждает Main → Profile → Back → Main; `git diff --check` — успешно; `rg` подтвердил отсутствие Domain/infrastructure/bootstrap writer coupling в navigation. Финальный routing: core 00/01/08/10/11 и conditional 02/07/09 соблюдены; Domain/data/network/design semantics не менялись.
