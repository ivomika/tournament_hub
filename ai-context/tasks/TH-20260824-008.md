# TH-20260824-008: Разделить profile domain/data по ответственности

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя разделить `domain` и `data` на понятные подпапки, не хранить объекты разных ответственностей в одном файле и закрепить правила.

## Цель

Profile feature имеет однозначную структуру каталогов и файлов по ответственности без смешения entity, value object, exception, mapping и repository implementation.

## Контекст

После реализации локального профиля несколько domain-типов находятся в `local_profile.dart`, repository exception объединена с контрактом, а data DTO одновременно выполняет mapping. Это затрудняет навигацию и размывает границы ответственности.

## Границы задачи

### Входит

- Разделение `domain` на `entities`, `value_objects`, `repositories` и `exceptions`.
- Разделение `data` на `database/tables`, `models`, `mappers` и `repositories`.
- Выделение разных типов ответственности в отдельные файлы.
- Обновление импортов, generated parts и тестов без изменения поведения.
- Закрепление общих правил структуры в `AGENTS.md`.

### Не входит

- Изменение бизнес-правил локального профиля.
- Изменение UI и пользовательских сценариев.
- Перестройка остальных пустых feature до появления в них реализации.

## Требования и ограничения

- Один файл имеет одну основную ответственность и, как правило, один публичный production-тип.
- Entity не содержит объявления value objects или exceptions.
- DTO/model не отвечает за mapping между слоями.
- Generated-файлы перемещаются только через изменение исходного `part` и повторный code generation.
- Публичные имена и поведение сохраняются, чтобы реорганизация не меняла контракты.
- Приватные helpers допустимы рядом с основным типом, если они обслуживают только его реализацию и не имеют самостоятельной ответственности.

## План

1. Создать целевую структуру `domain` и перенести типы по ответственности.
2. Создать целевую структуру `data`, выделить mapper и перенести Drift table/repository/Freezed model.
3. Обновить все production/test imports и database composition.
4. Зафиксировать правила структуры в `AGENTS.md`.
5. Повторно сгенерировать Drift/Freezed-код.
6. Запустить форматирование, анализ, тесты и сборку.

## Критерии приёмки

- [x] В корне `domain` и `data` нет production-файлов со смешанной ответственностью.
- [x] Entity, value objects, exceptions и repository contract разделены.
- [x] Table, Freezed model, mapper и Drift repository разделены.
- [x] Generated-код успешно создан по новым путям.
- [x] Правила закреплены в `AGENTS.md`.
- [x] `make check` и Flutter-сборка проходят.

## Проверка

- `find` для profile feature: подтверждены отдельные `entities`, `value_objects`, `repositories`, `exceptions`, `database/tables`, `models`, `mappers` и data `repositories`.
- `make generate`: успешно; Freezed output создан рядом с `data/models/local_profile_data.dart`, Drift output — рядом с `AppDatabase`.
- Проверка `rg` старых imports и `LocalProfileDto`: совпадений не найдено.
- `make check`: форматирование, Flutter analyze, ESLint и 21 тест монорепозитория прошли.
- `flutter build macos`: release-приложение собрано, размер 46,4 МБ.

## Журнал решений

- 2026-08-24 — private helper может оставаться рядом с основным типом, чтобы правило «одна ответственность» не приводило к искусственному дроблению implementation details.
- 2026-08-24 — mapping выделяется из Freezed model в отдельный mapper, поскольку преобразование между data/domain является самостоятельной ответственностью.

## Результат

Profile domain и data преобразованы из плоских каталогов в структуру по ответственности. `LocalProfile`, оба value objects, exceptions и repository contract находятся в отдельных файлах. Drift table, Freezed `LocalProfileData`, `LocalProfileMapper` и repository implementation также разделены. Mapping удалён из data model. Все импорты и generated parts обновлены без изменения поведения. Общие правила структуры и допустимое исключение для private helpers закреплены в `AGENTS.md`.
