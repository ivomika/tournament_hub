# TH-20260825-004: Добавить список истории и просмотр турнира

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос пользователя просматривать историю турниров и открывать конкретный турнир.

## Цель

Пользователь может открыть локальную историю, увидеть список завершённых турниров и перейти на read-only экран конкретного immutable snapshot с участниками, матчами, standings и champion.

## Контекст

`TH-20260825-003` предоставляет history summary и загрузку snapshot по ID. Текущий champion flow показывает только последний завершённый турнир; новая навигация должна работать независимо от наличия active tournament и не позволять менять исторические результаты.

Зависимость: `TH-20260825-003`.

## Границы задачи

### Входит

- Точка входа «История турниров» из основной части приложения.
- Read-only список history summaries с пустым, loading и error/retry состояниями.
- Открытие конкретного snapshot по ID.
- Detail screen с названием, champion, ruleset/format metadata, participant snapshots, fighter avatars/names, матчами, результатами и итоговыми местами.
- Понятное состояние, если snapshot был удалён или повреждён вне приложения.
- Mobile-first и адаптивная desktop-композиция.
- Application/controller и widget/integration tests.

### Не входит

- Редактирование или повторное открытие завершённого турнира как active.
- Удаление, поиск, фильтры, сортировка пользователем и экспорт.
- Career/achievement UI.
- Отображение Double Elimination bracket до завершения `TH-20260825-005`–`TH-20260825-007`.

## Требования и ограничения

- UI получает summaries и snapshots через application API, не обращается к Drift напрямую.
- Исторический detail отображает сохранённые snapshots и не пересчитывает standings/champion текущими policies.
- Строка списка не требует календарной даты: обязательны название, champion и число участников; дополнительная metadata отображается только при наличии в summary contract.
- Все participant mentions используют сохранённые nickname, fighter ID/display name и локальный avatar resolver с явным fallback.
- Phone использует последовательную навигацию list → detail; desktop при достаточной ширине может использовать master-detail без потери route semantics.
- Ошибка одного detail snapshot не должна делать недоступным весь список.
