# TH-20260825-003: Расширить finished snapshots до истории турниров

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос пользователя добавить локальную историю турниров и просмотр конкретного завершённого турнира.

## Цель

Приложение хранит несколько неизменяемых завершённых tournament snapshots и предоставляет через заменяемый repository/application API полный список истории и получение конкретного турнира по стабильному ID.

## Контекст

`TH-20260824-023` реализовала immutable `FinishedTournamentSnapshot`, Drift-сохранение и восстановление текущего завершённого результата, но намеренно исключила историю нескольких турниров. Для экрана истории persistence должна стать append-only коллекцией и не терять ранее завершённые турниры при создании следующего.

Зависимость: `TH-20260824-023`.

## Границы задачи

### Входит

- Repository contracts для списка завершённых турниров и получения snapshot по tournament ID.
- Append-only хранение нескольких finished snapshots без перезаписи предыдущих.
- Компактная history summary projection без загрузки всех подробностей для каждой строки списка.
- Детерминированный порядок от последнего завершённого турнира к более ранним.
- Drift schema/migration и отдельные Freezed models/mappers при необходимости.
- Round-trip, multiple-finish, reopen, migration и repository contract tests.

### Не входит

- UI списка и деталей — `TH-20260825-004`.
- Удаление, редактирование, импорт, экспорт, поиск и фильтрация истории.
- Cloud backup и синхронизация истории между устройствами.
- Career и achievements projections.

## Требования и ограничения

- История остаётся local-first и доступна без сети.
- Существующие finished snapshots сохраняют immutable и идемпотентные свойства.
- Новый finish добавляет или идемпотентно подтверждает snapshot по tournament ID, но не удаляет другие записи.
- Summary содержит только данные, уже зафиксированные в авторитетном snapshot: ID, название, champion, число участников, ruleset/format metadata, если они присутствуют в snapshot.
- Порядок истории обеспечивается устойчивым completion order, не зависящим от текущих системных часов; показ календарной даты пользователю запросом не определён.
- Migration сохраняет существующий одиночный finished snapshot, active tournament, профиль и draft.
- Application и UI зависят от history port, а не от Drift.

## План

1. Выделить history summary и query contracts поверх finished snapshot.
2. Изменить persistence с одиночного результата на append-only коллекцию.
3. Добавить устойчивый completion order и запрос snapshot по ID.
4. Реализовать migration с сохранением существующего finished snapshot.
5. Покрыть multi-finish, duplicate ID, list/detail, reopen и migration tests.
6. Перенести итоговые storage/query решения в архитектурную документацию.

## Критерии приёмки

- [x] Последовательное завершение нескольких турниров сохраняет каждый snapshot.
- [x] History API возвращает все summaries в детерминированном порядке от новых к старым.
- [x] Конкретный snapshot загружается по стабильному tournament ID.
- [x] Повторное завершение того же ID не создаёт дубликат.
- [x] Поздние изменения профиля, fighter registry и ruleset implementation не меняют историю.
- [x] Migration сохраняет ранее завершённый турнир и остальное локальное состояние.
- [x] Repository можно заменить fake-реализацией без изменения application/UI.
- [x] Code generation, persistence tests и полный `make check` проходят.

## Проверка

- Repository contract tests для fake и Drift implementations: одинаковые list/getById semantics.
- Multi-finish test: два разных ID остаются в истории после reopen.
- Duplicate finish test: один ID представлен один раз.
- Snapshot immutability test после изменения исходных профилей/registry/policies.
- Migration test из текущей schema с существующим finished snapshot.
- `make generate`, `flutter analyze`, `make check`.

## Результат

Добавлены `TournamentHistoryRepository`, summary projection, snapshot mapper и Drift schema v5. История хранит несколько immutable snapshots, возвращает их от новых к старым, загружает по ID и сохраняет fighter display names на момент завершения.
