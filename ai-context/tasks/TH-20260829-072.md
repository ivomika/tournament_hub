# TH-20260829-072: Перестроить первый viewport и visual focus экранов турнира

- Статус: Готова
- Создана: 2026-08-29
- Обновлена: 2026-08-29
- Источник: аудит дизайнера, UX-инженера и агента visual focus по проблемам «много места до полезной информации» и неочевидному главному элементу

## Цель

Для каждого tournament screen сделать главный объект и следующий шаг понятными в первом viewport, уменьшив путь до полезной информации без потери контекста.

## Контекст

Аудит определил state-dependent visual focus: текущий матч на Running, выбор победителя на Result Entry, champion/result на Finished, roster/readiness на Open, fighter identity на Profile, а QR — вспомогательный канал доступа, не главный объект Host/Open.

## Границы задачи

### Входит

- Screen-by-screen focus map для Main, Draft, Open, Distribution, Running, Result Entry, Finished, Cancelled, History и History Detail.
- Фокус и первый viewport для Participant flow и Spectator dashboard/final.
- Сжатие избыточного header/metadata spacing; видимость dominant object и primary action.
- Sticky context summary только там, где он поддерживает текущий матч/результат, без дублирования ActionDock.

### Не входит

- Изменение tournament rules, bracket engine, persistence или protocol.
- Перегенерация fighter artwork и смена typography family.
- Реализация ActionDock (069–071) и role-aware nav (074).

## Требования и ограничения

- Главный объект определяется состоянием экрана, а не одинаковым шаблоном для всех ролей.
- Header mobile ориентировочно не превышает 120–144 px до первого смыслового объекта.
- Dominant object виден в первом viewport; primary action — не позже второго viewport; расстояние dominant object → action целится в ≤ 0,5 viewport.
- На Open QR остаётся доступным, но не получает gold-accent dominance.

## План

1. Составить focus matrix по ролям и states.
2. Перестроить header/summary/content order на приоритетных экранах.
3. Проверить QR, fighter identity, result и freshness cues.
4. Прогнать first-viewport visual matrix и обновить evidence.

## Критерии приёмки

- [ ] Для каждого перечисленного экрана указан и визуально подтверждён один dominant object.
- [ ] Dominant object виден в первом viewport на mobile и desktop composition не является простым масштабированием.
- [ ] Current match/result/champion не скрыты за декоративными блоками или длинным header.
- [ ] QR и freshness cues остаются доступными, но не конкурируют с главным объектом.
- [ ] First-viewport golden/manual checks пройдены.

- Непроведённые проверки и причина запрета/невозможности: записываются исполнителем.
