# TH-20260828-053: Привести Spectator Web к утверждённому visual language

- Статус: Черновик
- Создана: 2026-08-28
- Обновлена: 2026-08-28
- Источник: продолжение задачи 049 по запросу пользователя; запускать после подтверждения результата 049

## Цель

Синхронизировать Spectator Web с утверждённым visual language Tournament Hub и сделать dashboard, tournament view и champion/final presentation выразительными, читаемыми с расстояния и согласованными с Flutter Host.

## Контекст

Дополнение по аудиту 2026-08-29: Spectator dashboard должен делать текущий матч и свежесть projection главным объектом; финальный экран — champion/result. Служебный connection context не должен отодвигать эти объекты из первого viewport.

Spectator Web — отдельный desktop-first клиент без mutation controls. Его visual contract требует показывать previous/current/next, connection state, canonical Double Elimination structure и финальную identity чемпиона.

## Границы задачи

### Входит

- Spectator dashboard, tournament view, final/champion и waiting/connecting/stale/reconnecting states.
- Desktop-first wide composition, responsive fallback и читаемость с расстояния.
- Canonical Double Elimination presentation без превращения сетки в декоративную картинку.
- Shared semantic visual language, fighter artwork hierarchy и status semantics.
- Screenshot evidence в основных desktop и fallback viewport.

### Не входит

- Изменение WebSocket protocol, snapshot schema, Host server или Flutter domain.
- Mutation controls, spectator authentication и новые режимы турнира.

## Требования и ограничения

- Предшественник: 049; зависит также от готового spectator vertical slice и задачи 052 для общих identity/state решений.
- Spectator остаётся read-only и desktop-first.
- Shared tokens/contract нельзя дублировать raw values между Flutter и Web.
