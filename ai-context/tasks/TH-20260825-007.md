# TH-20260825-007: Добавить отдельный UI Double Elimination

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос пользователя добавить новый UI для режима Double Elimination; приложенное изображение 8-team bracket используется как визуальный ориентир.

## Цель

Пользователь может выбрать Double Elimination при создании турнира, проводить его через отдельное bracket-представление и просматривать завершённую сетку в истории на phone и desktop.

## Контекст

Существующий rounds UI ориентирован на round robin и не должен обрастать format-specific ветками. Приложенный ориентир показывает winners bracket сверху, losers bracket снизу, grand final справа и connector lines для 8 участников. На телефоне буквальное уменьшение desktop-схемы сделает данные нечитаемыми, поэтому режиму нужен отдельный presentation route/widget при общих application commands и participant primitives.

Зависимости:

- `TH-20260825-005` — Double Elimination Core и presentation projection;
- `TH-20260825-006` — устойчивое active/finished состояние;
- `TH-20260825-004` — history list/detail navigation.

## Границы задачи

### Входит

- Выбор tournament format в creation flow без изменения правил внутри widgets.
- Отдельный active Double Elimination route/widget.
- Winners bracket, losers bracket, случайные seeding и `bye`, обязательный grand-final reset и placement replay round robin согласно Core projection.
- Match cards с participant nickname, fighter avatar/display name, score/status и доступным действием ввода результата.
- Явные связи/переходы между матчами либо равноценная доступная навигация на узком экране.
- Read-only bracket detail для history snapshot.
- Loading/error/retry, keyboard/focus и защита от повторного submit.
- Phone/tablet/desktop widget и end-to-end tests.

### Не входит

- Расчёт topology, advancement или champion в UI.
- Редактирование завершённой истории.
- Сетевой Participant/Spectator bracket.
- Точная визуальная копия приложенного изображения.

## Требования и ограничения

- UI зависит только от application/presentation projections и commands; coordinates не становятся domain state.
- Round robin и Double Elimination имеют разные верхнеуровневые widgets/routes, но переиспользуют общие participant/fighter/match components там, где ответственность совпадает.
- Desktop показывает пространственную структуру winners/losers brackets и grand final без растягивания mobile layout.
- Phone использует читаемую адаптацию: секции/раунды, горизонтальную навигацию или focus mode; карточки и действия нельзя просто уменьшить до полной схемы.
- Connector lines являются presentation detail и строятся из stable bracket edges; при недоступности графического отображения связь должна оставаться понятной через labels/navigation.
- Все match result actions проходят существующую validation/persistence цепочку и подтверждаются только после сохранения.
- Исправление результата явно предупреждает о пересчёте; после подтверждения UI удаляет инвалидированные downstream results и отображает пересчитанные slots из application state.
- Произвольный размер состава не должен менять доступность основных действий; `bye` отображается как автоматический проход без результата матча.
- Первый grand final и обязательный reset визуально различаются; placement replay round robin для всей группы с общим местом не смешивается с winners/losers bracket.
- Phone-композиция: верхнеуровневые вкладки «Победители», «Проигравшие», «Финал», «Места» и последовательные карточки раундов внутри вкладки. Это сохраняет контекст без уменьшения desktop-сетки.
