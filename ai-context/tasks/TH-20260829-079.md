# TH-20260829-079: Выровнять density, surface hierarchy и archive/participant layouts

- Статус: Выполнена
- Создана: 2026-08-29
- Обновлена: 2026-08-30
- Источник: golden-аудит — repeated cards и равный visual weight размывают archive, read-only и supporting content

## Цель

Установить согласованную плотность и surface hierarchy для History, Profile, Settings, terminal screens и Participant flows, сохранив fighter identity, read-only semantics и доступность информации.

## Контекст

UI и DS аудит выявил stack of cards с одинаковым весом, слишком «hero»-подачу archive и визуальное сходство Participant с Host. Критик подтвердил необходимость density contract, но запретил превращать его в набор локальных magic values или скрывать fighter/result metadata.

## Границы задачи

### Входит

- Семантические density roles `comfortable`, `compact`, `presentation`.
- Surface hierarchy `base/elevated/accent` для supporting, current, champion, error и archived states.
- Более плотные History/History Detail rows без потери fighter identity/result/status.
- Спокойные Participant/read-only layouts и terminal Cancelled composition.
- Profile/Settings short-screen composition без декоративного заполнения пустоты.

### Не входит

- Новые layout presets и desktop workspace implementation (077).
- Header/dominant-object contract (078), кроме необходимой интеграции.
- Изменение action/navigation/domain/network contracts.
- Runtime typography/font fallback и кириллический type QA.

## Требования и ограничения

- Density semantics не уменьшают touch targets, critical text или fighter identity.
- Accent не дублируется на соседнем container без семантической причины.
- Archive не выглядит как live climax; Participant не выглядит как Host mutation surface.
- Не добавлять карточки только ради заполнения whitespace.
- Использовать существующие public DS API и token scale.

## Журнал решений

- 2026-08-29 — Density вводится как semantic role; whitespace не заполняется декоративными блоками.
- 2026-08-30 — `compact`, `comfortable` и `presentation` являются ролями компонента, а не responsive breakpoints: один экран может сочетать несколько ролей по смыслу контента.
- 2026-08-30 — History/History Detail используют archive preset и compact rows; Participant Distribution — presentation density на elevated surface без Host actions.
- 2026-08-30 — Profile использует ограниченную readable width с левым desktop-выравниванием; Settings и Cancelled используют split composition вместо центрированного или декоративного заполнения.
- 2026-08-30 — Визуально проверены девять изменившихся эталонов: History и History Detail на mobile/desktop, Participant Distribution на mobile/desktop, а также Profile, Settings и Host Cancelled на desktop.
- 2026-08-30 — Итоговый routing повторён: triggers по domain/data/network/typography не появились; применимыми остались 06, 07 и 09.

## Результат

Добавлен переиспользуемый density contract и документирована surface hierarchy. Archive-экраны стали плотнее и спокойнее, History Detail отделён от live-climax подачи, Participant Distribution визуально обозначен как read-only projection, а короткие и terminal screens получили семантические композиции без декоративных карточек. Widgetbook показывает все три density roles; новые layout/component tests и обновлённые goldens фиксируют результат. Полный `make check` завершился успешно.
