# TH-20260824-002: Создать локальный skill `task` для декомпозиции запросов

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя о локальном мини-skill `task`, работающем только с реестром задач.

## Цель

Создать локальный Codex skill `$task`, который анализирует переданный пользователем запрос, декомпозирует его в исполнимые задачи и сохраняет их в `ai-context`, не изменяя приложение и не приступая к реализации.

## Контекст

В проекте уже действует обязательный процесс через `ai-context/task-list.md` и детальные карточки в `ai-context/tasks/`. Нужен явно вызываемый планировочный skill, ограниченный только этой рабочей памятью.

## Границы задачи

### Входит

- Создание project-local skill `.codex/skills/task`.
- Описание строгой границы: только анализ, декомпозиция и обновление `ai-context`.
- Создание карточек по существующему шаблону и регистрация их в реестре.
- Настройка вызова `$task` и точного автоматического обнаружения запросов только на декомпозицию.
- Валидация структуры skill штатным валидатором.
- Документирование способа вызова.

### Не входит

- Реализация задач, созданных skill.
- Изменение исходного кода, `docs`, конфигурации приложения или внешних task trackers во время выполнения `$task`.
- Автоматизация через отдельный скрипт: для небольшого workflow достаточно инструкций skill.

## Требования и ограничения

- Skill работает только с `ai-context/README.md`, `ai-context/task-list.md`, `ai-context/templates/task.md` и карточками в `ai-context/tasks/`.
- Skill должен различать независимые задачи и шаги одной задачи, избегая чрезмерного дробления.
- Каждая созданная задача получает ID, полную карточку и статус `Готова` либо `Черновик`, если данных объективно недостаточно.
- При неоднозначности допущения фиксируются в карточке; skill не начинает реализацию.
- Автоматическое обнаружение остаётся включённым по умолчанию, но описание активирует skill только при явном `$task` или запросе исключительно на декомпозицию в `ai-context`.
- Тексты skill и создаваемых карточек пишутся на русском языке.

## План

1. Инициализировать локальный skill `task` без лишних ресурсов.
2. Заменить scaffold на краткие инструкции анализа, декомпозиции и записи задач.
3. Настроить русские UI-метаданные и точные условия применения.
4. Добавить инструкцию вызова `$task` в `ai-context/README.md` и корневой README.
5. Запустить штатный валидатор skill и проверить отсутствие изменений вне разрешённой области выполнения skill.
6. Зафиксировать результат и закрыть текущую карточку.

## Критерии приёмки

- [x] `.codex/skills/task/SKILL.md` имеет валидный frontmatter и узкое описание назначения.
- [x] Skill явно запрещает реализацию и изменение файлов вне `ai-context`.
- [x] Декомпозиция создаёт реестр и детальные карточки по текущему шаблону.
- [x] `agents/openai.yaml` содержит корректный `$task` default prompt, а описание skill не перехватывает обычную реализацию задач.
- [x] Пользовательская документация содержит пример вызова.
- [x] Штатный валидатор skill проходит.

## Проверка

- `uv run --with pyyaml python quick_validate.py .codex/skills/task`: `Skill is valid!`.
- `ruby -e 'YAML.load_file(...)'`: `openai.yaml: OK`.
- Ручная проверка scope инструкций: разрешено изменять только `ai-context/task-list.md` и `ai-context/tasks/`; реализация явно запрещена.
- `find .codex/skills/task -maxdepth 3 -type f`: присутствуют только `SKILL.md` и `agents/openai.yaml`, лишних ресурсов нет.

## Журнал решений

- 2026-08-24 — skill размещается в `.codex/skills/task`, потому что пользователь запросил локальный skill текущего проекта.
- 2026-08-24 — автоматическое обнаружение сохраняется согласно стандартному поведению Codex, но условия применения ограничиваются явным `$task` или запросом только на декомпозицию без реализации.
- 2026-08-24 — отдельный скрипт не создаётся, поскольку workflow требует смыслового анализа запроса, а не механического преобразования.

## Результат

Создан project-local skill `$task` в `.codex/skills/task`. Он анализирует запрос, выделяет зависимости и проверяемые результаты, создаёт или обновляет детальные карточки и синхронизирует реестр. Skill не меняет приложение и останавливается после декомпозиции. В `ai-context/README.md` и корневой README добавлены инструкция и пример вызова. Автоматический неявный вызов оставлен включённым по умолчанию, а точность маршрутизации обеспечена узким description: skill применяется только к явному `$task` или просьбе исключительно оформить задачи.
