# TH-20260829-075: Унифицировать действия всех Host-экранов через ActionDock

- Статус: Выполнена
- Создана: 2026-08-29
- Обновлена: 2026-08-29
- Источник: пользовательский отзыв — закреплённые снизу кнопки удачны, остальные Host-кнопки должны следовать одному подходу

## Цель

Сделать действия всех Host lifecycle-экранов визуально и поведенчески едиными: один action contract, закреплённый `ActionDock` на mobile и компактное представление того же набора действий у заголовка на desktop.

## Контекст

ADR-0006 ограничил `ActionDock` тремя критичными экранами. Поэтому Draft, Open, Finished и Cancelled используют другой placement, а некоторые mobile/desktop labels расходятся. Явный отзыв пользователя заменяет это ограничение требованием единого Host-паттерна.

## Границы задачи

### Входит

- Новый канонический контракт Host actions, superseding соответствующее ограничение ADR-0006.
- Единая модель primary/secondary/destructive actions для всех Host lifecycle screens.
- Закреплённый `ActionDock` на mobile для Draft, Open, Distribution, Running, Result Entry, Finished и Cancelled.
- Desktop toolbar из того же action contract без дублирования action definitions в screen.
- Перенос inline terminal navigation action в общий Host action region.
- Widget, adaptive, accessibility и golden проверки.

### Не входит

- Participant, Spectator, Main, History, Profile и Settings actions.
- Новые routes, domain commands, permissions или lifecycle transitions.
- Изменение navigation bar/rail и visual tokens.

## Требования и ограничения

- На mobile видимо одно primary action; secondary/destructive находятся в overflow.
- Один screen не определяет отдельно mobile и desktop labels/callbacks.
- Read-only Finished/Cancelled содержат только navigation/read-only actions.
- Destructive action требует confirmation и не конкурирует с primary.
- ActionDock вместе с navigation укладывается в существующий viewport ceiling и не перекрывает content.
- Screens используют только публичный design-system API.

## План

1. Принять ADR-0007 и обновить action placement matrix.
2. Сделать `ActionDock` единым adaptive action contract для mobile dock и desktop toolbar.
3. Перевести все Host lifecycle screens на один action definition и удалить дубли/inline navigation actions.
4. Расширить action/adaptive tests, обновить и визуально проверить затронутые goldens.
5. Прогнать project gates и сверить routing/evidence с итоговым diff.

## Результат

Все Host lifecycle previews определяют действия только через `ActionDock`. AppShell закрепляет этот contract над navigation на mobile и проецирует его через `ActionDock.toolbar` в PageHeader на desktop. Draft/Open/Finished/Cancelled переведены на общий placement, inline-дубли удалены, labels Running унифицированы. ADR-0007 заменил ограниченный ADR-0006, action placement matrix обновлена. Participant, Spectator, routes и domain lifecycle не менялись.
