# TH-20260830-081: Добавить full-page goldens и аудит layout по scroll

- Статус: Выполнена
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: запрос пользователя на full-page golden одного экрана и анализ layout-проблем

## Цель

Получить воспроизводимые full-page PNG для всех Flutter screen previews, чтобы видеть композицию от начала до конца контента, а не только первый viewport, и зафиксировать наблюдаемые проблемы layout для дальнейших задач.

## Контекст

Обычный visual golden ограничен viewport и не показывает нижние блоки после scroll. Это скрывает переполнения, чрезмерные вертикальные разрывы, позднее появление Structure и конфликт контента с fixed actions. Full-page capture должен быть отдельным диагностическим слоем и не менять production `AppShell`.

## Границы задачи

### Входит

- Full-page golden harness для существующих Flutter screen previews.
- Снимок всей фактической scrollable content-области каждого экрана в стабильном размере.
- Анализ высоты, вертикальных разрывов, порядка dominant/secondary/supporting regions и fixed overlay separation.
- Документирование найденных layout-проблем и рекомендаций с прямыми ссылками на golden assets.
- Тесты harness и проверка, что обычные viewport goldens не изменились.

### Не входит

- Изменение production layout, компонентов, typography или content.
- Замена обычных mobile/desktop goldens full-page изображениями.
- Скриншоты Widgetbook или Spectator Web.
- Автоматическое исправление найденных проблем в рамках этой задачи.

## Требования и ограничения

- Full-page capture не должен включать fixed `ActionDock`/navigation повторно как часть прокручиваемого контента.
- Все screen previews остаются в том же route/role/state, что и текущая visual matrix.
- Размеры capture должны быть детерминированными; dynamic IDs/timestamps не добавляются.
- Диагностика не должна ослаблять assertions или скрывать overflow.
- Пользовательские `pubspec.yaml` и `pubspec.lock` не включать в diff.

## Проверка

- `flutter test --update-goldens test/full_page_golden_test.dart` — создано 40 full-page PNG; после исправления fixed-region measurement все 40 cases прошли.
- `flutter test test/full_page_golden_test.dart test/visual_language_golden_test.dart` — 80 cases, exit 0.
- Проверены dimensions full-page assets: короткие screens остаются viewport-limited, длинные достигают 1–7 тыс. px; выборочно просмотрены `Host Running`, `History Detail`, `Host Open`, `History`, `Main` на mobile/desktop.
- `make check` — exit 0: architecture/token/assets/format, analyze, 184 Flutter tests и Spectator checks.
- Первый harness запуск выявил timeout у анимированного Bootstrap и ошибочно учитывал desktop toolbar как fixed region; добавлен стабильный pump для Bootstrap и фильтр `ActionDockPresentation.toolbar`, затем goldens пересозданы и повторно проверены.
- Device/TV camera checks не проводились: они не относятся к full-page Flutter capture и остаются out of scope.

## Журнал решений

- 2026-08-30 — Full-page goldens создаются отдельным test harness и не заменяют viewport contracts: viewport ловит fold/fixed-overlay regressions, full-page — вертикальную композицию и scroll order.
- 2026-08-30 — Fixed `ActionDock` и navigation исключаются из full-page canvas; их separation проверяется отдельным assertion.
- 2026-08-30 — Для коротких экранов сохраняется минимальная viewport height, чтобы full-page capture не менял responsive behavior; диагностический whitespace считается evidence, а не поводом для декоративного заполнения.
- 2026-08-30 — Layout findings вынесены в `docs/design/full-page-layout-audit.md`: production fixes не смешаны с capture harness.

## Результат

Добавлен test-only full-page harness `test/full_page_golden_test.dart` и 40 артефактов `test/goldens/full_page/` для всех 20 screen previews на mobile/desktop. Harness измеряет scrollable content, учитывает fixed region один раз и корректно обрабатывает анимированный Bootstrap. Проведён layout-аудит: основной P1 — несинхронная высота split/workspace колонок на desktop; второй P1 — чрезмерная длина mobile tournament stacks. Findings и следующие задачи записаны в [full-page layout audit](../../docs/design/full-page-layout-audit.md). Production layout не изменялся.
