# TH-20260830-085: Реализовать строгий architecture import gate

- Статус: Выполнена
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: реализация матрицы из [TH-20260830-084](TH-20260830-084.md)

## Цель

Сделать нарушение layer import boundaries автоматически блокирующим `make architecture` и `make check`, с понятным сообщением о файле, нарушенном правиле и допустимом направлении зависимости.

## Контекст

084 фиксирует архитектурный контракт, но без executable enforcement он останется рекомендацией. В репозитории уже есть project-level architecture orchestration; новый import checker должен встроиться в него и проверять production Dart roots до тестов и сборки.

## Границы задачи

### Входит

- Реализация статического сканера Dart imports по matrix из ADR-0010.
- Нормализация package и relative imports, определение layer roots и понятные diagnostics.
- Positive fixtures для разрешённых направлений и negative fixtures для каждого запрещённого crossing.
- Интеграция в `make architecture`/`make check` и документация команды запуска.
- Проверка существующего production tree и безопасный baseline для постепенного появления `app`, `application`, `domain`, `infrastructure`, `platform`.

### Не входит

- Изменение layer matrix, ADR-0010 или перемещение production-кода; такие изменения требуют сначала обновить 084.
- Runtime DI, build graph, Domain behavior, persistence/networking и UI.
- Проверка импортов spectator Web TypeScript: его boundary остаётся отдельным tooling scope.
- Разрешение нарушения через broad ignore, suppression comment или ручной allowlist без rationale.

## Требования и ограничения

- Нарушение `presentation → app/infrastructure/platform`, `application → presentation/app/concrete adapters` или `domain → outer/framework` возвращает non-zero exit code.
- `app/composition` может импортировать concrete implementations и связывать ports, но `app` business behavior не становится исключением.
- Диагностика содержит относительный путь, импорт и правило matrix; несколько нарушений выводятся детерминированно.
- Скрипт не выполняет Dart analyzer на несуществующих будущих roots и не падает из-за отсутствующей optional папки.
- Fixtures не попадают в production build и сами проходят проверку как ожидаемые positive/negative cases.
- Existing valid tree обязан проходить без ручного исключения.

## План

1. Реализовать scanner/parser и typed layer classification по ADR-0010.
2. Добавить deterministic diagnostics и positive/negative fixtures.
3. Подключить gate к `make architecture` и `make check`.
4. Проверить baseline существующего дерева и документацию команд.
5. Выполнить полный quality gate и записать фактические результаты.

## Критерии приёмки

- [x] Каждый запрещённый crossing из ADR-0010 имеет failing fixture.
- [x] Разрешённые направления и composition-root exceptions имеют passing fixture.
- [x] Любое нарушение возвращает non-zero exit и диагностирует file/import/rule.
- [x] `make architecture` и `make check` запускают gate автоматически.
- [x] Existing production tree проходит без suppression/ignore.
- [x] Docs, tests и task evidence обновлены; routing сверён с итоговым diff.

## Проверка

- Команда сканера на positive fixtures: ожидается exit 0.
- Команда сканера на negative fixtures: ожидается exit 1 и стабильные diagnostics.
- `make architecture` и `make check`: ожидается полный success.
- `git diff --check`, artifact/secret review и проверка отсутствия production fixture leakage.

## Журнал решений

- 2026-08-30 — Реализация checker откладывается до принятия ADR-0010; tooling не имеет права расширять matrix самостоятельно.
- 2026-08-30 — Предпочтён детерминированный source scan с negative fixtures; broad analyzer suppression запрещён.
- 2026-08-30 — Реальный package URI берётся из `pubspec.yaml`: `package:tournament_hub_app/...`; относительные imports нормализуются относительно source file.
- 2026-08-30 — `import`, `export` и URI-based `part` проверяются одинаково, чтобы public barrel или generated part не обходили matrix.

## Результат

Добавлен `tool/check_flutter_layer_imports.dart`: он классифицирует production Dart roots по ADR-0010, проверяет relative/package imports, framework/platform зависимости чистых слоёв, generated output и entry-point exceptions. Нарушения сортируются и содержат rule ID, source path и import URI. Checker запускается первым внутри `make architecture`, а значит также внутри `make test` и `make check`.

Добавлены 23 self-test fixture: positive направления, все запрещённые crossings, composition/main/Widgetbook, generated owner inheritance, framework restrictions, неизвестный root и выход за `lib`. Development/testing docs синхронизированы.

Фактические проверки:

- `dart analyze tool` — успешно, issues отсутствуют.
- `dart run tool/check_flutter_layer_imports.dart --self-test-only` — успешно, 23 fixture.
- `dart run tool/check_flutter_layer_imports.dart --project-only` — успешно на production tree.
- Временный probe `domain -> presentation` — ожидаемый exit 1 с `[layer-import:domain->presentation]`, source path и import URI; probe удалён.
- `make architecture` — оба layer/design-system gate успешны.
- `make check` — успешно: token/assets checks, architecture gates, formatter, Prettier, Flutter analyze, 234 Flutter tests и Spectator TypeScript/oxlint.
- `git diff --check` и проверка отсутствия probe — успешно.

Финальный routing не изменился: применимы core 00/01/08/10/11 и conditional 02/09. Diff ограничен checker, fixtures, orchestration, документацией и task evidence; production behavior, Domain/data/network/UI не менялись.
