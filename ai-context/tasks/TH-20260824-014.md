# TH-20260824-014: Добавить экран создания локального турнира

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя создать турнир на одном устройстве из локального профиля и гостей, минимум два игрока.

## Цель

Пользователь с локальным профилем может на одном устройстве создать tournament draft, добавить и отредактировать гостей, увидеть валидацию минимального состава и сохранить турнир.

## Контекст

Экран является presentation поверх guest application API и Tournament Core. Он не должен напрямую создавать domain entities, обращаться к Drift или загружать registry/assets без abstractions.

Зависимости:

- `TH-20260824-009` — guest profile API.
- `TH-20260824-012` — Tournament Core и creation use case.
- `TH-20260824-013` — локальное сохранение draft.
- `TH-20260824-010` и `TH-20260824-011` — если roster/avatar отображаются в creation flow.

## Границы задачи

### Входит

- Точка входа «Создать турнир» из основной части приложения.
- Mobile-first форма названия и состава турнира.
- Автоматически включённый текущий `LocalProfile`.
- Добавление, переименование и удаление гостей до сохранения.
- Явное состояние «нужен минимум ещё один игрок».
- Создание и устойчивое локальное сохранение draft через application use case.
- Loading/error/retry states и защита от повторного submit.
- Адаптивная desktop-композиция без растягивания mobile UI.
- Widget/application tests.

### Не входит

- Сетевая группа и подключение телефонов участников.
- Запуск матчей, раунды и standings.
- Изменение состава после старта.
- Правило выбора/случайного назначения бойцов, пока оно не подтверждено отдельно.

## Требования и ограничения

- Local profile отображается как обязательный участник и не удаляется.
- Создание недоступно при общем составе меньше двух игроков.
- UI зависит от application controller/use cases и ports, но не от Drift, UUID, asset paths или concrete registry.
- Сохранение считается успешным только после подтверждения repository.
- Введённые данные сохраняются при recoverable storage error.
- Phone layout оптимизирован для touch/keyboard; desktop использует ограниченную ширину или master-detail при достаточном пространстве.
- Fighter registry/avatar можно подключить через presentation model/resolver без изменения tournament creation domain.

## План

1. Определить presentation state и controller поверх guest/tournament use cases.
2. Добавить route и адаптивный экран создания.
3. Реализовать управление guest rows и minimum-participants validation.
4. Подключить создание/сохранение draft и состояния ошибок.
5. При готовности roster/assets подключить их только через abstractions.
6. Добавить widget/application tests для phone и desktop.

## Критерии приёмки

- [x] Local profile включён автоматически и не может быть удалён.
- [x] Гостей можно добавить, переименовать и удалить до создания.
- [x] При одном local profile создание заблокировано понятным сообщением.
- [x] При составе 2+ создаётся и сохраняется tournament draft.
- [x] Повторный submit заблокирован, storage error допускает повтор без потери ввода.
- [x] UI не зависит от concrete repositories, ID generators и asset implementation.
- [x] Phone/desktop widget tests и `make check` проходят.

## Проверка

- Widget test: local-only состав показывает minimum validation и не создаёт draft.
- Widget test: local + guest создаёт draft один раз.
- Widget tests add/rename/remove guest и storage retry.
- Layout tests для узкого phone и широкого desktop window без overflow.
- Integration test: сохранённый draft восстанавливается после повторной инициализации application.
- `make check` и production Flutter builds: ожидается успешное выполнение.

## Журнал решений

- 2026-08-24 — creation UI не знает concrete implementations; подмена repository/registry/assets выполняется в composition root.
- 2026-08-24 — local profile обязателен и immutable в составе до создания draft; гости редактируются свободно.
- 2026-08-24 — реализация начата; wide layout использует две ограниченные колонки от централизованного breakpoint, phone layout сохраняет одну последовательную колонку.
