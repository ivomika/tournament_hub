# TH-20260824-019: Рассчитывать таблицу, места и чемпиона

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-25
- Источник: запрос пользователя реализовать систему турнирных очков, расчёт чемпиона и завершение турнира по правилам технической документации.

## Цель

Из авторитетных результатов всех обязательных матчей и явно выбранного ruleset воспроизводимо рассчитываются standings, уникальные места и единственный чемпион, после чего турнир может перейти в завершённое состояние. Конкретные правила можно заменить без изменения агрегата, application-сценариев и UI.

## Контекст

Матчи и результаты создаются в `TH-20260824-017`, их устойчивое состояние — в `TH-20260824-018`. Разделы 25–30 и 81 [Technical Design Document](../../docs/architecture/tournament-hub-technical-design.md) описывают standings и tie-break stage, но прямо помечают scoring и порядок стандартных tie-break как неутверждённые. Scoring candidate: `2:0 → 3/0`, `2:1 → 2/1`, `1:2 → 1/2`, `0:2 → 0/3`. Подтверждено только то, что оставшееся равенство разрешается дополнительными матчами и finished tournament обязан иметь уникальные места.

Зависимости:

- `TH-20260824-017` — нормальные и технические результаты матчей;
- `TH-20260824-018` — авторитетное устойчивое состояние активного турнира;
- разделы 25–30 и 81 [Technical Design Document](../../docs/architecture/tournament-hub-technical-design.md);
- условие готовности: пользователь утверждает scoring candidate либо другое значение очков и определяет порядок стандартных tie-break критериев перед дополнительными матчами.

## Границы задачи

### Входит

- Заменяемый domain-контракт scoring policy для начисления турнирных очков из normal/technical results.
- Чистая standings projection с матчами, победами, поражениями, игровыми счетами и подтверждёнными дополнительными показателями.
- Заменяемая tie-break policy или последовательность критериев согласно подтверждённой документации.
- Заменяемый domain-контракт champion selection/completion policy, не связанный с конкретной scoring policy.
- Идентификатор и версия ruleset, достаточные для воспроизводимого повторного расчёта теми же правилами.
- Обнаружение неразрешённого равенства и типизированное состояние, требующее решения Host, если автоматических критериев недостаточно.
- Уникальные места, вычисление единственного champion и domain-инварианты завершения.
- Application use cases пересчёта и завершения турнира только после результатов всех обязательных матчей.
- Domain/property tests перестановок результатов, ничьих и идемпотентного пересчёта.
- Обновление `docs/product/open-decisions.md`, турнирной документации и ADR при необходимости.

### Не входит

- Match engine и запись схваток — `TH-20260824-017`.
- Persistence — `TH-20260824-018`.
- UI таблицы, tie-break, champion и завершения — `TH-20260824-020`.
- Career/achievements/history projection после завершения.

## Требования и ограничения

- Авторитетны только участники, расписание и результаты матчей; standings и champion всегда воспроизводимы из них.
- Значения очков, влияние технического результата и порядок tie-break не фиксируются до подтверждения указанного технического документа.
- Завершение запрещено, пока отсутствует результат хотя бы одного обязательного матча или остаётся неразрешённое равенство по местам.
- Champion определяется только первым уникальным местом, а не отдельным вручную редактируемым полем.
- Пересчёт не зависит от порядка доставки результатов и не накапливает очки повторно.
- Domain остаётся чистым Dart; scoring и tie-break policies заменяются независимо от aggregate/application orchestration.
- Application получает policies через интерфейсы и composition root; создание конкретной реализации внутри use case запрещено.
- Standings row и UI не должны содержать условные ветви по имени конкретного ruleset.
- Изменение реализации правил не переписывает результаты отдельных матчей.
- Обычный и технический результаты доступны policy как разные типы, даже если счёт совпадает.

## План

1. Получить подтверждение scoring candidate и порядка стандартных tie-break, затем перенести принятые правила в устойчивую документацию.
2. Перевести задачу в `Готова` после закрытия открытых продуктовых решений.
3. Определить standings row, scoring policy, tie-break policy, champion selection policy, ruleset identity/version и состояния неразрешённого равенства.
4. Реализовать чистый пересчёт из полного набора матчей и проверки завершения.
5. Реализовать application-команду завершения с вычисляемым champion.
6. Покрыть scoring, technical results, перестановки, duplicate input и tie scenarios domain/property tests.
7. Обновить документацию и выполнить полные проверки.

## Проверка

Заполняется фактическими результатами в ходе работы.

- Scoring examples из технической документации: ожидаются точные суммы и показатели.
- Property test перестановок одного набора результатов: standings совпадает.
- Contract tests с двумя различными scoring/champion policies: orchestration и projection используют внедрённую реализацию без ветвления по типу.
- Duplicate input test: очки не начисляются повторно.
- Tie scenarios для каждого подтверждённого критерия и неразрешимого равенства.
- Completion tests: незавершённые матчи/ничья блокируют finish; полный уникальный итог возвращает champion.
- `make check` и production build: ожидается успешное выполнение.

Фактически 2026-08-25: `flutter analyze` — успешно; полный `flutter test` — 108/108; domain ruleset suite — 9/9; `dart run build_runner build` и release APK — успешно. Web lint/test/build также успешны. ## Журнал решений

- 2026-08-24 — scoring, standings, tie-break и champion объединены как одна воспроизводимая projection/finish policy, но scoring и tie-break остаются независимыми заменяемыми контрактами.
- 2026-08-24 — статус `Черновик`: в запросе не указан конкретный технический документ, а постоянная память проекта запрещает придумывать очки и порядок tie-break.
- 2026-08-24 — TDD добавлен в репозиторий, но статус сохраняется: документ сам называет scoring и стандартный tie-break открытыми решениями; дополнительные матчи при оставшемся равенстве подтверждены.
- 2026-08-24 — задача заблокирована: `TH-20260824-017` и `TH-20260824-018` завершены, но проект запрещает фиксировать неподтверждённые scoring/tie-break. Для разблокировки нужны утверждённая таблица очков, правило для technical result и порядок автоматических критериев до дополнительного матча.
- 2026-08-24 — пользователь уточнил, что правила могут меняться; scoring, tie-break и champion selection должны быть независимыми domain-policy, собранными через dependency injection. Открытый вопрос: допускается ли смена ruleset внутри уже начатого турнира или только выбор перед стартом.
- 2026-08-24 — пользователь утвердил неизменяемость ruleset после старта и разрешил взять scoring/tie-break из TDD либо стандартной практики. Приняты scoring `3/0`, `2/1`, technical как `2:0`, порядок `Points → Wins → Game Difference → Games Won → Head-to-Head → Tie-Break Stage`; задача переведена из `Заблокирована` через `Готова` в `В работе`.
- 2026-08-25 — реализованы независимые scoring, tie-break и champion policies, standings projection и ruleset `mvp-round-robin` v1; незавершённые матчи и оставшееся равенство блокируют завершение.

## Результат

Добавлен чистый Dart feature `standings`: MVP-scoring для normal/technical результатов, стандартная последовательность tie-break, обнаружение общей позиции, выбор единственного champion и заменяемый `TournamentRuleset`. Тесты подтверждают все варианты счёта, technical result, независимую замену трёх policies, неизменность матчей при альтернативном ruleset, независимость от порядка входных матчей, блокировку неполного турнира и равенства. Дополнительные tie-break матчи намеренно не генерируются этой projection-задачей: необходимость этапа представлена явным незавершаемым состоянием.
