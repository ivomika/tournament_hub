# TH-20260825-011: Публиковать состояние турнира через WebSocket

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос реализовать WebSocket для наблюдения за текущим турниром.

## Цель

Flutter Host публикует согласованный realtime snapshot активного или завершённого турнира всем подключённым spectator и корректно обслуживает reconnect без влияния на local-first проведение турнира.

## Контекст

Состояние обоих форматов уже устойчиво сохраняется локально. Сетевой слой должен наблюдать подтверждённые application-state transitions и не становиться новым источником истины.

Зависимость: `TH-20260825-010`. Условие готовности — realtime-контракт и connection model утверждены.

## Границы задачи

### Входит

- Жизненный цикл WebSocket-host в согласованном runtime.
- Встроенная раздача production bundle Spectator Web по HTTP из Flutter Host.
- Projection adapters Round Robin и Double Elimination.
- Full snapshot при connect/reconnect и публикация только подтверждённого состояния после persistence commit.
- Монотонная revision, несколько spectator, heartbeat/timeout и освобождение ресурсов.
- Публичное состояние подключения для Host: доступный LAN URL, QR-код с этим URL, копирование адреса, число клиентов и recoverable error.
- Тесты сервера без привязки к production UI.

### Не входит

- Ввод или исправление результата со стороны spectator.
- Постоянный внешний backend, internet relay, authentication и доступ вне LAN.
- React-визуализация.

## Требования и ограничения

- Ошибка сети не блокирует локальное проведение и сохранение турнира.
- Не публиковать состояние до успешного локального commit.
- Новый клиент не обязан воспроизводить историю events: актуальный snapshot достаточен для сходимости.
- Все упоминания участника содержат fighter metadata либо явный fallback.
- Сервер не зависит от Flutter widgets и заменяем через application port.
- HTTP и WebSocket используют встроенный Host lifecycle; браузер открывает spectator по LAN URL без предварительной установки.
- QR-код и копируемый текст содержат один и тот же фактически доступный URL.

## План

1. Добавить transport/application ports и format projection adapters.
2. Реализовать lifecycle, handshake, snapshot broadcast и reconnect.
3. Подключить публикацию к подтверждённым изменениям обоих tournament controllers/use cases.
4. Добавить Host connection status и проверки отказоустойчивости.
5. Обновить документацию и локальные команды запуска.

## Критерии приёмки

- [x] Spectator получает актуальный snapshot при подключении в любой момент турнира.
- [x] Каждое подтверждённое изменение обоих форматов увеличивает revision и доставляется клиентам.
- [x] Disconnect/reconnect сходится к текущему состоянию без дублей и пропусков.
- [x] Несколько spectator не влияют на Host flow; сетевой сбой не останавливает турнир.
- [x] Серверные tests и целевые Flutter проверки проходят; полный `make check` выполняется после web-задач.
