# TH-20260824-022: Подключить выбор победителя схватки в экране раундов

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: сообщение пользователя о невозможности выбрать победителя на экране раундов.

## Цель

Host может открыть любой незавершённый матч из раунда, выбрать победителя очередной схватки и увидеть обновлённый счёт только после устойчивого локального сохранения.

## Контекст

`TH-20260824-017` реализовала best-of-three и исправление результата, `TH-20260824-018` — атомарное сохранение активного турнира. Экран `TournamentRoundsScreen` из `TH-20260824-016` всё ещё получает только `TournamentSetup` и показывает статичное расписание. Полная `TH-20260824-020` заблокирована правилами standings/tie-break, однако ввод результата отдельного матча от них не зависит.

## Границы задачи

### Входит

- Запуск и передача в UI устойчивого `ActiveTournament`.
- Отображение planned/in-progress/completed состояния, текущего счёта и номера следующей схватки.
- Выбор победителя очередной схватки из двух участников матча.
- Блокировка повторного ввода во время сохранения и понятная ошибка с возможностью повторить действие.
- Явное исправление завершённого результата полной заменой на `2:0`, `2:1`, `1:2` или `0:2`.
- Отображение каждого участника вместе с avatar и именем назначенного бойца.
- Widget-тесты выбора, завершения, исправления и ошибки сохранения.

### Не входит

- Standings, очки, tie-break, завершение турнира и экран чемпиона — `TH-20260824-019`/`TH-20260824-020`.
- Сетевой ввод результата Participant и spectator projection.
- Технический результат через UI.

## Требования и ограничения

- Presentation вызывает application-команды и не вычисляет результат матча самостоятельно.
- Новое состояние отображается только после успешного `TournamentRepository.saveActiveTournament`.
- Каждый матч хранит собственную нумерацию схваток.
- Для update ID используется стабильный уникальный идентификатор из `IdGenerator`.
- Mobile-first экран не допускает overflow; кнопки выбора содержат понятные подписи и доступны с клавиатуры.

## План

1. Добавить presentation controller для запуска турнира и устойчивых изменений матча.
2. Передать `ActiveTournament`, repository, registry и resolver в экран раундов.
3. Переработать карточку матча: участники с бойцами, счёт, статус и действия выбора/исправления.
4. Добавить widget-тесты persistence-aware сценариев и обновить документацию.
5. Выполнить генерацию, анализ, тесты и production build.

## Критерии приёмки

- [x] В planned/in-progress матче можно выбрать победителя следующей схватки.
- [x] При второй победе отображается завершённый normal result и лишний ввод блокируется.
- [x] Каждый матч ведёт независимую последовательность схваток.
- [x] Завершённый результат можно явно исправить одним из четырёх допустимых итогов.
- [x] Ошибка сохранения не меняет показанное авторитетное состояние; действие можно повторить.
- [x] Участник в карточке матча показан с nickname, fighter avatar и fighter display name.
- [x] Widget-тесты, полные проверки и build проходят; документация обновлена.

## Журнал решений

- 2026-08-24 — ввод результата выделен из заблокированной `TH-20260824-020`, потому что не зависит от scoring и tie-break.
- 2026-08-24 — после детализации карточка переведена из `Готова` в `В работе`; реализация начата сразу по запросу пользователя.
- 2026-08-24 — controller сначала восстанавливает активный турнир с тем же ID и только при отсутствии создаёт новый; повторное открытие экрана не меняет ранее назначенных бойцов и результаты.
- 2026-08-24 — задача завершена; standings, итоговый экран и champion остаются в заблокированной `TH-20260824-020`.

## Результат

Экран раундов переведён со статичного расписания на `ActiveTournament`. Карточка матча показывает текущую схватку, счёт, участников с бойцами, позволяет записать победителя и после завершения явно заменить результат. `TournamentConductController` не публикует новое состояние до успешного persistence и оставляет прежний счёт при ошибке. Итоги турнира и экран чемпиона сознательно не добавлены без утверждённой scoring/tie-break policy.
