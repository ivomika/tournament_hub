# TH-20260831-121: Исправить fullscreen и канонизировать линии Spectator bracket

- Статус: Выполнена
- Создана: 2026-08-31
- Обновлена: 2026-08-31
- Источник: скриншот пользователя; в fullscreen полотно сетки обрезается/пропадает, bracket не читается как связная сетка.

## Цель

Сделать fullscreen bracket полностью видимым и управляемым, а rounds/matches — визуально связанными каноничными connector lines без переноса progression logic в presentation.

## Контекст

Текущий fullscreen сохраняет фиксированную высоту `bracket-pan-area`, поэтому нижняя часть экрана остаётся пустой, а увеличенное полотно скрывается за `overflow`. Между rounds есть только короткий декоративный отрезок у заголовка, не связывающий match cards.

## Границы задачи

### Входит

- Fullscreen flex layout, полноразмерный pan viewport и автоматический fit при входе.
- Декоративные горизонтальные/вертикальные connectors между соседними match groups и rounds.
- Keyboard/pointer/zoom/fullscreen regression tests и design canon update.

### Не входит

- Изменение Domain progression, protocol DTO, explicit dependency graph и Host bracket generation.
- Интерактивное редактирование связей или результатов из Spectator.

## Требования и ограничения

- Fullscreen всегда сохраняет видимые toolbar и exit affordance.
- Полотно занимает всё оставшееся пространство fullscreen и автоматически вписывается после layout change.
- Lines являются presentation-only и не объявляют несуществующую domain dependency; semantic read order остаётся rounds → matches.
- Цвета, толщины, gaps и размеры используют существующие design tokens.

## Журнал решений

- 2026-08-31 — connectors presentation-only: без authoritative dependency graph они показывают направление bracket flow, но не вычисляют progression.
- 2026-08-31 — fullscreen viewport стал flex-column; pan area получает оставшееся пространство после toolbar вместо фиксированной высоты.
- 2026-08-31 — `fullscreenchange` планирует fit на следующий animation frame, когда браузер уже применил fullscreen geometry.
- 2026-08-31 — соседние matches группируются попарно только для branch geometry; semantic sections/articles и исходный round order сохранены.
- 2026-08-31 — connectors включены только для elimination lanes; RR rounds не получают ложных линий progression.
- 2026-08-31 — итоговый routing подтверждён: изменены только Spectator bracket component/styles/tests, design canon и task metadata; domain/protocol не затронуты.

## Результат

Fullscreen bracket больше не ограничен прежней фиксированной высотой: toolbar остаётся доступным, pan canvas заполняет остаток экрана и автоматически вписывается после входа. Elimination-раунды получили каноничные горизонтальные branches, вертикальные merge lines и входящие connectors к карточкам; линии используют существующие surface/border/spacing tokens и не меняют authoritative progression. RR сохраняет pairing presentation без ложных elimination connectors.
