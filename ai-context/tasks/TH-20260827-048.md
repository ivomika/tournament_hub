# TH-20260827-048: Сделать fighter artwork главным идентификатором участника

- Статус: Выполнена
- Создана: 2026-08-27
- Обновлена: 2026-08-28
- Источник: пользователь указал на несоответствие размеров UI и participant identity исходному Design Doc.

## Цель

Привести Flutter design system к иерархии Design Doc: крупный UI, реальные character assets и визуально доминирующий fighter artwork во всех tournament representations участника.

## Контекст

Текущий `FighterAvatar` показывает generic Material icon размером 44–48 px. Design Doc §18 требует strong typography hierarchy, называет character artwork частью identity, а после Distribution требует `Character Asset + Character Name + Participant Nickname`. Current Match должен быть самым сильным operational state. Исходные 37 PNG и roster manifest уже находятся в read-only `docs/source/fighters`, но runtime pipeline ещё не создан.

## Границы задачи

### Входит

- Semantic artwork-size tokens и повышение manifest minor version.
- Детерминированная синхронизация 37 runtime fighter assets из read-only source с check mode.
- Реальный artwork, fallback и size variants в `FighterAvatar`.
- Identity variants для compact standings/bracket, standard distribution, matchup/current match и champion/own fighter hero.
- Увеличение component typography, controls, padding/gaps в рамках token manifest.
- Обновление Widgetbook use cases/screens и regression tests Mobile/Desktop.
- Синхронизация design/assets/development documentation.

### Не входит

- Изменение Domain participant/fighter assignment.
- Лицензионное разрешение OD-010 или публикация assets в release.
- React/Spectator design-system implementation.
- Build, интерактивный запуск и commit.

## Требования и ограничения

- Artwork остаётся сопровождено character name и participant nickname; image не является единственным carrier.
- Runtime widgets читают только typed component themes, generated tokens доступны только общей theme composition.
- Source assets не редактируются; runtime copy полностью проверяется против source manifest.
- Missing asset показывает themed placeholder и сохраняет text/semantics.

## Журнал решений

- 2026-08-27 — artwork sizes оформляются semantic tokens `artwork.size.*`; это additive minor manifest change, source/model ADR-0001 не меняется.
- 2026-08-27 — все 37 assets синхронизируются, а не только preview subset, чтобы runtime roster и manifest не расходились.
- 2026-08-28 — compact/standard identity остаётся горизонтальной, matchup/hero использует вертикальную composition с artwork первым; это сохраняет крупный visual anchor на узком viewport.

## Результат

Token manifest обновлён до `1.1.0` и содержит semantic artwork sizes для compact, standard, matchup и hero. Все 37 PNG подключены через валидируемый source→runtime pipeline. `FighterAvatar` показывает реальный asset с themed fallback; `ParticipantIdentity`, match, bracket, standings, champion и distribution используют variant hierarchy, всегда сохраняя fighter name и nickname. Typography, controls, surfaces и spacing увеличены по Design Doc. Widgetbook показывает все identity variants и новый artwork token group. Design/assets/development docs и Make interface синхронизированы; OD-010 остаётся release blocker.
