# TH-20260830-087: Реализовать bootstrap и composition root app-слоя

- Статус: Готова
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: реализация нового app-потока после `TH-20260830-086`

## Цель

Создать единый production entry point и composition root, который собирает зависимости, запускает устойчивый bootstrap pipeline и публикует валидный `AppState` без прямого управления router.

## Контекст

Текущий `main.dart` является минимальным entry point, а зависимости и startup checks не оформлены единым app contract. Эфемерные callbacks могут привести к разным lifecycle implementations и потерянному состоянию после restart.

## Границы задачи

### Входит

- Entry point, `AppComposition` и production dependency graph.
- `AppBootstrap` с явным startup/recovery pipeline.
- Immutable app lifecycle states и publisher/read-only stream согласно ADR-0011.
- Restore local profile/active tournament через application ports с корректным ordering и error mapping.
- Lifecycle disposal/background hooks только в пределах принятого app contract.

### Не входит

- Logical route catalog и router adapter — 088.
- Полный test/fitness gate — 089.
- Новые Domain entities/use cases, database schema, LAN transport или UI redesign.
- Решение OD-013 о port conflict и permanent hosting.

## Требования и ограничения

- `main.dart` только создаёт composition и запускает app host.
- Production concrete adapters собираются только в `app/composition`.
- Bootstrap не импортирует presentation widgets и не вызывает router.
- Состояния immutable, transitions проверяемы и не зависят от widget mount timing.
- Ошибки разделяются на recoverable/fatal; stack trace не выходит в UI state.
- `AppState` публикуется после успешной проверки/restore, а не до commit.
- Dependencies injectable; tests используют fakes на ports.

## План

1. Добавить app state types и bootstrap contract по ADR-0011.
2. Собрать composition root и entry point с injectable dependencies.
3. Реализовать restore/check ordering и typed recoverable/fatal states.
4. Подключить lifecycle disposal без router calls и подготовить fixtures для 089.

## Критерии приёмки

- [ ] Есть единый production entry point и `AppComposition`.
- [ ] Bootstrap публикует состояния через read-only contract и не знает о router.
- [ ] Restore profile/active tournament и ошибки проходят через application ports.
- [ ] Concrete infrastructure imports находятся только в `app/composition`.
- [ ] App/tournament/connection state не смешаны.
- [ ] Tests 089 подтверждают transitions, ordering, restart/recovery и disposal.
- [ ] Rule routing повторно сверён с итоговым diff.

## Проверка

- `make architecture` — import boundaries.
- `dart analyze` и unit tests app state/bootstrap.
- Contract tests с fake ports: fresh, profile absent, restore success, recoverable/fatal failure, active restore, disposal.
- Проверка, что bootstrap не импортирует presentation/router.

## Журнал решений

- 2026-08-30 — Composition root остаётся единственным местом production wiring.
- 2026-08-30 — Bootstrap публикует read-only state и не вызывает навигацию напрямую.
