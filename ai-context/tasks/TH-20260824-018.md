# TH-20260824-018: Сохранять активный турнир и результаты матчей

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя реализовать проведение и завершение турнира; local-first требование сохранять заметные пользователю результаты до сообщения об успехе.

## Цель

Подготовленное расписание, назначения бойцов, состояние каждой схватки и результаты матчей атомарно сохраняются локально и восстанавливаются без потери после перезапуска приложения.

## Контекст

`TH-20260824-013` сохраняет только tournament draft, а `TH-20260824-016` явно оставила persistence `TournamentSetup` за границами. Для ввода результатов и последующего завершения турнира состояние не может оставаться только в памяти. Задача зависит от match-модели `TH-20260824-017`.

Зависимости:

- `TH-20260824-013` — текущий Drift repository и schema v2;
- `TH-20260824-015` — schedule и fighter assignments;
- `TH-20260824-017` — модель схваток и результатов матчей.

## Границы задачи

### Входит

- Расширение repository contract для активного турнира.
- Drift schema/migration для schedule, fighter assignments, внутренних схваток и normal/technical results.
- Атомарная запись авторитетного изменения результата до подтверждения успеха application-слою.
- Восстановление активного турнира и продолжение незавершённого матча после reopen.
- Дедупликация повторной записи результата по стабильным идентификаторам.
- Отдельные data models/mappers/tables/repository implementation и persistence tests.
- Подготовка состояния к последующей неизменяемой фиксации завершённого snapshot без реализации истории.

### Не входит

- Расчёт standings и champion — `TH-20260824-019`.
- UI ввода/восстановления — `TH-20260824-020`.
- История завершённых snapshot, career и achievements.
- Сетевая доставка результатов и Host revision.

## Требования и ограничения

- Domain/application зависят только от repository port, а не от Drift.
- Schedule, assignments, match state и результат одного изменения сохраняются транзакционно в согласованном состоянии.
- Migration сохраняет существующие local profile и tournament draft.
- Generated Drift/Freezed-файлы создаются штатно и не редактируются вручную.
- Повторная доставка одной операции не создаёт дубликат схватки и не меняет итог повторно.
- Ошибка записи не должна оставлять UI с ложным подтверждением результата.
- Структура файлов следует разделению table/model/mapper/repository.

## План

1. После завершения `TH-20260824-017` определить persistent-проекцию активного турнира и границу транзакции.
2. Расширить repository contract и спроектировать следующую Drift migration.
3. Реализовать data models, mappers и Drift adapter.
4. Подключить атомарное сохранение application-команд результата.
5. Добавить round-trip, reopen, migration, duplicate и rollback tests.
6. Обновить архитектурную документацию и generated code.

Добавлен `ActiveTournament`, repository port и application-сценарии старта/изменения матча. Drift schema поднята до v3 с отдельными tables для rounds, assignments, matches, bouts и update IDs; repository атомарно сохраняет и восстанавливает незавершённые, normal и technical состояния. UI-подключение остаётся в `TH-20260824-020`; standings/champion — в `TH-20260824-019` после утверждения правил.
