# TH-20260831-118: Стабилизировать Spectator waiting и переход после terminal

- Статус: Готова
- Создана: 2026-08-31
- Обновлена: 2026-08-31
- Источник: запрос пользователя; до начала и после завершения зритель должен показывать waiting, не зависать на последнем матче.

## Цель

Сделать переходы Spectator `waiting ↔ distribution/running/finished` детерминированными: до турнира и после очистки terminal projection показывать waiting, без дёрганья и stale last-match.

## Контекст

Finished Champion screen остаётся доступным, пока Host находится в завершённом турнире. После действия Host «На главный экран» active tournament удаляется из app state, public projection очищается, а уже открытый Spectator переходит в waiting. Сам Finished screen и его визуал не изменяются.

## Границы задачи

### Входит

- State machine клиента, snapshot 503/200, WebSocket close/reconnect и reducer reset.
- Устранение визуального flicker при polling/reconnect.
- Waiting, loading, stale и terminal presentation tests.

### Не входит

- Изменение Host domain lifecycle и protocol version.
- Bracket visuals (task 117) и dashboard lanes (task 116).

## Требования и ограничения

- Waiting не показывает последний матч как live.
- После очистки public projection старые participant/match данные удаляются из presentation state.
- Нельзя маскировать reconnect error таймаутом или бесконечным spinner.
- Finished не заменяется waiting сам по себе: waiting начинается только после выхода Host на главный экран и очистки active context.
