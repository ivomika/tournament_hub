# TH-20260827-045: Добавить Flutter Widgetbook с дизайн-системой и экранами

- Статус: Выполнена
- Создана: 2026-08-27
- Обновлена: 2026-08-27
- Источник: пользователь запросил Widgetbook, отдельный main, mobile/desktop targets, каталог дизайн-системы, reusable widgets и всех экранов приложения.

## Цель

Создать отдельный запускаемый Widgetbook-каталог Flutter-приложения, в котором представлены machine-generated design tokens, базовые компоненты и все логические экраны из screen map в mobile и desktop viewports.

## Контекст

Flutter application пока содержит только bootstrap screen. Канон уже определяет visual direction, token manifest, component contract и карту экранов. Widgetbook должен стать development catalog, а не новым владельцем project facts или parallel navigation/business implementation.

## Границы задачи

### Входит

- Stable Widgetbook dependency и отдельный `lib/main_widgetbook.dart`.
- Два Widgetbook viewport targets: Mobile и Desktop.
- Generated Dart bindings из `docs/design/tokens.json`, theme и typography showcase.
- Reusable widgets, перечисленные design system: identity/avatar, status/connection, match, standings, bracket, empty/error, confirmation preview, champion.
- Статические presentation mocks всех Flutter logical screens и Host/Participant states из screen map.
- Widgetbook navigation groups `Design system`, `Components`, `Screens`.
- Make targets для запуска Widgetbook на mobile/desktop и проверки catalog.
- `.vscode` launch configurations и tasks для запуска главного Flutter app и Widgetbook.
- ADR выбранного UI-catalog tooling и документация запуска.

### Не входит

- Реальный router, controllers, Domain transitions, persistence, network и mutation behavior.
- Закрытие open decisions или выдумывание tournament rules/settings.
- React Spectator screens: текущий scope пользователя — Flutter; Spectator показывается только как явно помеченный reference preview, если нужен для полноты screen map.
- Golden baseline и production visual polish с лицензированными fighter assets.

## Требования и ограничения

- Values design tokens генерируются из canonical JSON и не поддерживаются вручную вторым baseline.
- Screen examples используют immutable fixture/view data и не принимают domain decisions.
- После assignment participant identity содержит artwork fallback, fighter name и nickname.
- Mobile/desktop composition выбирается по constraints; Widgetbook viewport addon задаёт обе проверки.
- Каждый async screen имеет минимум representative content и применимые loading/empty/error/stale previews через catalog.

- `.vscode/launch.json` и `tasks.json`: JSON валиден, по две отдельные configurations/tasks.
- `make --dry-run run-widgetbook DEVICE=windows`: корректный отдельный entry command.

## Журнал решений

- 2026-08-27 — используется latest stable Widgetbook 3.x, а не prerelease 4.x.
- 2026-08-27 — Widgetbook tree поддерживается вручную: для текущего объёма это исключает annotation/codegen dependency и оставляет каталог явным.
- 2026-08-27 — screen catalog является presentation fixture; он не реализует navigation или domain behavior.
- 2026-08-27 — размеры project viewports собираются из breakpoint tokens; технический pixel ratio фиксирован единицей и не является reusable visual token.
