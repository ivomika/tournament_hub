# TH-20260828-052: Выравнять history, participant и recoverable screens по visual language

- Статус: Черновик
- Создана: 2026-08-28
- Обновлена: 2026-08-28
- Источник: продолжение задачи 049 по запросу пользователя; запускать после подтверждения результата 049

## Цель

Привести `History`, `History Detail`, `Join`, `Participant Lobby`, `Participant Distribution`, `Participant Running`, `Participant Finished` и `Recoverable Error` к единому read-only/participant visual language с ясными connection и stale states.

## Контекст

Эти экраны должны продолжать baseline 049, но имеют отдельные роли: history — read-only snapshot, participant — projection без Host mutation controls, recoverable error — безопасное восстановление без stack trace.

## Границы задачи

### Входит

- History list/detail с champion, fighter identity, ranking и snapshot context.
- Join/lobby/distribution/running/finished participant compositions без organizer actions.
- Connection/reconnecting/stale/incompatible/error/empty states с понятным recovery.
- Adaptive mobile/desktop layouts, long text, focus and semantic labels.
- Widgetbook cases и screenshot/golden evidence для read-only/participant states.

### Не входит

- Изменение snapshot schema, websocket protocol, reconnect algorithm, route guards и participant permissions.
- Изменение spectator web UI (отдельная будущая задача 053).

## Требования и ограничения

- Предшественник: 049; запускать после подтверждения visual baseline.
- History остаётся read-only; participant не получает mutation controls.
- Last-known stale data не выглядит live; identity contract сохраняется.
