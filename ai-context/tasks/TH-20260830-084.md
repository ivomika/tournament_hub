# TH-20260830-084: Зафиксировать матрицу зависимостей слоёв

- Статус: Выполнена
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: запрос пользователя на строгий import-boundary gate

## Цель

Зафиксировать проверяемую архитектурную матрицу импортов Tournament HUB и правило, по которому нарушение зависимости между слоями является ошибкой сборки, а не рекомендацией для code review.

## Контекст

Канон уже задаёт направление `presentation → application → domain` и отдельную composition boundary для `app`/`infrastructure`, но не описывает полный allow/deny matrix для Dart imports. Без такой матрицы presentation может незаметно начать импортировать `infra` или `app`, а application — concrete adapter.

## Границы задачи

### Входит

- Матрица разрешённых зависимостей для `app`, `presentation`, `application`, `domain`, `infrastructure`, `shared` и `spectator_web`.
- Правила для public ports, composition root, generated files, tests и Widgetbook.
- ADR с rationale, альтернативами, migration и rollback.
- Уточнение канонического [architecture guide](../../docs/architecture/README.md) и traceability/enforcement terminology.

### Не входит

- Реализация самого analyzer/checker и интеграция в Makefile — отдельная задача 085.
- Перенос существующих production files между слоями.
- Изменение Domain, application use cases, persistence, networking или UI behavior.
- Изменение обязательных `ai-context/rules`: enforcement остаётся project tooling, без дублирования facts в rules.

## Требования и ограничения

- `presentation` не импортирует `app`, `infrastructure`, `platform` или concrete adapters; presentation вызывает application services/ports по публичному контракту.
- `application` не импортирует `presentation`, `app`, concrete `infrastructure`/`platform` и framework UI; зависимости передаются через ports.
- `domain` не импортирует `application`, `app`, `presentation`, `infrastructure`, `platform`, Flutter, Riverpod, Drift, JSON или sockets.
- `infrastructure` и `platform` реализуют ports и могут зависеть от Domain contracts, но не от presentation.
- Только `app/composition` имеет право связывать concrete adapters с application/domain ports и presentation controllers.
- `shared` остаётся dependency-light и не становится обходным каналом для layer coupling.
- Тестовые fixtures и generated output не должны ослаблять production boundary; исключения должны быть именованными и проверяемыми.

## Журнал решений

- 2026-08-30 — Для Tournament HUB сохраняется отдельный `application` слой; `app` является composition root и не заменяет application services.
- 2026-08-30 — Import boundary проверяется по production layer roots; тестовые и generated paths не получают неявного права ослаблять production matrix.
- 2026-08-30 — Concrete infrastructure/platform implementations связываются только в `app/composition`; application и presentation видят ports/typed contracts.
