# TH-20260825-010: Определить realtime-контракт Spectator

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос реализовать WebSocket и Spectator Web для всех поддерживаемых форматов турнира.

## Цель

Зафиксирован версионированный read-only realtime-контракт, по которому spectator получает полное актуальное состояние Round Robin или Double Elimination, восстанавливается после разрыва соединения и однозначно переходит на экран завершённого турнира.

## Контекст

Flutter Host уже хранит авторитетное local-first состояние Round Robin и Double Elimination. Spectator Web существует как отдельное React-приложение, но пока не получает фактическое состояние турнира. Перед реализацией транспорта нужно определить границу Host, способ подключения и стабильную projection, не перенося domain-расчёты в web.

Зависимости: завершённые `TH-20260824-023`, `TH-20260825-005`, `TH-20260825-006` и `TH-20260825-008`.

## Границы задачи

### Входит

- Envelope WebSocket-сообщений с protocol version, tournament ID, revision и типом payload.
- Полный snapshot при подключении/reconnect и модель последующих изменений без пропуска состояния.
- Общая projection участника с nickname, fighter ID/display name/avatar reference.
- Format discriminant и отдельные projections Round Robin и Double Elimination.
- Состояния `idle`, `active`, `finished`, несовместимая версия и ошибка.
- Правила упорядочивания, идемпотентности, stale revision и full resync.
- Решение о размещении WebSocket-сервера, обнаружении Host и доступе spectator.
- Архитектурная документация/ADR в будущей реализации.

### Не входит

- Реализация сервера или React UI.
- Команды spectator на изменение турнира: spectator остаётся read-only.
- Облачный архив и просмотр чужой локальной истории.

## Требования и ограничения

- Host остаётся единственным источником истины; web не вычисляет продвижение, standings, места или чемпиона.
- Контракт покрывает Round Robin best-of-three и winner-only Double Elimination, включая `bye`, grand-final reset и placement replay.
- Новый spectator после подключения сразу получает самодостаточный snapshot.
- Неизвестные поля допускаются в пределах совместимой версии; несовместимость верхнего уровня обрабатывается явно.
- Нельзя включать секреты или локальные filesystem paths.
- WebSocket- и HTTP-сервер запускаются внутри Flutter Host и доступны устройствам в той же локальной сети.
- Spectator открывает показанный Host URL в обычном браузере; отдельная установка web app на телевизор не требуется.
- Доступ read-only публичен внутри LAN, без кода, аккаунта или токена.
- Host показывает URL текстом, позволяет копировать его и отображает QR-код с тем же URL.

## План

1. Закрыть продуктовые вопросы подключения и границы локальной сети.
2. Описать общий envelope, revision/full-sync semantics и ошибки.
3. Описать format-specific active/finished projections и примеры payload.
4. Зафиксировать контракт в protocol docs/ADR и подготовить contract fixtures для Dart и TypeScript.

## Критерии приёмки

- [x] Подтверждены место запуска WebSocket-сервера, discovery и access model.
- [x] Любое поддерживаемое active/finished состояние представимо без domain-расчётов на web.
- [x] Описаны connect, reconnect, duplicate, stale/out-of-order и incompatible-version сценарии.
- [x] Dart и TypeScript могут проверяться одними JSON fixtures.
- [x] Связанная документация обновлена.

## Проверка

- Ручной review примеров Round Robin active/finished и Double Elimination active/reset/replay/finished.

## Результат

Зафиксирован Spectator WebSocket protocol v1 с full snapshot, revision, reconnect/full sync и format-specific projections. Добавлены общие Round Robin/Double Elimination JSON fixtures, Dart envelope decoder и TypeScript runtime decoder. Решение встроенного публичного LAN Host закреплено ADR-0003.

Проверки: 2 Dart protocol tests и 3 TypeScript protocol tests прошли.
