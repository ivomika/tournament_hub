# TH-20260825-014: Отобразить каноничную сетку Double Elimination

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос сделать spectator Double Elimination обязательной каноничной bracket-сеткой; приложенное изображение используется как визуальный ориентир.

## Цель

Spectator Web отображает актуальную Double Elimination как каноничную пространственную сетку: winners bracket сверху, losers bracket снизу, grand final/reset справа, с видимыми связями продвижения между карточками матчей.

## Контекст

Host Core уже предоставляет stable match IDs, stages и seed/winner/loser sources. В отличие от упрощённого Host UI, spectator должен использовать полноценную bracket-визуализацию по структуре приложенного 8-player reference и поддерживать произвольный состав, случайные `bye`, reset и placement replay.

Зависимость: `TH-20260825-012`. Условие готовности — realtime projection содержит topology edges и рассчитанные slots без вычисления progression в React.

## Границы задачи

### Входит

- Winners bracket сверху и losers bracket снизу, сгруппированные по раундам.
- Grand final и условный grand-final reset справа от основных ветвей.
- Connector lines по stable topology edges, включая переход проигравшего в losers bracket.
- Match cards с участниками, fighter, статусом, победителем, `bye` и ожиданием slot.
- Placement replay как отдельный семантический блок, не смешанный с основной сеткой.
- Pan/scroll/zoom либо другая подтверждённая читаемая навигация для больших сеток и узких экранов.
- Live transition при новой revision без перестроения identity карточек.
- Golden/component/accessibility tests каноничной topology.

### Не входит

- Расчёт topology, координатов как domain state или advancement в React.
- Буквальное копирование цветов, текста и брендинга приложенного изображения.
- Редактирование результатов spectator.

## Требования и ограничения

- Визуальная иерархия reference обязательна: winners сверху, losers снизу, финалы справа, связи явно видимы.
- Сетка строится из Host projection и работает минимум для 2, 3, 5, 8 и 16 участников.
- `Bye`, skipped match, waiting slot, completed match и reset визуально различаются.
- Карточка участника содержит nickname, fighter display name и avatar/fallback.
- На узком экране сетка не превращается в неканоничный список; допустима управляемая viewport-навигация по общей пространственной схеме.
- Пользователь подтвердил pan/zoom для узкого экрана: spatial topology и connector lines сохраняются при любом viewport.

## План

1. Определить presentation layout model из topology edges и измеряемых карточек.
2. Реализовать winners/losers/final regions и match cards.
3. Реализовать connectors, viewport navigation и responsive behavior.
4. Добавить reset, `bye`, placement replay и live update states.
5. Зафиксировать golden cases и проверить accessibility/performance больших сеток.

## Критерии приёмки

- [x] Layout сохраняет каноничную структуру: winners сверху, losers снизу, финалы справа.
- [x] Winners/losers transitions и grand final/reset однозначно читаются по connector lines.
- [x] Произвольное число карточек распределяется по раундам без наложений внутри колонки.
- [x] Новая Host revision обновляет slots при сохранении stable match key.
- [x] Узкий экран предоставляет scroll/pan и zoom общей сетки, desktop/TV использует доступную площадь.
- [x] Layout/component tests и web production build проходят.

## Проверка

- Golden fixtures для 2, 3, 5, 8 и 16 участников, reset и placement replay.
- Component test progression winners → losers → grand final.
- Manual visual QA относительно приложенного reference на phone/desktop/TV.

## Результат

Spectator Web отображает Double Elimination единой каноничной пространственной сеткой. Геометрия отделена от React-компонентов и покрыта unit test; карточки используют стабильные match IDs, поэтому realtime revisions обновляют содержимое без смены identity. На узком экране сохраняется исходная топология с прокруткой и масштабированием.
