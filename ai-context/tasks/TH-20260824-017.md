# TH-20260824-017: Реализовать результаты отдельных схваток best-of-three

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя реализовать выбор победителя каждой схватки, отдельные раунды внутри каждого матча и подсчёт матчевого счёта по технической документации.

## Цель

Каждый запланированный матч получает собственную независимую последовательность схваток best-of-three, из которой Tournament Core однозначно вычисляет допустимый итоговый счёт и победителя матча.

## Контекст

`TH-20260824-015` создаёт tournament rounds и пары матчей, но `ScheduledTournamentMatch` пока не содержит состояния проведения. Разделы 23–24 [Technical Design Document](../../docs/architecture/tournament-hub-technical-design.md) подтверждают best-of-three, результаты `2:0`, `2:1`, `1:2`, `0:2` и различие normal/technical result. Пользователь отдельно уточнил, что внутреннее деление на раунды должно быть собственным для каждой битвы, а ранее введённый результат разрешено исправлять.

Зависимости:

- `TH-20260824-015` — расписание и идентичность запланированных матчей;
- разделы 23–24 и end-to-end шаги 18–19 [Technical Design Document](../../docs/architecture/tournament-hub-technical-design.md).

## Границы задачи

### Входит

- Стабильная идентичность матча и domain-состояние его проведения.
- Независимая коллекция схваток/игровых раундов внутри каждого матча.
- Запись победителя очередной схватки и автоматический расчёт матчевого счёта.
- Завершение обычного матча при двух победах одного участника с допустимыми итогами `2:0`, `2:1`, `1:2`, `0:2`.
- Раздельные domain-типы обычного и технического результата без смешения одинаковых числовых счетов.
- Запрет лишней схватки после определения победителя и изменение результата только через явный application use case.
- Явный use case исправления ранее введённого результата с заменой прежнего match state, audit-событием и последующим полным пересчётом производных данных.
- Типизированные validation/conflict errors, audit-ready команды и domain/application tests.
- Обновление документации подтверждённых матчевых правил.

### Не входит

- Турнирные очки за победу/поражение и standings — `TH-20260824-019`.
- Стандартный порядок tie-break и вычисление чемпиона.
- Persistence результатов — `TH-20260824-018`.
- UI выбора победителя — `TH-20260824-020`.
- Технические причины выхода участника и автоматическое назначение технических результатов оставшихся матчей; в этой задаче создаётся только различимый тип результата и его базовые инварианты.

## Требования и ограничения

- Внутренний номер схватки принадлежит конкретному матчу; номера не разделяются между матчами одного tournament round.
- Победителем схватки может быть только один из двух участников её матча.
- Обычный матч завершается сразу после второй победы одного участника; третья схватка отсутствует при `2:0`/`0:2`.
- Итоговый победитель и счёт являются производными от записанных схваток, а не независимо редактируемыми полями.
- Исправление результата пересобирает допустимую последовательность схваток матча; оно не дописывает новый итог поверх старого и не оставляет два авторитетных результата.
- Повтор команды с тем же стабильным command/result ID должен обрабатываться идемпотентно либо отклоняться типизированным conflict без двойного изменения.
- Domain остаётся чистым Dart, использует Equatable и не зависит от UI, Drift или transport.
- Если техническая документация задаёт дополнительные правила, сначала их точная ссылка и формулировка записываются в карточку и `docs`, затем обновляется scope.

## План

2. Определить match aggregate, внутреннюю схватку, обычный/технический результат и типизированные ошибки.
3. Реализовать команды записи победителя схватки и вычисление счёта/победителя матча.
4. Добавить идемпотентность, запрет неявного изменения завершённого матча и явный сценарий исправления результата.
5. Покрыть все допустимые счета, преждевременное завершение и невалидные переходы domain/application tests.
6. Обновить турнирную документацию и выполнить проверки.

## Критерии приёмки

- [x] У каждого матча собственная последовательность схваток с нумерацией от 1.
- [x] По победителям схваток автоматически получаются только `2:0`, `2:1`, `1:2` или `0:2`.
- [x] Победитель матча однозначно соответствует участнику с двумя победами.
- [x] После определения победителя новая схватка не добавляется.
- [x] Ранее введённый результат можно исправить явной командой; старый результат заменяется, а производные данные подлежат полному пересчёту.
- [x] Обычный и технический результат различаются domain-типом.
- [x] Невалидный участник, дубликат и конфликт изменения обрабатываются типизированно.
- [x] Domain/application tests и проверки ответственного слоя проходят; правила документированы.

## Результат

Добавлены стабильный `TournamentMatchId`, immutable `TournamentMatch`, собственные `MatchBout`, normal/technical results, идемпотентные update IDs и типизированные validation/conflict errors. `RecordMatchBout` последовательно формирует best-of-three, а `CorrectMatchResult` полностью заменяет завершённый итог. Round robin назначает стабильные match IDs. Scoring, persistence и UI остаются в связанных задачах.
