# TH-20260825-012: Подключить Spectator Web к realtime-потоку

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: запрос реализовать realtime Spectator Web через WebSocket.

## Цель

React-приложение подключается к Host, валидирует protocol payload и поддерживает единый актуальный read model для dashboard, сеток и финального экрана при connect/reconnect/error.

## Контекст

UI-задачи не должны самостоятельно разбирать WebSocket или вычислять турнирные правила. Нужен отдельный transport/store слой с format-discriminated state.

Зависимости: `TH-20260825-010`, `TH-20260825-011`. Условие готовности — доступны контрактные fixtures и тестовый WebSocket Host.

## Границы задачи

### Входит

- Загрузка production web bundle с HTTP URL Flutter Host и подключение WebSocket к тому же Host без ручной настройки отдельного endpoint.
- WebSocket client, runtime validation, protocol negotiation и typed mapping.
- State machine connection/loading/active/finished/error/incompatible.
- Revision ordering, duplicate suppression, reconnect с full resync.
- Заменяемый realtime source и deterministic fixtures для UI tests.
- Connection status и понятные retry states.

### Не входит

- Конкретная компоновка Round Robin или Double Elimination.
- Изменение турнира из браузера.
- Повторная реализация scoring/bracket progression.

## Требования и ограничения

- Read model заменяется полным Host snapshot и не сливает данные разных tournament ID.
- Stale/out-of-order update не откатывает показанное состояние.
- UI получает typed projection, а не сырой JSON.
- Соединение освобождается при смене Host/страницы и восстанавливается с ограниченной retry policy.
- Spectator не запрашивает authentication: доступ публичен для устройств, способных открыть LAN URL.

## План

1. Ввести TypeScript protocol types и runtime decoder на общих fixtures.
2. Реализовать WebSocket transport и reconnect state machine.
3. Реализовать format-discriminated spectator store/read model.
4. Добавить connection/error UI primitives и transport tests.

## Критерии приёмки

- [x] Web app подключается к реальному и fake Host одним интерфейсом.
- [x] Active и finished snapshots обоих форматов типизированы и доступны UI.
- [x] Reconnect, duplicate, stale revision и incompatible protocol покрыты тестами.
- [x] Ошибка соединения представлена transport state и допускает retry; экран подключается в следующей задаче.
- [x] Web lint/test/build проходят.

## Проверка

- Vitest transport/store tests с fake WebSocket server и contract fixtures.
- Ручное подключение web app к Host, разрыв и восстановление соединения.

## Журнал решений

- 2026-08-25 — transport/store отделяется от экранов, чтобы визуализации не зависели от WebSocket API.
- 2026-08-25 — задача оставлена в `Черновик` до `TH-20260825-010` и `TH-20260825-011`.
- 2026-08-25 — connection model подтверждена: браузер загружает app с LAN URL встроенного Host и подключается к его WebSocket; задача переведена в `Готова`.
- 2026-08-25 — начата реализация WebSocket transport, revision store и connection state machine.

## Результат

Добавлены TypeScript protocol model/runtime decoder, WebSocket transport, reconnect/full sync, connection state machine и spectator revision store. UI получает typed envelope и не работает с raw JSON.

Проверки: web lint, 8 Vitest tests и production build прошли.
