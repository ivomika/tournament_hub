# TH-20260831-112: Проверить и исправить LAN-раздачу packaged Spectator bundle

- Статус: Выполнена
- Создана: 2026-08-31
- Источник: Host показывает LAN URI, но браузер получает 404 на JS/CSS и не монтирует React.

## Цель

Гарантировать, что каждая сборка Spectator синхронизируется во Flutter assets, вложенные ресурсы попадают в macOS/APK и другие Flutter targets, а реальный Host LAN endpoint раздаёт UI и WebSocket.

## Scope

- Входит: Flutter asset declarations, build pipeline, HTTP static assets, same-origin snapshot/WebSocket smoke checks.
- Не входит: redesign React, изменение протокола или domain-логики.

## Routing и evidence

- Router: [`ai-context/rules/README.md`](../rules/README.md).
- Core: workflow, authority, quality, scope, safety — карточка до изменений, проверяемый build/runtime diff, без commit без запроса.
- Conditional: 02 Architecture (build/runtime boundary), 04 Data (generated assets), 05 Network/security (LAN endpoint), 09 Docs/assets (packaging contract).

## Plan

1. Добавить явные Flutter asset directories для вложенных `assets/` и `fighters/`.
2. Сделать sync/build fail-fast при неполном bundle.
3. Пересобрать macOS и APK, проверить packaged JS/CSS и реальный LAN HTTP/WebSocket.

## Criteria

- [x] `build-flutter` всегда выполняет React build и sync.
- [x] Packaged Flutter output содержит `index.html`, JS/CSS и fighter assets.
- [x] Host LAN adapter возвращает UI assets без 404; snapshot/WebSocket имеют ожидаемый контракт.

## Checks

Результат проверок:

- `dart run tool/project.dart build-spectator` — React build и sync выполнены; неполный bundle теперь останавливает сборку.
- `flutter pub get && flutter build macos --debug` — успешно; packaged `assets/spectator/assets/*.js`, `*.css` и `fighters/*.png` присутствуют.
- `flutter test test/infrastructure/spectator/spectator_lan_server_test.dart test/app/spectator_host_integration_test.dart test/contract/spectator_protocol_v1_test.dart` — 13 тестов пройдено, включая реальный LAN adapter и WebSocket.
- `npm test` — 13 тестов пройдено.
- Прямой запрос к запущенному Host без активного турнира даёт ожидаемый отказ запуска сервера; это не 404 статических ресурсов. Адрес `10.3.44.59:8080` проверять после открытия турнира.

## Итог

Причина пустого экрана была в том, что Flutter упаковывал только корневые файлы `assets/spectator/`, но не вложенные `assets/` и `fighters/`. Из-за этого Host отдавал `index.html`, а JS/CSS получали 404. Добавлены явные asset directories и fail-fast проверка sync; `build-flutter` сначала собирает React и синхронизирует bundle.
