# TH-20260830-093: Реализовать SQLite/Drift stores и crash-safe terminal history

- Статус: Выполнена
- Создана: 2026-08-30
- Обновлена: 2026-08-30
- Источник: P4 implementation plan; authoritative Host persistence.

## Цель

Сохранить active tournament, event log, idempotency и immutable Finished/Cancelled history с atomic commit-before-broadcast semantics и восстановлением после restart.

## Контекст

Data canon разделяет stores и запрещает сериализовать Domain напрямую. App bootstrap уже имеет reader port, но нет Drift schema/adapters.

## Границы задачи

### Входит

- SQLite/Drift schema, DTO/mappers, repository ports, migrations и fixtures.
- Active snapshot/event/idempotency/history stores, terminal normalization, clear history.
- Round-trip, upgrade, crash/fault and duplicate command tests.

### Не входит

- Participant cache/binding и Participant protocol.
- Format engine semantics или UI beyond integration ports.

## Требования и ограничения

- BEGIN verifies revision, persists complete snapshot/event/idempotency, then COMMIT; publish only after commit.
- Terminal insert history + delete active rows atomic; history dedupes tournamentId.
- Domain models не сериализуются напрямую.

3. Добавить migration/fault/restart tests и bootstrap adapter.

## Критерии приёмки

- [x] Active snapshot round-trip сохраняет полную payload и revision.
- [x] Duplicate commandId возвращает ранее сохранённый result без второй mutation.
- [x] Terminal transaction возвращает event только после commit и не дублирует history.
- [x] Upgrade v1→v2, revision conflict и rollback после constraint failure проходят.
- [x] Local DB не появился в git; analyzer и architecture checks проходят.

## Проверка

- `flutter analyze` — успешно.
- 30 targeted bootstrap/profile/domain/persistence tests — успешно.
- Из них 9 Drift contract tests: profile round-trip, atomic mutation, idempotency, revision conflict, rollback, terminal dedupe и v1→v2 migration.
- Layer import и design-system architecture checks — успешно.
- Full `make check` и production build не запускались; LAN/Participant cache проверки отложены.

## Журнал решений

- 2026-08-30 — используется каноническая terminal normalization из data docs; event log не становится permanent event sourcing.
- 2026-08-30 — физическая SQLite database общая для atomic terminal transaction, а application ports разделены на profile, active store и history consistency boundaries.

## Результат

Реализованы Drift schema v2/codegen, versioned DTO, active mutation/idempotency store, terminal history store, migration v1→v2 и production bootstrap adapter.
