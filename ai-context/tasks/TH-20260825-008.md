# TH-20260825-008: Упростить результат Double Elimination до выбора победителя

- Статус: Выполнена
- Создана: 2026-08-25
- Обновлена: 2026-08-25
- Источник: пользователь не может завершить матч Double Elimination и уточнил, что в этом формате не должно быть счёта `2:0` или подсчёта очков — фиксируется только победа/поражение.

## Цель

Матч Double Elimination завершается одним выбором победителя. Domain, persistence, активный UI, placement replay и история не хранят и не показывают счёт или очки для этого формата.

## Контекст

В `TH-20260825-005`–`TH-20260825-007` Double Elimination переиспользовал round-robin `TournamentMatch` best-of-three. Из-за этого UI показывает действие `2:0`, а persistence хранит bouts/scores, хотя продуктовый смысл DE — бинарный результат матча. Round robin должен сохранить существующий best-of-three и начисление очков без изменений.

## Границы задачи

### Входит

- Отдельный Equatable domain result Double Elimination с участниками, winner, loser и update ID.
- Одно действие выбора победителя для bracket и placement replay.
- Correction с пересчётом зависимых bracket matches.
- Обновление versioned mapper с чтением ранее сохранённого DE payload, если возможно без потери результата.
- Удаление счёта и очков из active/history UI Double Elimination.
- Единый вертикальный список матчей вместо колонок; этапы разделяются семантическими заголовками.
- Итоговое состояние после завершения с явным отображением победителя и занятых мест.
- Domain, persistence и widget regression tests.

### Не входит

- Изменение best-of-three, scoring и standings формата round robin.
- Настройка серии игр внутри одного DE-матча.

## Требования и ограничения

- Победитель обязан быть одним из двух участников; loser выводится однозначно.
- Повтор одного update ID идемпотентен.
- В DE запрещены score, points и bouts как авторитетное состояние.
- Existing payload schema v1 с результатами `2:0`/`2:1` мигрируется в winner-only state по сохранённому winner ID.
- UI подтверждает успешное завершение только после persistence commit.

## План

1. Ввести winner-only result и заменить им bracket/placement aggregates.
2. Обновить mapper с новой schema и backward-compatible decode v1.
3. Упростить controller и active/history UI до выбора победителя.
4. Актуализировать tests и правила турнира.
5. Выполнить `make check` и release build.

## Критерии приёмки

- [x] Один выбор участника завершает готовый DE-матч.
- [x] Active и history UI не содержат `2:0`, score или points для DE.
- [x] Active UI показывает матчи единым списком без колонок раундов.
- [x] После успешного завершения экран показывает победителя, а повторная кнопка завершения скрыта.
- [x] Placement replay также хранит только winner/loser.
- [x] Correction пересчитывает зависимые матчи.
- [x] Reopen сохраняет winner-only state и читает payload v1.
- [x] Round robin поведение не изменено.
- [x] `make check` и release build проходят.

## Проверка

- Domain tests winner validation, idempotency, correction и replay.
- Mapper/repository round-trip и legacy v1 decode.
- Widget test одного выбора победителя и отсутствия `2:0`.
- Полный regression suite и production APK.

## Журнал решений

- 2026-08-25 — начата замена переиспользованного best-of-three результата на отдельный winner-only domain type, поскольку ответственности форматов различаются.
- 2026-08-25 — экран сетки упрощён до единого вертикального списка с заголовками этапов.
- 2026-08-25 — устранён дефект завершения: после persistence commit UI переходит в итоговое состояние и показывает чемпиона.

## Результат

Double Elimination использует отдельный winner-only результат для основной сетки и placement replay. Mapper schema v2 не сохраняет счёт и читает прежние payload v1, извлекая из них победителя. Активный экран и история не показывают очки или `2:0`; матчи представлены единым списком. После завершения отображаются чемпион и итоговые места.

`make check` прошёл: Flutter analyze, 128 Flutter tests, lint и test React-приложения. Release APK был успешно собран до последнего UI-исправления; повторный build не запускался по явной просьбе пользователя остановить сборку, а итоговое UI-исправление покрыто analyze и полным regression suite.
