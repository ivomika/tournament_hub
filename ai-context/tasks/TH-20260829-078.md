# TH-20260829-078: Упростить header и закрепить dominant object экранов

- Статус: Выполнена
- Создана: 2026-08-29
- Обновлена: 2026-08-29
- Источник: golden-аудит — PageHeader, StageHeader и supporting surfaces конкурируют и отодвигают главное содержимое

## Цель

Сделать экранную иерархию state-first: один dominant object, один dominant action и компактный контекст состояния без повторения title/subtitle/stage information.

## Контекст

На operational screens повторяющаяся связка `PageHeader → StageHeader → Surface` создаёт тяжёлый верх и несколько равных акцентов. Это особенно заметно на Host Open/Running/Result Entry, Finished и Participant flows.

## Границы задачи

### Входит

- Карта `dominantObject`, `dominantAction`, supporting objects для ключевых экранов.
- Сведение StageHeader к компактному status strip там, где он дублирует PageHeader.
- Согласование `compact/standard/hero` header variants с screen state.
- Устранение конкурирующих accent borders/surfaces в первом viewport.
- First-viewport, semantics и golden checks.

### Не входит

- Изменение domain state, lifecycle, routes, guards или action callbacks.
- Desktop layout preset implementation (задача 077), кроме контрактов, которые нужны для hierarchy.
- Runtime typography/font fallback, line-height и кириллическая типографика.
- Новые visual tokens без отдельного ADR.

## Требования и ограничения

- Dominant object начинается не дальше одного viewport от safe-area.
- В первом viewport не более одной accent surface и одной dominant primary action.
- Running: current matchup; Result Entry: winner selection; Finished: champion; Open: roster/readiness; Cancelled: reason/recovery.
- Color, artwork или motion не являются единственным носителем состояния.
- Header/stage metadata не повторяют одну и ту же информацию более двух раз.

## Результат

Добавлен компактный `TournamentStageVariant.strip`, который сохраняет текстовые stage/status/detail, но убирает вторую elevated panel, divider и конкурирующий title. На strip переведены 7 Host и 4 Participant active/terminal screens; их dominant objects и actions задокументированы в общей matrix. Widgetbook показывает оба варианта, tests проверяют относительную высоту, base tone и использование strip на каждом consumer. First-viewport/golden matrix и полный `make check` прошли; typography не менялась.
