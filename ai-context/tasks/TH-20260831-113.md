# TH-20260831-113: Держать Spectator server активным вне турнира

- Статус: Выполнена
- Создана: 2026-08-31
- Обновлена: 2026-08-31
- Источник: прямое решение пользователя — LAN server должен быть доступен весь foreground runtime, а Spectator Web обязан показывать ожидание вне публичной стадии турнира.

## Цель

Отделить lifecycle Spectator LAN server от наличия active tournament: web app и endpoint доступны сразу после запуска Host, а public projection отражает `waiting`, `distribution`, `running` и `finished` без остановки transport между стадиями.

## Scope

- Входит: запуск server при `AppRuntime.start`, clear/publish projection при переходах, retry/resume без турнира, очистка terminal projection после выхода, tests и архитектурный/operations canon.
- Не входит: Participant networking, изменение wire schema v1, background serving вопреки ограничениям Android/iOS, redesign Spectator Web.

## Plan

1. Зафиксировать foreground runtime lifecycle в superseding ADR и каноне.
2. Запускать server независимо от active tournament; publish/clear projection независимо от transport.
3. Покрыть no-tournament, draft/open, distribution и leave-terminal сценарии интеграционными тестами.
4. Проверить Flutter/React suites, architecture gate и packaged LAN endpoint.

## Criteria

- [x] После `AppRuntime.start` static UI доступен даже без профиля/турнира.
- [x] Вне турнира и на Draft/Open Web показывает waiting; server не останавливается.
- [x] Distribution/Running/Finished публикуются через прежний v1 contract.
- [x] После выхода из terminal tournament snapshot очищен, endpoint остаётся доступным, а уже открытый Web сбрасывает финал в waiting.
- [x] Mobile pause/resume сохраняет OS-safe policy ADR-0012.

- Полный набор Flutter tests без golden suites — 236 тестов пройдено.

- `flutter analyze` — без замечаний; `make architecture` — оба architecture gates пройдены; `git diff --check` — пройдено.
- `flutter build macos --debug` — успешно, актуальный React bundle упакован.
- Packaged runtime на `http://10.3.44.59:8080/`: root `200`, hashed JS `200`/212649 bytes, snapshot `503 SNAPSHOT_UNAVAILABLE` без турнира; реальный headless Chrome показал «Ожидаем начало турнира» без network/JS exception.
- LAN integration сохраняет один endpoint для no tournament → Draft/Open → Distribution/Running/Finished → waiting; WebSocket/protocol/redaction tests пройдены.
- Полный `flutter test` запускался, но 24 существующих visual/role golden comparisons не совпадают с уже изменёнными UI baselines из текущего dirty worktree. Задача 113 визуалы Flutter/goldens не меняет; failure images удалены, риск ограничен отдельной синхронизацией goldens.

## Результат

Spectator server теперь стартует вместе с app runtime и остаётся доступным в foreground независимо от профиля или active tournament. Draft/Open/отсутствие турнира дают waiting, Distribution/Running/Finished — committed public projection, а после terminal exit старый финал очищается и уже открытый Web возвращается в waiting. Исправлен browser-only `fetch` receiver, из-за которого HTTP/Node проверки проходили, но настоящий Chrome показывал ошибку подключения. Решение закреплено ADR-0014, Operations, Screen map, Architecture и OD-013.
