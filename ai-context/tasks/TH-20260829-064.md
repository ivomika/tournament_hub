# TH-20260829-064: Подключить ConnectionQrCard на Host/Open

- Статус: Готова
- Создана: 2026-08-29
- Обновлена: 2026-08-29
- Источник: запрос пользователя и итог QR design battle

## Цель

Показать на экране `Host/Open` готовый `ConnectionQrCard`, чтобы организатор мог вывести spectator-подключение через QR или вручную скопировать адрес, сохраняя Host lifecycle и корректные LAN/recovery states.

## Контекст

Задача зависит от [067 — реализовать переиспользуемые QrCode и QrQuietZone](TH-20260829-067.md), которые заменяют renderer, созданный в 063. На текущем локальном этапе принимается простой адрес `http://<ip>:<port>` для spectator web app, запущенного самим Flutter Host в LAN. Кодирование secret/expiry/session binding и полный protocol contract сознательно выносятся в отдельные будущие задачи.

## Границы задачи

### Входит

- Получить из application/network projection готовые `encodedValue`, безопасный `displayAddress` и typed state.
- Разместить `ConnectionQrCard` в `Host/Open` как secondary connection surface, не вытесняя roster и основное управление турниром.
- Показать ready/starting/reconnecting/unavailable/expired/error/stale states и recovery согласно Host server lifecycle.
- Поддержать copy/share/retry semantics, connected clients и ручной ввод адреса без дублирования business logic в screen.
- Добавить screen/widgetbook/golden и LAN acceptance checks для Host/Open.

### Не входит

- Реализация secret, expiry, session binding, privacy fields или protocol version; текущая визуальная задача использует простой `http://<ip>:<port>`.
- Реализация или изменение WebSocket/LAN server lifecycle, interface selection, port conflict и rebind policy.
- Изменение domain/tournament progression, Participant join и Spectator Web.
- Создание нового QR renderer вместо 067.

## Требования и ограничения

- Статус QR не должен блокировать создание/проведение турнира; Host progression автономен от spectator availability.
- `encodedValue` не логируется и не показывается в diagnostics; в UI используется только presentation contract.
- При отсутствии serving endpoint QR заменяется текстовым состоянием и recovery action; stale/rebind явно сообщает пользователю.
- На mobile QR не должен конкурировать с roster и primary Host action; на desktop допускается split connection panel.
- В QR и ручном адресе показывается только локальный HTTP endpoint будущего spectator app; profile/history данные не добавляются.

## План

1. Получить из Host/application готовый локальный `http://<ip>:<port>` endpoint и typed connection state.
2. Сопоставить projection с `ConnectionQrCard` без сборки QR payload в screen.
3. Встроить connection surface в Host/Open с правильным action priority и recovery states.
4. Добавить screen/widgetbook/golden/LAN/accessibility проверки и обновить документацию.

## Критерии приёмки

- [ ] Простой локальный HTTP endpoint передаётся в экран через projection; production session/privacy hardening явно не входит в реализацию.
- [ ] Host/Open показывает QR и тот же ручной адрес из одной authoritative projection.
- [ ] Starting, serving, rebind/stale, failed, expired и stopped состояния различимы и не раскрывают secrets.
- [ ] QR не блокирует Host progression и не вытесняет primary tournament action.
- [ ] Copy/share/retry работают с понятным feedback; fallback ручного ввода доступен.
- [ ] Mobile/desktop, keyboard, semantics, contrast, reduced motion и LAN reconnect checks проходят.
- [ ] Rule routing повторно сверён с итоговым diff; фактический evidence заполнен.

## Проверка

Заполняется после реализации.

- Ожидаемые команды: `make architecture`, `flutter analyze`, targeted Host/Open/widgetbook/golden tests, `make check`.
- Ручная проверка: scan с телефона и телевизионного браузера в LAN, смена адреса, недоступный сервер, copy/share fallback.
- Непроведённые проверки: реальный LAN scan и protocol hardening выполняются отдельными будущими задачами; визуальные и локальные Host/Open проверки входят в эту задачу.
