# TH-20260828-049: Пересобрать визуальный язык и ключевые экраны Flutter UI

- Статус: Выполнена
- Создана: 2026-08-28
- Обновлена: 2026-08-28
- Источник: запрос пользователя о фиксации тезисов визуального улучшения UI и приведении реализации к вкусу проекта

## Цель

Сформировать и реализовать цельный визуальный язык Tournament Hub в направлении `Competitive / Cinematic / Clean`, чтобы ключевые экраны воспринимались как единый продукт, соответствовали канону дизайн-системы, подчёркивали fighter identity и корректно адаптировались от телефона до desktop.

## Контекст

Текущая реализация содержит дизайн-систему и Widgetbook, но визуально воспринимается как набор типовых Flutter-карточек и недостаточно выражает характер турнирного продукта. Канон уже определяет dark-first направление, иерархию fighter artwork, semantic tokens, mobile-first композицию и отдельную desktop-адаптацию. Задача должна превратить эти принципы в заметный, проверяемый визуальный результат, а не в локальную замену цветов.

## Границы задачи

### Входит

- Провести визуальный аудит текущих Widgetbook previews на compact, medium и expanded ширинах.
- Зафиксировать visual direction: глубокий dark canvas, сдержанный cinematic-слой, контрастные surface-уровни и контролируемый gold accent.
- Пересобрать общую иерархию экранов: один dominant object и одно главное действие на каждом ключевом состоянии.
- Усилить fighter artwork как главный visual anchor после assignment: `compact`, `standard`, `matchup` и `hero` применяются по роли.
- Заменить ощущение generic card UI на специализированные композиции `matchup`, `current match`, `result`, `champion` и tournament summary.
- Привести типографику к явной иерархии display/heading/title/body/label с поддержкой длинного русского текста.
- Реализовать отдельные mobile и desktop композиции там, где меняется структура: панели, summary, matchup и tournament progress не должны просто растягиваться.
- Проверить и привести к единому виду состояния `loading`, `empty`, `error`, `offline/stale`, `disabled`, `focus`, `finished` и `missing artwork`.
- Обновить Widgetbook как visual review board: ключевые screens/components, состояния, темы и viewports должны быть представлены рядом для сравнения.
- Приложить screenshot/golden evidence для ключевых компонентов и экранов до/после.

### Не входит

- Изменение domain-правил турниров, bracket engines, lifecycle или result calculation.
- Изменение network/protocol, persistence, history schema или spectator contract.
- Добавление новых продуктовых экранов и навигационных маршрутов, не заданных screen map.
- Переписывание token manifest без отдельного design decision и согласования последствий для обеих платформ.
- Редактирование `docs/source` и лицензируемых исходных artwork.

## Требования и ограничения

- Flutter остаётся mobile-first; desktop использует адаптивную композицию, а не масштабирование мобильного layout.
- Screens используют только публичный Design System API и semantic tokens; raw colors, magic dimensions и private themes запрещены.
- Artwork, fighter name и nickname остаются частью полной participant identity на всех tournament screens.
- На visual region должна быть одна dominant Primary action; secondary и destructive actions визуально отделяются.
- Цвет, hover, motion и artwork не могут быть единственным носителем статуса или действия.
- Поддержать compact/medium/expanded width classes, keyboard/focus, 200% text scale и длинные русские строки.
- Сначала пересобираются `Main`, `Host Running / Result Entry` и `Host Finished / Champion`; остальные экраны выравниваются по утверждённому языку.
- Generated token bindings не редактируются вручную.
