# TH-20260824-023: Сохранять ruleset и завершённый результат турнира

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-25
- Источник: запрос пользователя реализовать start-to-end сценарий с итогами и чемпионом; уточнение, что турнирные правила могут меняться.

## Цель

Завершённый турнир атомарно сохраняется с применённым ruleset, итоговой таблицей и вычисленным champion, а после перезапуска восстанавливается тот же воспроизводимый результат независимо от будущих изменений реализаций правил.

## Контекст

`TH-20260824-018` хранит только активный турнир. `TH-20260824-019` должна определить заменяемые scoring, tie-break и champion selection policies. Для полного start-to-end сценария недостаточно показать итог только в памяти: local-first и неизменяемая история требуют устойчивого finished snapshot. Задача заблокирована до определения contracts и ruleset identity в `TH-20260824-019`.

Зависимости:

- `TH-20260824-018` — активное состояние и Drift repository;
- `TH-20260824-019` — standings, champion, completion invariants и ruleset identity/version;
- `TH-20260824-020` использует сохранённый результат для экранов итогов и чемпиона.

## Границы задачи

### Входит

- Неизменяемый finished tournament snapshot с участниками, назначениями бойцов, всеми матчами, итоговыми местами и champion.
- Сохранение стабильного `rulesetId` и версии правил, применённых при расчёте.
- Атомарный переход active → finished без состояния, где турнир одновременно активен и завершён.
- Repository contracts, Drift schema/migration, mapper и round-trip/reopen tests.
- Идемпотентность повторного завершения по стабильному tournament ID.
- Проверка, что поздняя замена production policy не переписывает уже сохранённый snapshot.

### Не входит

- Career и achievements projections.
- Сетевая синхронизация finished snapshot.
- Полный экран истории нескольких турниров; сохраняется модель, необходимая текущему start-to-end flow.
- Выбор конкретных значений scoring/tie-break — `TH-20260824-019`.

## Требования и ограничения

- Finished snapshot является только добавляемым и не пересчитывается неявно новой версией ruleset.
- Champion и standings внутри snapshot должны соответствовать авторитетным матчам и зафиксированному ruleset.
- Persistence не зависит от конкретных policy-классов: сохраняются стабильные данные и identity/version правил.
- Повторная команда завершения не создаёт второй snapshot и не удаляет первый.
- Migration сохраняет active tournament, profile и draft.
- Открытый продуктовый вопрос: может ли Host менять ruleset после старта. До решения persistence должна как минимум фиксировать фактически применённую версию при завершении.

- Policy replacement test: новая policy не меняет прочитанный finished snapshot.
- Duplicate finish test: в базе остаётся один snapshot.
- Transaction rollback test: ошибка не удаляет active tournament и не создаёт partial finished state.
- Migration test из schema v3 с активным турниром.
- `make generate`, `make check`, production build.

## Результат

Добавлены `FinishedTournamentSnapshot`, отдельный completion repository port, Drift-таблицы finished tournament/standings и schema v4. Сохранение выполняется одной транзакцией, удаляет active marker только после записи полного результата и идемпотентно по tournament ID. Reopen восстанавливает сохранённые standings/champion напрямую. Миграция v3 добавляет MVP ruleset по умолчанию, не теряя активное состояние. Persistence suite: 11 тестов, включая rollback и reopen.
