# TH-20260824-013: Реализовать локальное хранение tournament draft

- Статус: Выполнена
- Создана: 2026-08-24
- Обновлена: 2026-08-24
- Источник: запрос пользователя сделать систему турнира локально на одном устройстве с возможностью подмены реализации.

## Цель

Tournament draft устойчиво сохраняется на текущем устройстве через заменяемый `TournamentRepository` и восстанавливается после перезапуска приложения.

## Контекст

В проекте уже приняты Drift, Freezed и code generation (`TH-20260824-004`). Tournament Core и repository contract создаются в `TH-20260824-012`. Сеть и другие устройства на этом этапе отсутствуют.

Зависимость: `TH-20260824-012`.

## Границы задачи

### Входит

- Drift tables для tournament draft и participant snapshots.
- Freezed data models и отдельные mappers data/domain.
- Drift implementation `TournamentRepository`.
- Атомарное сохранение draft и участников.
- Загрузка активного draft после повторного открытия базы.
- Schema migration с текущей версии database.
- Persistence и repository contract tests.

### Не входит

- Матчи, standings и tournament history.
- Сетевой transport, Host session и multi-device sync.
- Cloud backup.
- UI создания турнира.

## Требования и ограничения

- Application/Core зависит только от `TournamentRepository`, а не от Drift.
- Сохранение draft и всех participant snapshots выполняется одной транзакцией.
- Data models, mappers, tables и repository implementation разделены по ответственности.
- Использовать Drift/Freezed generation и не редактировать generated code вручную.
- Migration не должна повреждать уже сохранённый local profile.
- Тесты должны использовать заменяемый executor и проверять reopen существующей SQLite database.

## План

1. Спроектировать schema draft/participants и migration следующей database version.
2. Описать Freezed data models и mappers.
3. Реализовать Drift repository adapter и транзакционное сохранение.
4. Добавить contract tests, round-trip и database reopen tests.
5. Проверить сохранность local profile после migration.
6. Обновить ADR/architecture docs и generated code.

## Критерии приёмки

- [x] Draft и все participants сохраняются атомарно.
- [x] Local/guest source и snapshot nickname восстанавливаются без потери.
- [x] Повторное сохранение обновляет draft без дубликатов.
- [x] Reopen базы восстанавливает активный draft.
- [x] Migration сохраняет существующий local profile.
- [x] Core/application можно переключить на fake/in-memory repository без изменения кода.
- [x] Code generation, persistence tests и `make check` проходят.

## Проверка

- Repository contract tests для fake и Drift adapters.
- Drift round-trip/reopen tests с local + guest participants.
- Migration test с database schema предыдущей версии и сохранённым local profile.
- `make generate`, `flutter analyze`, `make check`: ожидается успешное выполнение.

## Журнал решений

- 2026-08-24 — для первой single-device реализации используется Drift adapter, но Tournament Core видит только repository port.
- 2026-08-24 — draft сохраняется целиком транзакционно, чтобы participant snapshots не расходились с aggregate state.
- 2026-08-24 — реализация начата со schema v2; порядок participants хранится явной колонкой `position`, а единственный active draft заменяется целиком в одной транзакции.

## Результат

Добавлены Drift tables schema v2, Freezed data models, отдельные mappers и `DriftTournamentRepository`. Draft и ordered participants заменяются целиком в одной транзакции; repository загружает один active draft через domain port. Tests проверяют round-trip/update, reopen SQLite-файла и migration v1→v2 с сохранённым `LocalProfile`. Generated Drift/Freezed code обновлён штатной командой. `make check` завершён успешно 2026-08-24.
