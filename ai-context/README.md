# AI Context

`ai-context` — рабочая память проекта для задач, решений и проверок. Перед любым изменением репозитория исполнитель читает [rules/README.md](rules/README.md), затем сверяется с [task-list.md](task-list.md).

Постановка и реализация задач следуют [экспериментальному workflow](workflow.md). Это единственный канонический текст этапов, test-first gate и approval; он применяется и без вызова skill.

## Правила работы

- Любое изменение репозитория начинается с задачи в едином списке.
- Задачи нумеруются сквозным целым числом без дат и без повторного использования номера.
- Реестр не делится на таблицы, категории или архивы: это один упорядоченный список.
- Статус задачи обозначается только цветным индикатором: `🟣` запланирована, `🚧` в работе, `🔴` заблокирована, `✅` выполнена.
- У задачи в работе может быть только один исполнитель.
- Перед началом задача декомпозируется до проверяемого результата. Если деталей недостаточно для безопасного решения, это фиксируется в карточке как открытый вопрос.
- Для задачи, которой нужны решения, границы, критерии или журнал работы, создаётся карточка в `task-details/` по [template.md](task-details/template.md). Ссылка на неё остаётся в строке списка.
- Обратная связь, дефект или уточнение в пределах уже сформулированной цели не создаёт новую задачу. Исполнитель продолжает ту же карточку; если карточки ещё нет, создаёт её для существующего номера и добавляет ссылку в реестр. Если задача уже имела статус `✅`, перед изменениями она возвращается в `🚧` и после повторной проверки снова закрывается.
- Новая задача создаётся только тогда, когда результат можно реализовать и принять независимо от исходной цели. Если запрос содержит и follow-up, и независимую цель, существующая карточка получает follow-up, а новый номер — только независимая часть.
- Каждая карточка ведёт append-only раздел `Changelog`. Для каждой итерации в нём дословно сохраняются относящийся к задаче prompt пользователя, выполненные изменения и проверки. Старые записи не переписываются при последующих правках.
- В каждой карточке обязателен раздел «Применимые правила»: прочитанные core rules, flutter rules для Flutter scope, результат conditional scan и конкретное влияние применимых правил.
- После завершения обновляются индикатор, критерии, проверки, решения и итог карточки.
- Рабочая документация ведётся на русском; технические identifiers не переводятся.
- Обязательные core rules читаются целиком до начала работы. Для Flutter scope дополнительно читаются все обязательные flutter rules; порядок и границы задаёт `rules/README.md`. Conditional rules читаются при совпадении trigger.

## Что является источником истины

- [task-list.md](task-list.md) — состояние всех задач.
- `task-details/` — детализация конкретных задач.
- [rules/README.md](rules/README.md) — router обязательных правил.
- [workflow.md](workflow.md) — процесс задач; текущий Stage и evidence хранятся в карточке, статус — в task-list.
- [.agents/skills](../.agents/skills) — единственный каталог локальных skills проекта; [назначение навыков](../docs/development/repository-skills.md).
- Файлы вне `ai-context` не заменяют эти записи.
