# Обзор архитектуры

Tournament HUB — local-first система с двумя пользовательскими приложениями:

```text
Flutter Host (авторитетное состояние + локальный сервер)
                         |
                    локальная сеть
                  /                 \
Flutter Participant              React Spectator
полное производное состояние     display projection только для чтения
```

Host владеет активным состоянием `LocalGroup` и `Tournament`. Состояние Participant и Spectator можно восстановить: при подключении или reconnect они сходятся с Host через полный snapshot, после чего применяют инкрементальные event в порядке revision.

## Категории состояния

- Постоянное личное состояние: identity, профиль, история и настройки; карьера и достижения вычисляются из истории.
- Постоянное состояние Host: данные активного турнира, сохраняемые достаточно часто, чтобы перезапуск приложения не приводил к потере введённых результатов.
- Состояние сессии: соединения, ожидающие подтверждения заявки, spectators и временное состояние transport.
- Производное состояние: таблица, карьера, достижения и spectator display projection.

## Основной поток данных

```text
действие UI -> application command -> domain validation -> изменение агрегата
           -> локальное сохранение -> event/projection с revision -> клиенты
```

При завершении Host создаёт неизменяемый и самодостаточный Tournament Snapshot и повторяет его доставку каждому Participant до подтверждения. Стабильный идентификатор турнира делает импорт snapshot идемпотентным.

Production bundle React собирается отдельно и встраивается во Flutter-приложение. Локальный сервер Host раздаёт его браузерам в той же сети.

## Presentation и размеры экрана

Архитектура presentation следует принципу mobile-first, но не связывает пользовательский сценарий с фиксированным размером телефона. Domain и application слои одинаковы для всех платформ, а Flutter presentation выбирает композицию по доступной ширине и возможностям ввода.

Desktop-представление является адаптацией, а не масштабированием мобильного дерева widgets. На широком экране presentation может менять навигацию, ограничивать ширину основного контента, показывать связанные области рядом и использовать master-detail. Изменение размера окна должно приводить к предсказуемой перестройке без потери состояния или доступных действий.

Подробные требования и критерии проверки описаны в `docs/product/platform-and-responsive-ui.md`.
