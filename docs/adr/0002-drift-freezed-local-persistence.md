# ADR-0002: Drift и Freezed для локального хранения

- Статус: Принято
- Дата: 2026-08-24

## Контекст

Flutter-приложению требуется типобезопасное локальное хранилище, работающее на mobile и desktop, с контролируемыми миграциями и минимальным количеством ручного boilerplate. Domain не должен зависеть от схемы базы данных.

## Решение

Использовать Drift для SQLite database client, таблиц, запросов и миграций. Data models/DTO описывать через Freezed. Код Drift и Freezed генерировать командой `make generate`; generated-файлы хранить в Git и не редактировать вручную.

Явный ручной mapping допускается только на границе data/domain, где он сохраняет изоляцию domain и делает преобразование проверяемым.

Агрегат tournament draft сохраняется целиком: строка draft и упорядоченные participant snapshots записываются в одной Drift-транзакции. В приложении существует не более одного active draft; повторное сохранение атомарно заменяет предыдущий состав. Schema v2 добавляет tournament tables последовательной migration, не изменяя таблицу локального профиля.

## Последствия

Схема, companions, data classes и value equality DTO генерируются типобезопасно. Изменение аннотированных исходников требует повторной генерации и проверки generated diff. В проект добавляются build-time зависимости Drift/Freezed и обязательная стратегия последовательных migrations при увеличении `schemaVersion`.
