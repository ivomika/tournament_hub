# Домен турнира

## Реализованные этапы

Tournament draft создаётся локально на одном устройстве из обязательного профиля владельца и гостей. Минимальный состав — два участника. Каждый участник сохраняется как самостоятельный snapshot с source `localProfile` или `guestProfile`; nickname исходного профиля не является живой ссылкой.

Поверх состава реализована подготовка стартового состояния турнира. Заменяемый `TournamentRules` формирует детерминированное расписание одного круга round robin, а независимый `FighterAssignmentStrategy` назначает участникам уникальных бойцов. Production-стратегия назначения использует управляемый источник случайных индексов, поэтому её можно воспроизводимо тестировать и заменять без изменения application-сценария.

Расписание представлено упорядоченной матрицей раундов. При чётном составе создаётся `N - 1` раундов без bye, при нечётном — `N` раундов с одним bye в каждом. Domain-модель расписания самостоятельно проверяет количество матчей, уникальность каждой пары, покрытие состава и запрет повторного участия игрока в одном раунде. `TournamentSetup` дополнительно проверяет полноту назначений и уникальность бойцов, не доверяя конкретным реализациям стратегий.

Подготовка пока не меняет статус и не сохраняет стартовое состояние: persistence, UI запуска, результаты матчей и таблица входят в последующие задачи.

## Экраны турнира

После успешного создания draft приложение подготавливает `TournamentSetup` и открывает экран обзора. Обзор показывает название, количество участников и раундов, а также snapshot каждого игрока с назначенным бойцом и локальным avatar. Presentation получает готовое расписание и назначения и не повторяет domain-расчёты.

Из обзора отдельным маршрутом открывается прокручиваемый экран раундов. Каждый раунд показывает все пары игроков; при нечётном составе явно указан участник с bye. На телефоне обзор использует одну колонку, на широком окне сводка и список участников располагаются рядом. Подготовленное состояние пока не восстанавливается после перезапуска: для этого потребуется отдельное persistent-представление активного турнира.

## Целевая модель MVP

MVP использует агрегат Tournament формата round robin: расписание по раундам, обычные и технические результаты, уникальное назначение бойцов, standings projection, этапы tie-break и неизменяемый итоговый snapshot.

Основные инварианты:

- Игрок не играет сам с собой.
- До изменения состава каждая основная пара встречается ровно один раз.
- Игрок участвует не более чем в одном основном матче раунда.
- Каждый активный игрок имеет одного бойца, бойцы не повторяются.
- Standings полностью воспроизводится из участников, матчей и результатов.
- Повторное применение одного результата не меняет итог второй раз.
- История завершённых матчей сохраняется при выходе игрока и позднем изменении состава.
- Завершённый турнир не содержит неразрешённых ничьих по местам.

Система очков и порядок стандартных tie-break критериев остаются открытыми продуктовыми решениями.
