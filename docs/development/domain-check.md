# Domain architecture checker

`tools/domain-check` — локальное Web mini app для просмотра Domain-архитектуры TournamentHUB.

Инструмент читает generated `domain-architecture.json` и показывает фактические Dart declarations и ссылки между ними. Карта не содержит придуманных групп и не требует перехода к файлам, чтобы узнать точные имена Domain-типов.

## Модель данных

`domain-structure.mjs` рекурсивно сканирует `apps/tournament_app/lib/domain` и полностью генерирует schema v6:

- каждый `class`, `abstract class`, `sealed class`, `interface` и `enum` становится отдельным node с точным Dart-именем;
- `kind` берётся из синтаксических modifiers, а `signature` — из заголовка declaration;
- непосредственно предшествующий Dart doc comment `///` становится `description`; при его отсутствии генератор сообщает только kind и фактическое количество членов, не придумывая назначение объекта;
- top-level поля, getters, конструкторы и методы извлекаются из тела declaration в отдельные `fields` и `methods`;
- значения enum извлекаются в `members`;
- area определяется верхнеуровневым Domain module: `tournament`, `statistics`, `profile` и так далее;
- `folder` каждого node и общий реестр `folders` генерируются из фактического относительного каталога declaration внутри area; viewer не классифицирует declarations по имени, kind или назначению;
- `role` определяется каталогом declaration: `entity`, `model`, `port`, `repository`, `value-object` или `failure`;
- `importance` вычисляется из `role`, `kind`, имени declaration и имени area и принимает `prominent`, `standard` или `compact`;
- edge создаётся, когда declaration фактически упоминает другой известный Domain-тип; `extends` и `implements` сохраняются как отдельные синтаксические labels, остальные упоминания имеют label `references`;
- comments и string literals маскируются перед поиском references, поэтому текст документации и сообщений не создаёт ложные связи.

Source file paths намеренно не входят в UI. Физическое расположение используется генератором для определения Domain area и структурного folder container; viewer показывает только имя относительной папки, но не путь к Dart-файлу. `domain-architecture.json` вручную не редактируется. После изменения Domain-кода выполняется `make domain-check-generate`, а `make domain-check-validate` обнаруживает drift generated-карты.

Generator выполняет лексический разбор без Dart analyzer. Поэтому edge гарантирует наличие точного identifier в declaration, но не заявляет runtime-вызов или владение. Извлечение членов ограничено top-level содержимым declaration: локальные переменные и вызовы внутри тела метода не становятся полями или методами. Конструкторы входят в `methods`, getters также считаются методами поведения. Имена Domain declarations должны быть уникальны; при дубликате generator завершается ошибкой вместо неоднозначного объединения.

## Как читать связи

- Объекты сгруппированы в подписанные кластеры по Domain area. Внутри каждой area находятся вложенные контейнеры фактических каталогов `entities`, `failures`, `models`, `ports`, `repositories`, `value_objects` и любых каталогов, которые появятся в Domain-коде позднее. Имена и принадлежность этих контейнеров приходят из generated schema, а не из ручного списка viewer.
- Число в заголовке area показывает количество её видимых объектов после применения фильтров; число в заголовке folder container — количество видимых объектов папки. Пустые после фильтрации folders не отображаются.
- Кластеры распределяются по просторной сетке независимо от размера области. Широкие горизонтальные коридоры между соседними карточками и между кластерами приоритетны: они оставляют место для чтения и выбора edges, даже если вся карта требует горизонтальной прокрутки. Граница кластера означает принадлежность к area, а не отдельную runtime-границу.
- Обзорная карточка показывает только kind declaration, его точное имя и описание. Поля, методы, конструкторы и enum values намеренно не выводятся ни на graph card, ни в inventory: полный состав выбранного объекта находится исключительно в detail panel.
- Поиск продолжает индексировать signature, поля, методы, конструкторы и enum values. Поэтому declaration можно найти по его API, не перегружая этим API обзорную карту.
- `prominent` занимает всю внутреннюю ширину cluster и имеет высоту `176px`. Его получает root entity, точное имя которой совпадает с PascalCase-именем area: `Tournament`, `Profile`, `Game`.
- `compact` высотой `118px` получают declarations из `value_objects`, `failures` и все enums. Остальные entities, models, ports и repositories имеют `standard` высотой `142px`.
- Размер отражает воспроизводимую структурную роль из кода, а не ручную оценку исполнителя, количество связей или runtime ownership. `role` и `importance` выбранного объекта видны в detail panel.
- Стрелка идёт от объекта, который использует зависимость, к объекту, от которого он зависит.
- После выбора карточки detail panel разделяет её прямые связи на «Использует» и «Используется в». Кнопка в списке переносит фокус к связанному объекту.
- «Фокус связей» оставляет карту видимой, но приглушает объекты и рёбра вне прямого окружения выбранной карточки. Это помогает читать локальную зависимость без заявления о транзитивных связях.
- «Фокус связей» намеренно выключен по умолчанию, и viewer не назначает стартовый выбранный объект: локальный контекст включается только явным действием пользователя.
- Золотым показаны исходящие связи выбранного объекта, голубым — входящие.

Связи между объектами одной Domain area отображаются сплошными линиями. Связи, пересекающие границу area cluster, отображаются более контрастным пунктиром. Пунктир кодирует только пересечение границы области: он не меняет направление, label, семантику или интерактивное поведение edge.

Каждая сторона карточки использует две общие точки подключения: исходящие edges выходят из первой, входящие приходят во вторую. Для горизонтальной связи исходящий порт находится выше центра стороны, входящий — ниже; для вертикальной исходящий находится левее центра, входящий — правее. Точки разнесены на `18px` поперёк основного направления связи. Это разделяет встречные стрелки у карточки без создания отдельного порта для каждого edge и без изменения смысла зависимости.

## Навигация по карте

Сам `graph-viewport` имеет минимальную высоту `window.innerHeight - panelHeader.offsetHeight`, но не менее `320px`. Поэтому интерактивная область занимает высоту экрана за исключением собственного header карты независимо от положения viewer на странице. Общая панель может продолжаться ниже первого экрана; inventory расположен после неё. При resize окна минимальная высота и режим «Вписать» пересчитываются.

Горизонтальная компоновка сохраняет исходные ограничения: общий layout имеет максимальную ширину `1600px` и внешний отступ `24px`, а Details постоянно находится в отдельной колонке шириной `310px`.

Размером карты внутри viewport можно управлять в её заголовке:

- `−` и `+` меняют масштаб шагом `10%`;
- range control задаёт точный масштаб в диапазоне `10–200%` с шагом `5%`;
- `100%` возвращает исходные размеры layout;
- `Вписать` выбирает минимальный масштаб по ширине и высоте, чтобы весь текущий graph canvas оказался внутри viewport с внутренним отступом `12px`;
- ручной масштаб сохраняется в `localStorage`; режим «Вписать» пересчитывается при изменении окна, фильтров или состава видимых nodes.

## Горячие клавиши

- `+`/`=` или `Numpad +` — увеличить масштаб на `10%`;
- `−` или `Numpad −` — уменьшить масштаб на `10%`;
- `0` или `Numpad 0` — вернуть масштаб `100%`;
- `F` — включить или выключить «Фокус связей».

Shortcuts определяются через физические `KeyboardEvent.code`, поэтому не зависят от русской или английской раскладки. Они не обрабатываются, когда фокус находится в `input`, `select`, `textarea` или `contenteditable`; сфокусированная карточка не отключает управление картой. Сочетания с `Ctrl`, `Meta` и `Alt` остаются браузеру и операционной системе. У controls есть видимые подсказки, `title` и `aria-keyshortcuts`.

Масштаб применяется к graph canvas целиком: карточкам, cluster boundaries, тексту и edges. Отдельный `graph-stage` получает уже масштабированные размеры и формирует корректную область прокрутки, поэтому уменьшенная или увеличенная карта не обрезается и не пропадает. Если карта меньше viewport, она центрируется в свободном пространстве. Геометрия layout и смысл связей при этом не меняются. Высота viewport определяется экраном и не управляется zoom controls.

Карту можно перемещать удержанием основной кнопки мыши на свободном месте и движением указателя. Drag-to-pan изменяет стандартные `scrollLeft` и `scrollTop`; ползунки прокрутки, колесо мыши и клавиатурная навигация остаются доступны. Начало drag на интерактивном элементе не перехватывается, поэтому карточки объектов продолжают открываться обычным кликом.

Запуск из корня репозитория:

```sh
make domain-check
```

На Windows команда использует Python launcher `py -3`, на macOS/Linux —
`python3`. При нестандартной установке интерпретатор можно задать явно:

```sh
make domain-check PYTHON=python
```

При изменении Domain declarations generated JSON обновляется в той же задаче.
