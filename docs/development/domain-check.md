# Domain architecture checker

`tools/domain-check` — локальное Web mini app для просмотра Domain-архитектуры TournamentHUB.

Инструмент читает `domain-architecture.json` и показывает области, объекты, ports, repositories и основные связи. JSON намеренно описывает архитектуру кратко: имена, важные поля, доступные операции и зависимости, без копирования исходного Dart-кода.

## Как читать связи

- Объекты сгруппированы в подписанные кластеры по Domain area. Число в заголовке показывает количество видимых объектов области после применения фильтров.
- Кластеры распределяются по просторной сетке независимо от размера области. Широкие горизонтальные коридоры между соседними карточками и между кластерами приоритетны: они оставляют место для чтения и выбора edges, даже если вся карта требует горизонтальной прокрутки. Граница кластера означает принадлежность к area, а не отдельную runtime-границу.
- Размер карточки передаёт роль узла на обзорной карте: `aggregate` занимает всю внутреннюю ширину кластера; entities, ports, repositories, models и abstractions используют стандартный размер; value objects и failures компактны. Размер означает визуальный уровень, а не бизнес-приоритет или runtime ownership.
- Стрелка идёт от объекта, который использует зависимость, к объекту, от которого он зависит.
- После выбора карточки detail panel разделяет её прямые связи на «Использует» и «Используется в». Кнопка в списке переносит фокус к связанному объекту.
- «Фокус связей» оставляет карту видимой, но приглушает объекты и рёбра вне прямого окружения выбранной карточки. Это помогает читать локальную зависимость без заявления о транзитивных связях.
- «Фокус связей» намеренно выключен по умолчанию, и viewer не назначает стартовый выбранный объект: локальный контекст включается только явным действием пользователя.
- Золотым показаны исходящие связи выбранного объекта, голубым — входящие.

Связи между объектами одной Domain area отображаются сплошными линиями. Связи, пересекающие границу area cluster, отображаются более контрастным пунктиром. Пунктир кодирует только пересечение границы области: он не меняет направление, label, семантику или интерактивное поведение edge.

Каждая сторона карточки использует две общие точки подключения: исходящие edges выходят из первой, входящие приходят во вторую. Для горизонтальной связи исходящий порт находится выше центра стороны, входящий — ниже; для вертикальной исходящий находится левее центра, входящий — правее. Точки разнесены на `18px` поперёк основного направления связи. Это разделяет встречные стрелки у карточки без создания отдельного порта для каждого edge и без изменения смысла зависимости.

## Навигация по карте

Viewer занимает оставшуюся под header, controls и legend высоту окна, но не менее `320px`. Карта прокручивается внутри viewer по вертикали и горизонтали, поэтому большой graph не увеличивает высоту всей страницы.

Карту можно перемещать удержанием основной кнопки мыши на свободном месте и движением указателя. Drag-to-pan изменяет стандартные `scrollLeft` и `scrollTop`; ползунки прокрутки, колесо мыши и клавиатурная навигация остаются доступны. Начало drag на интерактивном элементе не перехватывается, поэтому карточки объектов продолжают открываться обычным кликом.

Запуск из корня репозитория:

```sh
make domain-check
```

На Windows команда использует Python launcher `py -3`, на macOS/Linux —
`python3`. При нестандартной установке интерпретатор можно задать явно:

```sh
make domain-check PYTHON=python
```

При изменении публичной Domain-архитектуры обновляется и JSON-инвентарь в той же задаче.
