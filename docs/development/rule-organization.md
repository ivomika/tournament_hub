# Организация правил проекта

## Scope

`ai-context/rules/core` содержит требования ко всему коду проекта. `ai-context/rules/flutter` содержит требования Flutter-клиента `apps/tournament_app` и его тестов, включая domain, app, infrastructure и presentation.

Папка определяет технологический scope, именованный подсписок — ответственность. Архитектура spectator web, JS-инструментов и других приложений определяется отдельно.

## Действующие правила

| ID | Ответственность | Scope |
| --- | --- | --- |
| R-001 | SOLID | core |
| R-002 | Документирование | core |
| R-003.a–d | Границы слоёв, use cases через state, библиотеки и дизайн-система | flutter |
| R-004 | Типизация | core |
| R-005 | Локализация intl | flutter |
| R-006.a–b | Композиция widgets и именованные callbacks | flutter |

## Сопровождение

[Router](../../ai-context/rules/README.md) определяет обязательное чтение по scope. [Registry](../../ai-context/rules/registry.json) содержит текущие ID, группы и пути. [Maintenance](../../ai-context/rules/maintenance.md) задаёт добавление и изменение правил через task-list и документацию.

Уточнение требования меняет его leaf без нового ID; самостоятельное требование внутри группы получает следующий suffix; независимая ответственность получает следующий root. Для текущего состава следующие номера — R-003.e, R-006.c и R-007. Номера проверяются перед регистрацией; proposals их не резервируют.

## Проверка

`node tools/check_rules.cjs` проверяет последовательность ID и suffix, уникальность, имена файлов, группы, обязательный router и ссылки. Семантическое размещение и отсутствие дублей оцениваются при review. [Skill аудита](code-rules-audit.md) читает правила по scope и использует точные действующие leaf ID.
