# Тестирование кода

Любое изменение кода сопровождается проверкой затронутого поведения. Новое поведение и исправленные дефекты получают автоматическое покрытие; рефакторинг проверяется сохранением поведения. Обязательное требование: [R-007](../../ai-context/rules/core/007-code-testing.md).

## Выбор уровня

| Изменение | Основная проверка |
| --- | --- |
| Вычисления, валидация, domain | Unit-тесты результата, инвариантов, ошибок и границ |
| Port/adapter, хранение, сериализация | Контрактные/интеграционные тесты с контролируемыми зависимостями |
| State/controller и UI | Переходы состояния и widget-тесты отображения/действий |
| Сценарий нескольких компонентов | Интеграционный тест цепочки и отказов |
| Checker/скрипт | Положительные и отрицательные fixtures, exit code и диагностика |
| Документация, skills, метаданные | Ссылки, структура, целостность и соответствующий workflow |

Не все уровни требуются для каждого изменения. Тесты должны ловить реальную ошибку; буквальное повторение алгоритма или наличие строк в source не заменяют проверку поведения. Generated-код проверяется вместе с генератором.

## Запуск и отчёт

Для Flutter-импортов выполняется `make architecture-test`, для состава правил — `node tools/check_rules.cjs`. Они проверяют свой контракт и не заменяют unit/widget/integration tests приложения.

Карточка содержит план, команды, фактические результаты, покрытие и пробелы. Невыполненная проверка не называется успешной. Ограничения среды или пользователя фиксируются явно. Запрет билдов сохраняется: тестирование не означает автоматическое разрешение сборки или запуска приложения.
