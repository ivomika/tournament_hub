# Тестирование кода

Любое изменение кода сопровождается соразмерной проверкой. Автоматическое покрытие обязательно для новой/изменённой бизнес- и прикладной логики и её дефектов. Чистый визуал и настройки локального запуска проверяются по риску, без требования тестировать каждый параметр. Обязательное требование: [R-007](../../ai-context/rules/core/007-code-testing.md).

Область TestGate, порядок test-first, RED/baseline GREEN и human approval задаёт только [канонический workflow](../../ai-context/workflow.md). Gate относится к логике, в том числе state/controllers и обработке данных инструментов; чистое отображение и debug-профили не требуют gate. Пример проверки процесса находится в [walkthrough](ai-development-workflow.md).

## Выбор уровня

| Изменение | Основная проверка |
| --- | --- |
| Вычисления, валидация, domain | Unit-тесты результата, инвариантов, ошибок и границ |
| Port/adapter, хранение, сериализация | Контрактные/интеграционные тесты с контролируемыми зависимостями |
| State/controller, действия UI с бизнес-эффектом | Тесты переходов состояния/сценария; widget-тест при необходимости |
| Оформление, темы, layout, отображение/zoom/pan/drag viewer | Визуальная проверка состояний/размеров, analyzer; существующие tests или новый целевой тест при оправданном риске |
| Локальный debug/launch-профиль | Проверка конфигурации и реальный запуск; без теста наличия каждого параметра |
| Сценарий нескольких компонентов | Интеграционный тест цепочки и отказов |
| Логика checker/скрипта, анализ кода и данных | Положительные и отрицательные fixtures, exit code и диагностика |
| Документация, skills, метаданные | Ссылки, структура, целостность и соответствующий workflow |

Не все уровни требуются для каждого изменения. Тесты должны ловить реальную ошибку; буквальное повторение алгоритма или наличие строк в source не заменяют проверку поведения. Generated-код проверяется вместе с генератором.

## Запуск и отчёт

Для Flutter-импортов выполняется `make architecture-test`, для состава правил — `node tools/check_rules.cjs`. Они проверяют свой контракт и не заменяют unit/widget/integration tests приложения.

Карточка содержит план, команды, фактические результаты, покрытие и пробелы. Невыполненная проверка не называется успешной. Ограничения среды или пользователя фиксируются явно. Запрет билдов сохраняется: тестирование не означает автоматическое разрешение сборки или запуска приложения.
