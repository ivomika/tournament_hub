# Открытые продуктовые решения

До фиксации решения нельзя реализовывать следующие пункты как неизменяемые доменные правила:

1. Автоматическое восстановление активной сессии после полного перезапуска Host.
2. Входит ли собственный аватар игрока в MVP.
3. Срок хранения недоставленного результата на Host.
4. Учитываются ли технические победы и поражения в обычном карьерном win rate.
5. Точная граница раундов между пропущенными и будущими матчами для late join.

После принятия решения нужно обновить соответствующий domain- или protocol-документ и добавить ADR, если решение меняет границы компонентов, хранение данных или совместимость.

## Подтверждённые связанные решения

- Ранее введённый результат матча разрешено исправлять. Исправление заменяет авторитетный результат, фиксируется в audit и запускает полный пересчёт производных standings; повторное начисление поверх старого результата не допускается.
- Очки: `2:0 → 3/0`, `2:1 → 2/1`, `1:2 → 1/2`, `0:2 → 0/3`. Technical result `2:0` начисляется как обычный `2:0`, оставаясь отдельным типом результата.
- Standings сортируется по очкам, затем по победам, разнице схваток, выигранным схваткам и личной встрече. Если критерии не дают уникальные места, равенство разрешается дополнительным Tie-Break Stage.
- Ruleset выбирается при старте турнира, фиксируется его ID и версией и не может быть заменён внутри начатого турнира. Конкретные scoring, tie-break и champion policies остаются заменяемыми между турнирами.
