# Task

Преобразуй запрос пользователя в независимые, проверяемые задачи и сохрани их в `ai-context` текущего проекта. Этот навык только планирует и фиксирует работу: не вносит продуктовые изменения и не начинает реализацию.

## Перед началом

1. Прочитай `ai-context/README.md` и `ai-context/task-list.md`.
2. Определи, является ли запрос новой независимо принимаемой целью или follow-up к существующей задаче.
3. Только для новой цели найди максимальный номер в реестре и продолжи сквозную нумерацию.
4. Отдели явные требования пользователя от предположений. Существенные неизвестные оставь открытыми вопросами, а не угадывай.

## Реестр

- Используй один маркированный список в `ai-context/task-list.md`; не создавай таблиц, разделов по статусу и привязок к датам.
- Новая задача получает `🟣` и короткое описание результата.
- Разбивай запрос на задачи, которые можно выполнить и проверить независимо. Не дроби искусственно мелкие изменения.
- Уточнение, замечание или исправление в пределах исходной цели продолжает существующую задачу и не получает новый номер.
- Если у существующей задачи ещё нет detail, при первом follow-up создай карточку для её текущего номера и добавь ссылку в строку реестра.
- Если follow-up относится к уже закрытой задаче, при начале реализации она возвращается из `✅` в `🚧`, а после повторной проверки закрывается снова.
- Создавай отдельную задачу только для результата, который можно реализовать и принять независимо от исходной задачи.

## Детализация

По умолчанию не создавай файл в `task-details/`: в список добавляется только готовая к работе задача.

Создавай карточку по `ai-context/task-details/template.md` только если пользователь прямо просит детализировать задачу, либо если задача содержит существенные решения, риски, несколько зависимых этапов или открытые вопросы. В строке списка добавь ссылку на карточку.

Карточка фиксирует цель, границы, декомпозицию, критерии готовности, открытые вопросы, ключевые решения, проверки и append-only `Changelog`. Каждая итерация changelog дословно сохраняет относящийся к задаче prompt пользователя, выполненные изменения и проверки. Старые итерации не переписываются. Карточка не содержит выдуманных реализационных деталей.

## Результат

Кратко сообщи, какие задачи добавлены и были ли созданы карточки. Не переходи к реализации, пока пользователь не попросит выполнить задачу отдельным запросом.
