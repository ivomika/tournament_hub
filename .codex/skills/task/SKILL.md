# Task

Работать только с постоянной памятью задач проекта. Результат skill — обновлённые `ai-context/task-list.md` и детальные карточки в `ai-context/tasks/`, но не изменения приложения.

## Разрешённая область

Можно читать:

- пользовательский запрос текущего диалога;
- `ai-context/README.md`;
- `ai-context/task-list.md`;
- `ai-context/templates/task.md`;
- существующие карточки `ai-context/tasks/*.md`.

Можно изменять только:

- `ai-context/task-list.md`;
- карточки в `ai-context/tasks/`.

Не изменять исходный код, тесты, `docs`, конфигурацию, шаблон задачи или другие файлы. Не запускать реализацию, сборку, миграции и внешние действия. Если вместе с `$task` пользователь просит выполнить работу, сначала только оформить задачи и остановиться; реализация требует отдельного следующего запроса.

## Порядок работы

1. Прочитать разрешённые файлы и проверить, нет ли уже совпадающих или связанных задач.
2. Выделить из запроса цель, ожидаемые результаты, ограничения, зависимости, неизвестные данные и критерии завершения.
3. Разделить запрос на задачи по самостоятельно проверяемым результатам. Не превращать каждый технический шаг в отдельную задачу. Разделять работу, если части имеют разные результаты, зависимости, области ответственности или могут выполняться независимо.
4. Расположить задачи в порядке зависимостей. В каждой зависимой карточке явно указать ID предшествующей задачи.
5. Назначить новые ID формата `TH-ГГГГММДД-NNN`, продолжая максимальный номер текущей даты среди существующих карточек. Не переиспользовать ID удалённых или завершённых задач.
6. Создать для каждой новой задачи полную карточку по `ai-context/templates/task.md`. Сохранять намерение пользователя и не добавлять функциональность, которой он не просил.
7. Ставить статус `Готова`, если задача имеет достаточный контекст для реализации. При существенной неоднозначности ставить `Черновик`, фиксировать неизвестные данные и условие готовности; не придумывать продуктовые решения.
8. Добавить или актуализировать записи в разделе активных задач `ai-context/task-list.md`. Существующие совпадающие задачи обновлять вместо создания дубликатов, сохраняя их историю и принятые решения.
9. Проверить совпадение ID, названий, статусов и ссылок между реестром и карточками.
10. Кратко сообщить пользователю, какие задачи созданы или обновлены, какие зависимости и открытые вопросы зафиксированы. После этого остановиться.

## Требования к карточкам

- Писать на русском языке, кроме технических идентификаторов и устоявшихся терминов.
- Заполнять каждый раздел шаблона. Для неприменимого раздела явно указывать причину.
- Формулировать цель как проверяемый результат, а не процесс.
- В границах отдельно фиксировать, что входит и не входит в задачу.
- План описывать на уровне значимых этапов, не привязывая будущего исполнителя к неподтверждённой реализации.
- Критерии приёмки делать наблюдаемыми и проверяемыми.
- В разделе проверки указывать предполагаемые команды или ручные сценарии; фактический результат заполняется исполнителем позже.
- В журнале решений фиксировать только решения, принятые во время декомпозиции, и явно помечать допущения.
- Не записывать пароли, токены, персональные данные и другие секреты.
