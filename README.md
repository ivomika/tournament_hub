# Tournament HUB

Local-first платформа для проведения офлайн-турнира с Flutter-приложением в роли Host и отображением состояния для зрителей в React-клиенте только для чтения.

## Структура репозитория

- `apps/tournament_app` — Flutter-приложение Host и Participant.
- `apps/spectator_web` — React-интерфейс зрителя только для чтения.
- `docs` — продукт, архитектура, протокол, турнирные правила и ADR.
- `ai-context` — постоянная память задач, их контекста, решений и результатов.
- `tools/scripts` — скрипты автоматизации репозитория.
- `AGENTS.md` — архитектурные границы и правила разработки.

## Быстрый старт

Требования: Flutter, npm и Node.js 20.19+ LTS. Нечётная версия Node.js 19 не поддерживается web-инструментами проекта.

```bash
make bootstrap
make generate
make run-web
make run-flutter
```

Полный список команд локальной разработки, проверок и сборки доступен через `make help`.

## Работа с задачами

Перед любым изменением приложения задача регистрируется в [реестре](ai-context/task-list.md) и детализируется отдельной карточкой по [шаблону](ai-context/templates/task.md). Полный процесс описан в `AGENTS.md` и `ai-context/README.md`.

Для отдельной декомпозиции запроса без реализации используется локальный skill:

```text
$task Описание функции или изменения
```

## Запуск Flutter в VS Code

1. Установите рекомендованные расширения Dart и Flutter при появлении подсказки VS Code.
2. Откройте раздел **Run and Debug**.
3. Выберите `Flutter: запуск с выбором устройства` или `Flutter: macOS`.
4. Запустите конфигурацию клавишей `F5`.

Режимы profile и release доступны отдельными конфигурациями. Команды установки зависимостей, анализа и тестирования находятся в меню **Tasks: Run Task**.

Текущий код — запускаемый каркас проекта. Неподтверждённые продуктовые правила перечислены в `docs/product/open-decisions.md` и не должны неявно фиксироваться в domain logic.
