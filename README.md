# Tournament HUB

Local-first платформа для проведения офлайн-турнира с Flutter-приложением в роли Host и отображением состояния для зрителей в React-клиенте только для чтения.

## Структура репозитория

- `apps/tournament_app` — Flutter-приложение Host и Participant.
- `apps/spectator_web` — React-интерфейс зрителя только для чтения.
- `docs` — продукт, архитектура, протокол, турнирные правила и ADR.
- `ai-context` — постоянная память задач, их контекста, решений и результатов.
- `tools/scripts` — скрипты автоматизации репозитория.
- `AGENTS.md` — архитектурные границы и правила разработки.

## Быстрый старт

Требования: Flutter, GNU Make, npm и Node.js 20.19+ LTS. Нечётная версия Node.js 19 не поддерживается web-инструментами проекта. На Windows команда `make` должна быть доступна в `PATH`, а для desktop-запуска должна быть включена поддержка Windows в Flutter.

```bash
make bootstrap
make generate
make run
```

`make run` собирает Spectator Web, кроссплатформенно встраивает bundle во Flutter и запускает Host. По умолчанию выбирается desktop-device текущей ОС: `windows`, `macos` или `linux`.

Устройство можно переопределить явно:

```powershell
make run FLUTTER_DEVICE=windows
```

```bash
make run FLUTTER_DEVICE=macos
```

Для изолированной UI-разработки без встроенного WebSocket Host доступна команда `make run-web`.

## Spectator в локальной сети

Flutter Host поднимает публичный read-only HTTP/WebSocket-сервер только в текущей локальной сети. На главном экране приложения отображаются QR-код, полный адрес и кнопка копирования.

1. Подключите Host и телевизор, ноутбук или телефон зрителя к одной Wi-Fi/LAN-сети.
2. Запустите Host через `make run` или штатную Flutter-конфигурацию с предварительно собранным bundle.
3. Отсканируйте QR-код либо введите показанный адрес вида `http://192.168.1.20:8080` в браузере другого устройства.
4. Откройтый экран автоматически получает актуальное состояние, восстанавливается после разрыва связи и переключается на итоги после завершения турнира.

Доступ не требует авторизации и предназначен только для доверенной локальной сети. Spectator не предоставляет команд изменения результатов. Если порт `8080` занят, Host выберет свободный порт и покажет фактический адрес.

Полный список команд локальной разработки, проверок и сборки доступен через `make help`.

## Работа с задачами

Перед любым изменением приложения задача регистрируется в [реестре](ai-context/task-list.md) и детализируется отдельной карточкой по [шаблону](ai-context/templates/task.md). Полный процесс описан в `AGENTS.md` и `ai-context/README.md`.

Для отдельной декомпозиции запроса без реализации используется локальный skill:

```text
$task Описание функции или изменения
```

## Запуск Flutter в VS Code

1. Установите рекомендованные расширения Dart и Flutter при появлении подсказки VS Code.
2. Откройте раздел **Run and Debug**.
3. Выберите `Flutter: запуск с выбором устройства` или `Flutter: macOS`.
4. Запустите конфигурацию клавишей `F5`.

Режимы profile и release доступны отдельными конфигурациями. Команды установки зависимостей, анализа и тестирования находятся в меню **Tasks: Run Task**.

Неподтверждённые продуктовые правила перечислены в `docs/product/open-decisions.md` и не должны неявно фиксироваться в domain logic.
